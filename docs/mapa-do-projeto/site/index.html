06 · onde cada coisa mora no código

O que cada arquivo do repositório representa

Não é um índice completo (o repositório tem centenas de arquivos, incluindo testes e migrations) — é o glossário dos arquivos com lógica de negócio real, agrupado por assunto. Clique em cada grupo pra abrir. Nomes de arquivo em monospace são caminhos reais, clicáveis mentalmente (abra no seu editor).

08 · auditoria, não suposição

Estado real por área

Cada linha reflete o que o código faz hoje — não o que a documentação antiga dizia. As pendências já apareceram nos fluxos das seções 01–05 (nó tracejado); aqui é só o resumo tabular pra busca rápida.

Isolamento multi-tenanttenantContext.ts, RLS
ativo
tenantId sempre vem do JWT autenticado — nunca de parâmetro enviado pelo cliente. RLS efetivo em produção desde 26/08/2026 (chave publicável + JWT curto por tenant), não é mais só disciplina de código.

ativo
Mensagem chega e é associada ao tenant pelo phone_number_id. Número desconhecido → mensagem é descartada, nunca gravada no tenant errado.
Agente de IA + CalendarautoReply.ts
ativo
Classificação → resposta especialista → agendamento real via function-calling no Google Calendar, com trava anti-alucinação preventiva e reativa.
Pré-reserva & expiração de holdpreReservationStore.ts, heldAppointmentExpiryJob.ts
ativo
Reserva não vinculante com lock por tenant; libera sozinho se o cliente não confirmar. Ver fluxo 02.

parcial
Código pronto (idioma por tenant, botões de confirmar/remarcar); canal Meta fora da janela de 24h depende de 2 templates ainda não aprovados no Meta Business Manager.

Corrigido pra cortar por identidade do próprio áudio, mesma classe de bug de uma correção anterior (TASK-0172).

Cada achado cai na Central de Qualidade pra revisão humana, nunca corrige o agente sozinho. Ainda não validado manualmente contra Supabase/Gemini reais pela sessão que mesclou (restrição de egress na hora).
