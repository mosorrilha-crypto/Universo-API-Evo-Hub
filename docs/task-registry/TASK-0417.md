# TASK-0417 — Corrige bolha duplicada de mensagem enviada manualmente (corrida SSE vs. resposta do POST /send)

## Objetivo

Achado real reportado ao vivo, com print do painel (tenant Monique — Evolution, contato "Francisca Ibarra"): a mesma mensagem enviada manualmente pelo operador ("¡Hola, amiga, el retoque de las cejas está Gs 150.000") apareceu **duas vezes** no painel.

## Investigação

Confirmei via Supabase que existe **apenas uma linha** em `messages` com esse texto (`sent_by: 'operator'`, um único id real) — ou seja, não é um envio duplicado de verdade (nenhuma mensagem extra chegou pro cliente), é um bug de estado só no cliente (frontend).

Causa raiz, em `WhatsAppLeadsSim.tsx`: quando o operador envia manualmente, o texto aparece na hora como uma bolha "otimista" (id local `msg-<timestamp>`) enquanto `POST /api/conversations/:phone/send` está em voo. TASK-0370 (03/09/2026) já corrigiu o caso simples: quando o POST resolve, a bolha otimista é substituída pela mensagem real (id de verdade) via `.map` por id.

O que a TASK-0370 não cobriu: o servidor publica o evento SSE assim que grava a mensagem — **antes** de esse mesmo POST devolver a resposta pro navegador que a originou. Se esse SSE chegar primeiro, `loadNewerMessages` (disparado por ele) busca `GET /messages?after=...` e já anexa a mensagem real (id de verdade) como uma entrada NOVA na lista, enquanto a bolha otimista (id local, ainda diferente) continua lá. Quando o POST original finalmente resolve, a reconciliação da TASK-0370 troca a bolha otimista por OUTRA cópia da mesma mensagem real — resultado: duas bolhas idênticas.

## Correção

`sendRealWhatsAppMessage` agora checa, antes de reconciliar, se uma mensagem com o id real já está presente na lista (ou seja, se o SSE venceu a corrida). Se já estiver, só remove a bolha otimista (a real já está lá); senão, mantém o comportamento de sempre (substituir a otimista pela real via id).

## Arquivos/commits

`src/components/WhatsAppLeadsSim.tsx` (função `sendRealWhatsAppMessage`), `src/components/__tests__/WhatsAppLeadsSim.duplicateSentBubble.test.tsx` (novo — reproduz a corrida exata via um `EventSource` fake controlável e um `POST /send` com resolução manual, confirma que sem a correção o teste falha com 2 bolhas e com a correção passa com 1).
