## Objetivo

Corrige botao verde no tema Azul (mesmo gap do bg-emerald-600 encontrado no Limpo)

## Atualizações

Follow-up direto da TASK-0061: ao corrigir o acento verde→azul do tema Limpo, encontrei (e
reportei) que o tema "Azul" já existente tinha o mesmo gap — `.bg-emerald-600` (usado por vários
botões primários, ex: `LoginModal.tsx`) nunca teve regra de override em nenhum tema, só
`.bg-emerald-500` tinha. Resultado visível: botão de login verde-Tailwind padrão mesmo com o tema
Azul ativo, contradizendo a própria identidade visual do tema. Usuário confirmou explicitamente
que quer "cada tema alinhado com seu objetivo visual".

- `src/index.css` (bloco `html[data-theme='blue']`, linhas ~503-520): adicionada
  `.bg-emerald-600 { background-color: #0b78b5 !important; }` espelhando a regra já existente pra
  `.bg-emerald-500` (mesmo valor hardcoded, estilo já usado pelas outras regras emerald→azul desse
  tema — não usa `var(--action)` como light/dark/clean, é a convenção própria já adotada ali).
  Também adicionado `.hover\:bg-emerald-600:hover` (mesma cor de hover já usada pra `-500`).
- Ajuste de contraste: `.bg-emerald-500.text-slate-950, .bg-emerald-600.text-slate-950 { color:
  #FFFFFF !important; }` — o botão do LoginModal usa `text-slate-950` (quase preto), pensado pro
  verde-Tailwind claro padrão; sem a correção o texto ficaria ilegível sobre o azul mais escuro
  `#0b78b5`.
- Validado com `npm run lint` (limpo), `npx vitest run` (894 testes, 173 arquivos, todos verdes),
  `npm run build` (limpo), e visualmente com Playwright (Chromium pré-instalado): tela de login
  com `data-theme=blue` forçado via `localStorage` mostra o botão "Validar senha e acessar painel"
  em azul com texto branco legível, sem verde residual.
