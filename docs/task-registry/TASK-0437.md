## Objetivo

Painel: adiciona botão de remover foto de produto/variante do catálogo, sem precisar trocar por outra

## Atualizações

**Contexto**: durante a auditoria de redundância/conflito nas KBs da Monique e do Dr. Daniel (pedido direto do usuário), veio à tona um achado adjacente: 7 produtos do catálogo da Monique ainda têm foto de exemplo em Base64 legado (`exampleImageBase64`, ~12,4MB somados), nunca migrada pro Storage (Cloudflare R2 desde TASK-0332). O código já documentava (TASK-0332) que a migração do conteúdo existente foi decisão deliberada de NÃO ser automática — "as fotos são reenviadas manualmente". Confirmado com o usuário: o caminho certo é reenviar cada foto pelo painel (`AgentKnowledgeBase.tsx`), o que já limpa o base64 sozinho no mesmo upload (`exampleImageBase64: undefined` já setado junto do novo `exampleImageId`).

Ao validar esse caminho, o usuário perguntou o que fazer se quisesse simplesmente apagar uma foto (sem substituir) — e o painel só tinha "Trocar foto"/"Adicionar foto de exemplo", nunca uma opção de remover. Pedido direto: adicionar essa opção.

**Implementação**:
- `server/services/knowledgeBaseImageStore.ts` já tinha `deleteKnowledgeBaseImage` pronta (melhor esforço, nunca lança) mas sem nenhuma rota que a chamasse (achado extra: o comentário da rota de upload menciona uma "limpeza de órfão" no save da KB que nunca foi implementada — fora do escopo desta task, não mexido).
- `server/routes/conversations.ts`: nova rota `DELETE /api/knowledge-base/images/:imageId` (`authenticateToken` + `requireRole('admin')`, tenant resolvido via `tenantOf(req)` — nunca por param), chama `deleteKnowledgeBaseImage` e sempre responde sucesso (mesmo padrão "melhor esforço" da função).
- `src/components/AgentKnowledgeBase.tsx`: `handleRemoveProductImage`/`handleRemoveVariantImage` — confirmação (`window.confirm`), limpam os campos locais (`exampleImageId`/`exampleImageMimeType`/`exampleImageFileName`/`exampleImageSizeBytes`/`exampleImageBase64`) e chamam a rota DELETE em melhor esforço (falha de rede não bloqueia a remoção local — mesmo espírito de "referência local já removida" já usado no resto do arquivo). Botão "Remover foto" (ícone `Trash2`, vermelho) aparece só quando já existe foto, ao lado de "Trocar foto", tanto no nível de produto quanto de variante.
- Persistência segue o mesmo padrão de sempre: só grava de verdade quando a KB inteira é salva/publicada.

**Testes novos**: `conversationsKnowledgeBaseImage.test.ts` (rota apaga e responde sucesso; idempotente quando a imagem já não existe), `conversationsKnowledgeBaseImageIsolation.test.ts` (tenant B nunca apaga imagem do tenant A mesmo sabendo o id exato; tenant A apaga a própria), `AgentKnowledgeBase.imageUpload.test.tsx` (clique remove a foto e chama DELETE; cancelar a confirmação mantém a foto intacta).

**Verificação**: `npm run lint` / `npx vitest run` (315 arquivos, 1808 testes) / `npm run build` — todos limpos.

**Achados do CodeQL na PR #795 (após o push inicial)**: 2 alertas novos (1 high, 1 medium) na rota `DELETE /api/knowledge-base/images/:imageId`. O log de execução do CodeQL não imprime o texto/local exato dos achados (SARIF vai direto pra API do GitHub, sem eco no log da Action) — diagnosticado a partir do próprio diff:
- **medium (`js/missing-rate-limiting`)**: rota administrativa nova sem limite de requisições, mesma classe já corrigida antes neste projeto (PR #496, TASK-0198/googleCalendarConnectRateLimiter). Corrigido com `knowledgeBaseImageDeleteRateLimiter` (20/min por IP, `server/middleware/rateLimit.ts`).
- **high (path/object injection)**: `req.params.imageId` chegava em `deleteKnowledgeBaseImage` → S3 `DeleteObjectCommand` só protegido por `encodeURIComponent` (em `storagePath`, `knowledgeBaseImageStore.ts`) — o CodeQL não reconhece encoding como sanitização suficiente. Corrigido com allowlist explícita (regex batendo com o formato real gerado no upload, `image-<timestamp>-<random>`) rejeitando qualquer id fora do padrão com 400 antes de qualquer chamada ao Storage. Novo teste cobrindo isso (`conversationsKnowledgeBaseImage.test.ts`).

Ambos os fixes validados localmente (lint/1831 testes/build limpos) e empurrados em commits separados; aguardando confirmação do CodeQL na PR após o segundo push (não consegui ler o texto exato dos alertas por nenhuma ferramenta disponível — diagnóstico feito por análise do próprio diff contra padrões já documentados neste repositório).

**Pendente**: as 7 fotos legadas da Monique (~12,4MB) continuam precisando ser reenviadas manualmente pelo painel — este botão de remover não migra automaticamente nada, só cobre o caso de querer tirar uma foto sem repor. Migração automática foi explicitamente descartada nesta conversa (decisão preexistente do dono do produto, TASK-0332).
