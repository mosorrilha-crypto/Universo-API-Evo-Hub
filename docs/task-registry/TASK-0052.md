# TASK-0052 — gera PDF do catálogo com o mesmo design (cores/fonte) do catálogo público, em vez de texto puro

- **Agente/plataforma:** Claude
- **Issue central:** [#290](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/290)
- **Status:** concluída

## Objetivo

Follow-up direto do dono do produto sobre o botão de download em PDF (TASK-0044/PR #399), depois de baixar o catálogo real: "Eu baixei o catálago mas ele veio assim sem o design existe a possibilidade de baixar igual aparece no site". O PDF anterior usava só a API de texto puro do jsPDF (`doc.text(...)`), sem cor, fonte ou layout — nada parecido com a página pública `/catalogo/:slug`.

## Correção

`src/lib/catalogPdf.ts` reescrito do zero, trocando a geração por texto puro por um pipeline HTML → canvas → PDF que replica o design real do catálogo público (`PublicCatalogPage.tsx`):

- Monta um HTML off-screen (anexado ao DOM, fora da viewport) com a mesma paleta (fundo creme `#f3eee4`, cartões `#fffdf9`, acentos terracota `#8d5c43`/`#987254`, rodapé `#221e1a`) e tipografia (Playfair Display pros títulos, Montserrat pro corpo — carregada via `document.fonts.load`/`document.fonts.ready` antes de capturar, senão o navegador cai pra uma serif genérica).
- **Bug real encontrado no `jsPDF@4.2.1`**: o método de alto nível `doc.html()` (usado inicialmente) roda o html2canvas normalmente por baixo dos panos, mas nunca conecta a imagem resultante aos recursos da página — página final em branco, confirmado inspecionando os bytes crus do PDF (`/XObject` vazio no dicionário `/Resources`). Correção: chama o `html2canvas` diretamente e usa `doc.addImage()` manualmente, fatiando o canvas por página.
- Fatias exportadas como JPEG (`toDataURL('image/jpeg', 0.9)`, com fundo opaco preenchido antes do `drawImage`) em vez de PNG — um teste de 3 páginas em PNG bruto passava de 24MB (inviável pra baixar/mandar por WhatsApp); em JPEG cai pra ~587KB sem perda visível.
- **Paginação ciente dos cartões**: cada cartão de produto ganhou `data-pdf-block="true"`. Antes de rasterizar, mede o `top`/`bottom` (em px do DOM, convertido pra px do canvas) de cada cartão; ao decidir onde cortar cada página, se o corte "ideal" cairia no meio de um cartão, empurra o corte pra antes dele (o cartão inteiro vai pra próxima página) — só faz corte no meio quando o cartão sozinho é maior que uma página inteira (sem alternativa). Evita o artefato de borda duplicada visto no teste inicial (cartão "Combo Micro Cejas + Labios" cortado ao meio entre página 1 e 2).
- `html2canvas` promovido de dependência transicional/opcional (usada só pelo `jspdf`) pra dependência direta no `package.json`, já que agora é chamado diretamente pelo código — `package-lock.json` atualizado (remove os `"optional": true` das entradas correspondentes).
