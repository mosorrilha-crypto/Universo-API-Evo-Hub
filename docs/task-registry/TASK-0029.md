# TASK-0029 — corrige fonte e cor perdidas na migracao do catalogo publico da Monique (Netlify -> Universo)

- **Iniciado em:** 2026-08-23T23:00:00.000Z
- **Agente/plataforma:** Claude
- **Issue central:** [#290](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/290) (fechada sem sucessora, ver TASK-0026)
- **Status:** concluída

## Objetivo

O usuário reportou "perdemos qualidade visual" comparando `/catalogo/monique-teste` (Universo/Render) com o site original na Netlify (`pestanas-por-monique-landing.netlify.app`), enviando prints dos dois lado a lado.

## Diagnóstico

Comparando os prints: os títulos grandes (h1 do hero, h2 de seção) apareciam **quase invisíveis** ("fantasma") no Universo — texto muito fino e claro, ilegível — enquanto no original eram serifados em itálico **bold**, escuros e nítidos. A faixa "13 años de experiencia..." também mudou de terracota (original) pra preto (Universo).

Causa raiz: a migração da landing (TASK-0010) portou os valores visuais (tamanhos, espaçamentos, cores de apoio) mas **não trouxe a fonte serifada de destaque real** (nenhum `@font-face`/Google Fonts import) — o CSS caiu pro fallback `Georgia, "Times New Roman", serif` em peso normal (400), que num tamanho grande (até 94px) fica visualmente fino e de baixo contraste, lendo como "fantasma". A cor da faixa de confiança também divergiu (`#221e1a` preto em vez do terracota original).

Acesso à Netlify original: bloqueado por egress de rede desta sessão (browser/curl/WebFetch todos recusados com 403 pelo proxy). Resolvido no meio da tarefa: o usuário conectou o **conector MCP do Netlify**, que deu acesso à API do Netlify (não sujeita ao mesmo bloqueio de domínio) — localizado o site (`pestanas-por-monique-landing`, id `7aa11222-...`), mas a API não expõe o HTML/CSS bruto do deploy (foi um deploy manual "drop", sem repositório/zip de origem). A fonte exata e a cor terracota foram confirmadas por inspeção visual dos prints enviados pelo usuário (fonte identificada como **Playfair Display** — serifada bold itálica de alto contraste, disponível gratuitamente no Google Fonts).

## Correção

`src/components/PublicCatalogPage.tsx`:
- Import do Google Fonts `Playfair Display` (pesos 400/700, regular/itálico) via `@import` no topo do `<style>` inline.
- Todo `font-family: Georgia, "Times New Roman", serif` (ou variação) trocado pra `'Playfair Display', Georgia, "Times New Roman", serif` — cobre marca no cabeçalho, h1 do hero, h2 de seção, número do passo, nome do produto, preço, pergunta do FAQ, marca no rodapé, título da tela de erro.
- `.catalog-hero h1` e `.steps-section h2, .services-section h2, .faq-section h2` (os que apareciam "fantasma") ganharam `font-weight: 700; font-style: italic;` pra bater com o original.
- `.trust-band` (faixa "13 años de experiencia...") trocado de `#221e1a`/`#f5ebdd` (preto) pra `#c9987a`/`#fffdf9` (terracota/creme) — reaproveita a mesma cor terracota já usada nos botões de WhatsApp (`.whatsapp-button`, `.sticky-whatsapp`), então fica consistente com o resto da paleta.

## Validação

- `npm run lint`: 0 erros.
- `npm run build`: Vite + esbuild concluídos sem erro.
- Validação visual local: harness estático (`file://`, sem depender de rede externa bloqueada) com o mesmo bloco `<style>` do componente + markup do hero/faixa/seção "Cómo funciona", renderizado via Playwright/Chromium local. Screenshot confirma: a fonte Playfair Display carrega e renderiza (título "Un trazo que no se nota como retoque." itálico bold, escuro, nítido — bate com o original), faixa de confiança em terracota com texto branco legível.
- **Não validado:** a página real em produção (`/catalogo/monique-teste`) continua fora de alcance desta sessão (egress bloqueado) — recomenda-se conferência visual humana após o deploy.

## Pendente ou risco

- Nenhum código de negócio foi tocado — mudança é só de CSS/tipografia dentro de um componente já existente.
- Recomenda-se conferência visual humana em produção depois do deploy, já que a validação aqui foi via harness local, não a página real.
