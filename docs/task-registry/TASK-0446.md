# TASK-0446 — Adiciona separador de data grudado no topo (sticky) ao rolar o histórico da conversa, igual ao comportamento nativo do WhatsApp

- **Status:** concluído

## Contexto

Pedido direto, com prints de referência: no painel (`WhatsAppLeadsSim.tsx`), rolando uma conversa longa, não há nenhuma indicação de qual dia você está vendo — diferente do WhatsApp nativo, que mostra um selo de data ("Hoje"/"Ontem"/data) grudado no topo da tela enquanto você rola, trocando só quando cruza pra um dia diferente.

O separador de data em si já existia (TASK-0281, `isNewChatDateGroup`/`formatChatDateLabel` em `src/lib/chatDate.ts`) — mas só como uma marca que aparece UMA VEZ no ponto exato da rolagem onde o dia muda, dentro do fluxo normal das bolhas. Se você rola pra dentro de um dia com muitas mensagens, o selo original já ficou pra trás e some da tela — exatamente o que os prints mostraram (a conversa da Nadia não tinha nenhuma data visível).

## O que foi feito

`server`/`src/components/WhatsAppLeadsSim.tsx`: o `<div>` do selo de data (dentro do `.map` de mensagens, já renderizado condicionalmente por `shouldShowDateSeparator`) ganhou `sticky top-0 z-10` — como cada selo é filho direto do container com `overflow-y-auto` (`messagesContainerRef`), o CSS sticky nativo já resolve o comportamento pedido: o selo do dia atual fica fixo no topo do scroll até o selo do próximo dia (também sticky) empurrá-lo, mesmo mecanismo do WhatsApp/Telegram — sem nenhuma lógica de JS de rastrear scroll. Fundo do pill trocado de `bg-[#202c33]/90` pra `bg-[#233138]` sólido + `shadow-md` (antes ficava só entre bolhas; agora fica por cima de bolhas rolando por baixo, precisa de mais contraste).

- `npm run build` — limpo.
