# TASK-0395 — Corrige bug real: gaveta Ferramentas (mobile) nao mostra botao pra cadastrar gatilhos de anuncio quando nenhum ja existe

- **Iniciado em:** 2026-09-11T23:22:22.051Z
- **Agente/plataforma:** Claude
- **Issue central:** [#504](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/504)
- **Status:** concluído

## Objetivo

Pedido direto do dono do produto, com print anotado: entrou na conta de um tenant (Daniel) e, ao ativar "Anúncios" na gaveta Ferramentas (mobile), não aparecia nenhuma opção pra cadastrar os gatilhos de texto que fazem o agente reconhecer leads vindos de anúncio sem `ctwa_clid`.

## Investigação

Confirmado no código (`src/components/WhatsAppLeadsSim.tsx`, dentro de `toolbarSettingsBody`, a gaveta "Ferramentas" do mobile): o botão que abre o modal "Gatilhos de Anúncio" (`openAdTriggersModal`) só renderizava quando `adTriggerMessages.length > 0`. Ou seja, pra cadastrar o PRIMEIRO gatilho era preciso já ter algum gatilho cadastrado — um beco sem saída pra qualquer tenant ativando "Anúncios" pela primeira vez pelo celular.

A versão desktop da mesma engrenagem (faixa fixa "Status do agente", `hidden lg:flex`, mais abaixo no mesmo arquivo) sempre usou a condição certa — `{adsOnly && (...)}`, aparece sempre que o modo está ligado, independente de já existir algum gatilho — só o mobile ficou com a condição errada (histórico: TASK-0348 moveu o botão de uma fileira própria pra virar "badge" desta pill, mas a condição virou contagem em vez de manter o estado do toggle).

## O que mudou

`src/components/WhatsAppLeadsSim.tsx`: condição do botão na gaveta mobile trocada de `adTriggerMessages.length > 0` pra `adsOnly` (igual ao desktop). Quando não há nenhum gatilho ainda, mostra um ícone de engrenagem (`Settings2`) convidando a configurar; quando já existe pelo menos um, mostra a contagem como badge vermelho (comportamento visual anterior preservado nesse caso).

## Validação

- `npm run lint` (limpo).
- `npx vitest run` — 1677 testes, todos verdes, incluindo 2 novos em `src/components/__tests__/WhatsAppLeadsSim.adTriggersEntryPoint.test.tsx` que cobrem exatamente o bug: (1) com `adTriggerMessages: []` e `adsOnly: true`, o botão "Configurar gatilhos de anúncio" existe; (2) com algum gatilho já cadastrado, aparece a contagem como badge ("Ver gatilhos de anúncio configurados") em vez do botão de configurar vazio.
- `npm run build` (limpo).

## Pendente ou risco

Nenhuma área crítica tocada (UI de configuração, sem mudança de rota/backend/schema). Recomendo o dono do produto confirmar visualmente na conta do Daniel após o deploy: ativar "Anúncios" sem nenhum gatilho cadastrado e conferir que o ícone de engrenagem aparece e abre o modal.
