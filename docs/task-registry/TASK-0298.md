## Objetivo

remove alerta de escalação via WhatsApp para o número do admin, manter só push no painel

## Atualizações

Usuário reportou (print do WhatsApp pessoal) que a mensagem "🚨 Nova escalação em Monique..." estava chegando como conversa comum no número pessoal do dono do tenant, misturada com os leads reais. Origem: `server/services/escalationAlertService.ts`, `notifyEscalationCreated()`, Canal 2 — enviava um template Meta (`escalonamento_alerta`) ou texto livre via Evolution API pro `tenants.admin_alert_phone` toda vez que uma escalação era criada (chamada em `escalationStore.ts`).

Ajuste: removido o Canal 2 (WhatsApp) inteiro dessa função — junto foram removidas as constantes `TEMPLATE_NAME`/`TEMPLATE_LANGUAGE` e o import de `sendAdminAlert` (`adminAlertChannel.ts`), que ficaram sem uso neste arquivo. O alerta agora é só "no sistema": Canal 1 (push pro PWA do atendente via `sendPushToTenant`, issue #159) mais o card de sempre na `EscalationsPanel.tsx` do painel.

**Escopo intencionalmente não tocado:** `admin_alert_phone` e `sendAdminAlert` continuam em uso por outros alertas distintos que o print não mostrava e que o pedido não mencionou — `agentPausedAlertJob.ts` (agente pausado) e `paymentPendingAlertJob.ts` (pagamento pendente). Se o usuário quiser o mesmo ajuste para esses, é uma tarefa separada.

Teste atualizado (`escalationAlertService.test.ts`): trocado o mock/asserção de `sendWhatsAppTemplateMessage`/`sendEvolutionTextMessage` (agora só verifica que **não** são chamados) para `sendPushToTenant` como canal único verificado.
