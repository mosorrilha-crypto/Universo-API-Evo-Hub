## Objetivo

aba de desempenho (leads/cliques) na tela de configuracao do catalogo

## Atualizações

**Pedido direto no chat**, continuação da TASK-0076 (contador interno de clique no catálogo): o dono do produto perguntou onde ficaria registrado o relatório de análise desses leads/cliques. Resposta na hora: hoje em nenhum lugar visível — só linhas cruas no Supabase. Ofereci duas opções (atualizar manualmente o painel-artifact existente, ou construir uma aba de verdade no produto); ele escolheu a aba de verdade, dentro da própria tela de configuração do catálogo (`PublicCatalogSettings.tsx`).

**O que foi construído:**
1. `server/services/publicCatalogClickStore.ts`: nova função `getCatalogClickAnalytics(tenantId)` — agrega os cliques dos últimos 90 dias em totais, janelas de 7/30 dias, por produto, e lista dos 20 mais recentes (com status "virou conversa" e telefone quando aplicável).
2. `server/routes/conversations.ts`: nova rota `GET /api/public-catalog-settings/analytics` (mesmo padrão de auth por JWT das rotas de settings já existentes, escopada só por `tenantOf(req)`).
3. `src/components/PublicCatalogSettings.tsx`: a tela ganhou um seletor de aba (Configuração / Desempenho). A aba nova (`CatalogPerformanceTab`) mostra 4 cards de resumo (cliques 90 dias, viraram conversa + taxa, últimos 7/30 dias), uma tabela por produto e a lista de cliques recentes.

**Arquivos:** `server/services/publicCatalogClickStore.ts`, `server/routes/conversations.ts`, `src/components/PublicCatalogSettings.tsx`, mais testes em `server/routes/__tests__/publicCatalogSettings.test.ts`.

**Validação:** `npm run lint`, `npx vitest run` (937 testes, todos passando — inclui 2 casos novos pra rota de analytics), `npm run build` — todos OK.

**Pendente/risco:** **não fiz verificação visual no navegador** — este ambiente sandbox não tem `SUPABASE_URL`/`SUPABASE_KEY` configurados, então não dá pra logar e carregar dados reais de tenant pra clicar na aba de verdade. A cobertura é só via testes automatizados (a rota simulando requisição HTTP real) e `npm run build` (confirma que o TSX compila e empacota sem erro). Recomendo forte que alguém confira visualmente a aba nova depois do deploy, antes de considerar 100% validada.
