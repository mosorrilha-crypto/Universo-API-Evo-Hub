## Objetivo

Corrige horário de atendimento que não persiste após salvar (estado local preso em valor inicial vazio)

## Atualizações

Bug real reportado por print: o modal "Horários de atendimento"
(`AgentKnowledgeBase.tsx`) sempre abria mostrando todo dia como "sem
atendimento", mesmo depois de salvar um horário real. O save em si
(`POST /api/business-hours`, `server/routes/conversations.ts`) e a
validação (`validateBusinessHours`, `server/services/tenantProfileStore.ts`)
estavam corretos — confirmei lendo os dois lados, nada rejeitava nem
silenciosamente falhava a gravação.

Causa raiz real: `const [hoursForm, setHoursForm] = useState<BusinessHours>(() => businessHours)`
— o inicializador de `useState` só roda uma vez, na primeira renderização.
`businessHours` chega em `App.tsx` por um `GET /api/business-hours`
assíncrono, numa `useEffect` própria, sem nenhuma relação com o
carregamento da Base de Conhecimento (`kbLoaded`) que controla quando este
componente monta. Se o componente montar antes desse fetch resolver
(cenário comum: usuário navega direto pra aba Base de Conhecimento após
login), `hoursForm` fica travado no valor inicial vazio `{}` PRA SEMPRE —
não existia nenhum efeito resincronizando com a prop depois que ela
chegasse com o dado real. Sintoma: o horário salvo continuava intacto no
banco (confirmável via `GET /api/business-hours` direto), mas a UI nunca
refletia isso, dando a impressão de que "não persiste".

Corrigido com um único `useEffect` que resincroniza `hoursForm` sempre que
a prop `businessHours` mudar — cobre tanto o modal quanto a seção inline
legada (tenants sem KB publicada ainda, `!usesPublishedKnowledgeBase`).
Seguro contra sobrescrever edição em andamento: a prop só muda nessas duas
situações (chegada tardia do fetch inicial, ou eco do próprio save deste
componente devolvendo o mesmo valor que acabou de ser salvo).

Entregue: `src/components/AgentKnowledgeBase.tsx` (1 useEffect novo, sem
mudança de comportamento fora do bug).

## Encerramento

**Status: concluído.** Não toca autenticação/pagamento/isolamento de
tenant — é puramente um bug de sincronização de estado local no frontend.
Self-merge autorizado. Validação: `npm run lint`, `npx vitest run`
(225 arquivos, 1166 testes) e `npm run build`, todos limpos.

**Pendente ou risco:** não escrevi teste de componente automatizado —
`AgentKnowledgeBaseView` tem uma superfície de props muito grande (fetch
próprio de documentos tipados, várias dependências externas) e montar um
fixture só pra este ajuste de uma linha seria desproporcional ao risco
real; a correção segue o mesmo padrão já usado em outros pontos do
arquivo (sincronizar estado derivado de uma prop assíncrona via
`useEffect`). Recomendo validação manual em produção: abrir a aba Base de
Conhecimento logo após o login (antes do painel "esquentar" o cache) e
conferir se o horário salvo aparece certo de primeira.
