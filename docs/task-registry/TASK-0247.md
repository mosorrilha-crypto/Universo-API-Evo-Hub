## Objetivo

Ficha do contato: fundo do painel principal fica cinza-amarelado no tema claro/limpo em vez de branco

## Atualizações

Follow-up direto da TASK-0246 (PR #624): o dono do produto mandou print
real do celular, tema claro, mostrando o painel "CONTEXTO SUPERVISIONADO"
(dentro da Ficha IA) com fundo cinza-amarelado, destoando dos cards
brancos vizinhos ("Orientador de conversa", "Interesse"/"Intenção"/
"Idioma") — "está cor escura não está de acordo com o tema".

**Achado real:** `ContactContextPanel.tsx` (`variant="detail"`) usa
`bg-slate-950/65` como fundo do painel PRINCIPAL. A auditoria geral de
classes -950 em `index.css` (adicionada numa tarefa anterior, cobre toda
a família -950 pra qualquer largura de opacidade) mapeia essa classe pra
`var(--surface-sunken)` — certo pra um "poço" recuado DENTRO de um card
(ex: input, bloco de código), mas errado aqui: `--surface-sunken` no tema
claro é `#EBE9E3` (cinza-amarelado), bem diferente do branco
(`--surface-panel`, `#FFFFFF`) usado pelos cards vizinhos da mesma Ficha
IA. A TASK-0246 tinha auditado as variantes -500/-600 que faltavam, mas
não notou que a -950 já coberta estava mapeada pro token errado
especificamente pra este uso.

Corrigido com escopo mínimo: nova classe `contact-context-detail` no
`<section>` do painel principal (`ContactContextPanel.tsx`), e uma regra
CSS de 2 classes (`html[data-theme='light'/'clean']
.contact-context-detail.bg-slate-950\/65`) que vence a regra geral de 1
classe sem precisar mudar o comportamento padrão de `-950` pros outros
usos legítimos dele no resto do app (que continuam corretos como "poço").

Arquivos alterados: `src/components/ContactContextPanel.tsx`,
`src/index.css`.

mas é candidata a ter o mesmo problema visual. Vale conferir num print
real antes de decidir se merece o mesmo ajuste.
