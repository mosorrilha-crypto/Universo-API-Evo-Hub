## Objetivo

Tenant Dr. Daniel Oliveira usa o mesmo número pessoal para atendimento profissional e assuntos pessoais — adiciona um mecanismo real (outOfScope no schema JSON do especialista) pra IA deixar de responder automaticamente mensagens que a Base de Conhecimento do tenant definir como fora de escopo, sem gerar falso escalonamento de falha

## Atualizações

**Pedido original**: usuário pediu pra analisar as conversas do tenant "Dr. Daniel Oliveira" (fisioterapeuta) e descobriu, junto comigo, que o número de WhatsApp cadastrado é o número pessoal dele — usado tanto para atendimento profissional quanto pra assuntos pessoais (organização de uma corrida de rua, carona, papo com conhecidos). Pediu uma regra no prompt pra IA só responder mensagens que ela identificar como profissionais.

**Por que isso não podia ser só uma regra de texto na Base de Conhecimento**: o mecanismo existente pro modelo "não responder" (`bubbles: []`) já colapsava pra `null` em `generateSpecialistReply`, e `webhooks.ts` trata qualquer `null` como FALHA REAL — cria um escalonamento ("IA não conseguiu gerar resposta automática") e alerta o operador. Se eu só tivesse adicionado a regra de texto sem mexer no código, toda mensagem pessoal ignorada de propósito viraria um card falso de "falha" na tela de Pendências — pior do que a situação atual, não melhor.

**Solução implementada — novo campo `outOfScope` no schema JSON do especialista** (`server/services/autoReply.ts`):
- Novo campo opcional `outOfScope` no JSON que o especialista (Gemini ou Groq) retorna — documentado no prompt (Camada 1, texto fixo, vale pra todo tenant) como só devendo ser usado quando a Base de Conhecimento do PRÓPRIO tenant definir explicitamente regras de quando responder. Sem essa instrução na KB do tenant, o modelo nunca marca isso — comportamento de todo outro tenant (incluindo a Monique) fica inalterado.
- `generateSpecialistReply`: quando `bubbles` vem vazio E `outOfScope: true`, retorna um resultado válido (não `null`) com `outOfScope: true` — distinto de uma falha real. Bubbles vazio SEM `outOfScope` continua caindo no comportamento antigo (`null` = falha).
- Groq (`TASK-0346`, fallback do especialista): o guard que tratava `bubbles` vazio como erro do Groq agora abre exceção quando `outOfScope` também veio true.
- `AutoReplyResult` (interface pública) ganhou `outOfScope?: boolean`.
- `generateAutoReplyForText`: curto-circuita assim que detecta `specialist.outOfScope`, antes do gate anti-alucinação (que pressupõe bubbles não vazio).
- `webhooks.ts` e `transcriptionQueue.ts` (os dois pontos reais de entrada — texto e áudio transcrito): quando `result.outOfScope`, emite o novo status `skipped_out_of_scope` e retorna sem enviar mensagem, sem `logEscalation`, sem alertar o operador — silêncio real, não uma falha disfarçada.
- `conversationEvents.ts`: novo valor `'skipped_out_of_scope'` no union de `aiReplyStatus`.
- `WhatsAppLeadsSim.tsx`: trata o novo status igual a `sent`/`template_sent` (limpa o spinner "gerando" na hora, sem passar pelo alerta amarelo de "aguardando humano" que sugeriria uma falha).

**Regra aplicada na Base de Conhecimento do tenant Dr. Daniel Oliveira** (`pricing_policies`, versão 9, publicada via SQL direto no Supabase — mesmo padrão de versionamento que o painel já usa, v8 arquivada): instrui a IA a só responder automaticamente mensagens com sinal claro de assunto profissional (dor, lesão, reabilitação, fisioterapia, avaliação, consulta, agendamento) ou uma primeira mensagem de número novo sem sinal pessoal identificável — qualquer sinal de assunto pessoal/social (cumprimento solto em conversa já pessoal, corrida, carona, papo com conhecido, figurinha sem texto) marca `outOfScope: true`.

**Achado ao investigar (não desta task, mas relevante)**: das 30 conversas reais deste tenant, só 1 teve alguma resposta de IA (7 mensagens); as outras 29 foram 100% operador manual — e nenhuma das 30 parecia claramente ser paciente buscando atendimento (a maioria era chat pessoal/organização de corrida). A regra nova deve reduzir drasticamente quantas dessas conversas pessoais recebem resposta automática indevida daqui pra frente.
