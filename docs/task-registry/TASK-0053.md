## Objetivo

Usuário pediu, a partir de um print de referência (dashboard "Darwin Ai" — layout claro, organizado, cabeçalho de KPIs, lista de conversas), um novo modo de cor "Limpo" no painel Universo, criado como experimento reversível (um 4º modo de tema, não uma substituição do modo claro existente) — se não ficar bom, é só remover.

## Atualizações

- Investigado o mecanismo de tema atual: `AppPreferencesContext.tsx` já suporta 3 modos (`dark`/`light`/`blue`) via atributo `data-theme` no `<html>` + `localStorage`, com seletor já existente em `Header.tsx` (2 lugares: mobile e desktop). Nenhum componente React tem lógica condicional de tema — tudo é resolvido via overrides globais em `src/index.css`.
- `src/index.css` (2418 linhas antes desta tarefa) tem 164 regras de override específicas para `html[data-theme='light']`, espalhadas pelo arquivo (não um bloco único) — cobrindo desde classes Tailwind cruas (`bg-slate-900`, `text-slate-400`, classes arbitrárias `bg-[#111b21]` etc.) até tokens CSS semânticos (`--surface-panel`, `--text-primary`, `--action`, `--danger`, `--bubble-ai` etc.) usados por componentes BEM mais novos (`.atendimento-*`, `.operations-module-frame*`, `.quality-workspace__*`).
- Implementado `html[data-theme='clean']` clonando programaticamente as 164 regras de `light` (script Node em `/tmp` descartável, não versionado) com um mapeamento de cor por bucket semântico (verde continua verde/sucesso, âmbar continua aviso, rosa continua perigo, cinza-quente vira cinza-azulado neutro, texto quase-preto fica mais frio/contrastado) — garante paridade de cobertura em TODO o app, não só na tela de WhatsApp, sem precisar redescobrir os 164 pontos manualmente.
- Corrigido um bug real do próprio script na primeira tentativa: a substituição de cor também reescrevia cores dentro do SELETOR (`[class~='bg-[#0b141a]']` virava `[class~='bg-[#FFFFFF]']`), quebrando o matching com a classe Tailwind real usada no JSX — corrigido pra só recolorir o corpo da declaração, nunca o seletor.
- Verificado programaticamente que nenhuma regra `clean` ficou com cor não-traduzida (só achou 1 caso real, `#cbdcdd` num border, corrigido manualmente pra `#E4E7EC`).
- Adicionado `'clean'` ao type `AppTheme` + lista de valores aceitos, e uma 4ª opção ("Limpo", ícone `Sparkles`) nas duas listas do seletor em `Header.tsx` (mobile e desktop — são arrays JSX distintos, não uma única fonte compartilhada).
- Validado com `npm run lint` (limpo), `npx vitest run` (876 testes, incluindo o teste de contraste específico do modo claro, que não foi tocado), `npm run build` (limpo), e visualmente no navegador (Playwright + Chromium pré-instalado, `playwright-core` instalado com `--no-save` só pra essa verificação): a tela de login renderiza com a paleta nova (fundo branco/cinza-frio, texto quase-preto, acento verde-esmeralda) exatamente como o print de referência.
- **Limitação da validação:** não foi possível logar na tela de WhatsApp de verdade neste sandbox (sem credencial/Supabase configurado) — só a tela de login (sem sessão) foi confirmada visualmente. A cobertura da tela de chat é garantida mecanicamente (clonada das mesmas 164 regras que já a cobrem no modo `light`), mas não foi vista ao vivo.
