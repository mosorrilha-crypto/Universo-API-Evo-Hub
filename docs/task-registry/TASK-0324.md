# TASK-0324 — Corrige regressao de legibilidade da barra de status (icone escuro sobre fundo escuro) revertendo troca dinamica de theme-color fora do modo PWA instalado

- **Iniciado em:** 2026-09-06T13:53:24.544Z
- **Agente/plataforma:** Claude
- **Issue central:** [#504](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/504)
- **Status:** concluído

## Objetivo

Reportado com prints reais (mesmo celular, tema claro): o relógio/ícones da
barra de status do Universo ficaram com pouco contraste (texto escuro sobre
fundo escuro), diferente do WhatsApp nativo no mesmo aparelho, que mantém o
relógio sempre branco/legível mesmo sobre a barra preta.

## Causa raiz

TASK-0321 passou a atualizar `<meta name="theme-color">` dinamicamente
conforme o tema ativo (branco pro claro/limpo). Print real comparando com o
WhatsApp nativo no mesmo celular provou que a barra de status, nesse modo de
navegador comum (não instalado como PWA), **não é realmente repintada** —
nem o app nativo do WhatsApp consegue, ela continua preta sempre. Porém
alguns navegadores/Android ainda usam a luminância do `theme-color` pra
decidir a cor do ícone/relógio (claro vs escuro), independente da barra em
si mudar de cor de verdade. Resultado: `theme-color` branco fez o ícone
ficar escuro, mas a barra continuou preta — texto escuro sobre fundo escuro,
ilegível. A meta original (barra branca) era baseada num gráfico de
comparação que não era uma screenshot real de dispositivo — não provava que
isso fosse alcançável.

## Correção

`src/contexts/AppPreferencesContext.tsx`: a troca dinâmica de `theme-color`
só acontece agora quando `window.matchMedia('(display-mode: standalone)')`
é verdadeiro — ou seja, só quando o app está instalado como PWA (único modo
em que o Android de fato repinta a barra). Fora disso (aba de navegador
comum, o caso mais comum), o valor estático de `index.html` (`#111b21`,
ícone sempre claro) permanece intocado — mesmo comportamento que o WhatsApp
nativo demonstrou ter no dispositivo real usado para o teste.

## Validação

`npm run lint` limpo. `npx vitest run`: 272 arquivos, 1508 testes, todos
passando. `npm run build` limpo.

## Pendente/risco

Não foi possível confirmar visualmente em tempo real (sem acesso de rede ao
domínio de produção nesta sessão) que o ícone volta a ficar legível depois
desta correção — validação depende de novo print real do usuário após o
deploy. Se o app for usado instalado como PWA, o comportamento antigo
(dinâmico) continua valendo, e nesse modo específico pode valer a pena uma
verificação futura separada.
