## Objetivo

Corrige recuperacao de JSON malformado do Gemini - chave sem aspas

## Atualizações

Follow-up direto da TASK-0227. Depois do deploy da TASK-0227 (confirmado
`live` às 04:03:28 UTC), o dono do produto rodou uma nova rodada de
avaliação automática (10 casos, 04:04-04:05 UTC) e pediu pra fechar os que
já foram revisados. Ao revisar, encontrei que **2 dos 10** ainda tinham o
erro EXATO "Erro: Falha ao avaliar: Expected double-quoted property name in
JSON at position 16 (line 1 column 17)" — mesma mensagem, mesma posição,
mesmo depois do deploy da correção anterior estar `live`.

Causa raiz real: a recuperação da TASK-0227 (`safeParseGeminiJson`) só
tratava ruído AO REDOR de um JSON válido (markdown, texto extra antes/
depois) — extraindo o primeiro bloco `{...}` balanceado. Mas a mensagem de
erro ("Expected double-quoted property name") é especificamente sobre
sintaxe INTERNA inválida (uma chave de objeto sem aspas, ex.:
`{issues: [...]}` em vez de `{"issues": [...]}`) — algo que Gemini às
vezes produz mesmo com `responseMimeType: 'application/json'` no modelo
`gemini-3.5-flash-lite`. Extrair um bloco balanceado não resolve esse tipo
de erro porque o bloco extraído continua com a mesma sintaxe inválida por
dentro — daí a mensagem idêntica se repetir mesmo com a correção anterior
ativa.

Corrigido: `safeParseGeminiJson` (`geminiJson.ts`) ganhou uma terceira
camada de recuperação — depois de extrair o bloco balanceado, se ainda
falhar, tenta consertar chaves sem aspas via regex
(`([{,]\s*)([A-Za-z_$][A-Za-z0-9_$]*)\s*:` → adiciona aspas) antes de
tentar o parse de novo. Só relança o erro original se essa recuperação
também não produzir JSON válido.
