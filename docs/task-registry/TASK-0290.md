# TASK-0290 — implementa integracao com History API para o botao fisico de voltar do Android navegar dentro do app antes de minimizar

## Objetivo

implementa integracao com History API para o botao fisico de voltar do Android navegar dentro do app antes de minimizar

## Atualizações

Pedido direto do dono do produto, com print da lista de Conversas no
mobile, círculo vermelho no botão físico/gesto de voltar do Android:
"tem como esse botão ser aproveitado dentro do sistema pois ele minimiza
o aplicativo e não volta as páginas dentro do aplicativo... poderia sair
da conversa voltando para lista e só minimizar quando chega na última
página disponível que é a página 'hoje'".

**Causa raiz confirmada no código**: o app inteiro nunca chamava
`history.pushState`/escutava `popstate` — sem nenhuma entrada própria no
histórico do navegador/WebView, o botão de voltar do Android não tem
nada pra "desfazer" e cai direto no comportamento padrão do sistema
(minimizar a PWA/WebView). Confirmado via `grep -r "popstate\|pushState"
src/` — zero ocorrências antes desta task.

**Implementado** (`src/App.tsx` + `src/components/WhatsAppLeadsSim.tsx`):
- `App.tsx` empilha uma entrada de histórico toda vez que `activeTab`
  sai de `'home'` ("Hoje") pra qualquer outra aba, e outra quando uma
  conversa abre no mobile (`isMobileWhatsAppThreadOpen`).
- Um listener de `popstate` desfaz exatamente UM nível por vez: se tem
  conversa aberta, fecha ela (via nova prop `closeThreadSignal`, mesmo
  padrão de `openLeadRequestId` — um contador que `WhatsAppLeadsSim`
  observa e, ao mudar, chama o mesmo fechamento do botão "voltar pra
  lista" já existente no cabeçalho); senão, se a aba ativa não é
  `'home'`, volta pra aba que estava no histórico (lida do próprio
  `event.state`, não sempre "home" direto — evita pular etapas quando o
  operador navegou por várias abas antes de "Hoje").
- Uma trava (`suppressTabPushRef`) evita que a própria mudança de aba
  disparada pelo `popstate` empilhe uma entrada nova (o que faria o
  histórico crescer sem fim e o botão de voltar nunca "andar" de
  verdade).

**Limitação conhecida, documentada e aceita**: fechar a conversa pelo
botão "voltar pra lista" DENTRO do app (não pelo botão do Android) não
desempilha a entrada de histórico correspondente. Na pior hipótese isso
custa 1 aperto de voltar "à toa" antes de sair de verdade — nunca uma
trava sem conseguir sair do app. Resolver isso por completo exigiria
sincronizar `history.back()` programático a cada fechamento manual, com
risco real de loop entre efeitos; dado que o pedido original é
justamente "não travar no app", preferi a versão mais simples e segura
nesta primeira rodada.

Arquivos alterados: `src/App.tsx`, `src/components/WhatsAppLeadsSim.tsx`.
