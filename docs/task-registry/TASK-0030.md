## Objetivo

Follow-up da TASK-0029: depois do fix da fonte/cor da faixa, o dono do produto testou de novo em produção (`/catalogo/monique-teste`, print real do celular) e os títulos grandes (h1 do hero, h2 "De la duda al resultado...") continuavam quase ilegíveis — a itálica da fonte já aparecia certa, mas a cor seguia muito clara/"fantasma".

## Diagnóstico

Padrão observado: todo texto que já tinha `color` **explícito** no CSS (subtítulo, eyebrow, preço, faixa de confiança) sempre renderizou certo; só os elementos que dependiam de **herança** (`h1`/`h2`/`h3`/`h4`/`.brand`, sem `color` próprio, herdando do `body`) ficavam ilegíveis. Essa página compartilha o documento com o `index.css` do painel principal (que declara `:root { color-scheme: dark }`, porque o resto do app é escuro de propósito) — a hipótese mais provável é o "Tema escuro automático" do Chrome Android tratando elementos com cor só herdada como "sem estilo próprio" e aplicando a heurística de inversão/lavagem de forma diferente dos elementos com cor explícita.

Tentei reproduzir localmente com a flag `--force-dark-mode --enable-features=WebContentsForceDark` do Chromium desktop (existe pra testar esse recurso), mas ela inverte a página inteira de forma uniforme e legível — não reproduz o "lavado parcial só nos títulos" visto no celular real. Ou seja, não consegui confirmar 100% localmente, mas a correção aplicada é a recomendação oficial do Chrome pra esse cenário e, independente do mecanismo exato, torna o CSS mais robusto por si só.

## Correção

`src/components/PublicCatalogPage.tsx`:
- `color: #211d1a;` explícito adicionado em `.brand`, `.catalog-hero h1`, `.steps-section h2/.services-section h2/.faq-section h2`, `.step h3`, `.product-card h4`, `.catalog-state h1` — todos os elementos que antes só herdavam a cor do `body`.
- Novo `useLayoutEffect` que injeta `<meta name="color-scheme" content="light">` no `<head>` enquanto a página está montada (removido no unmount) — sinal que a documentação do Chrome trata como definitivo pra desligar o tema escuro forçado numa página clara, complementando o `:root { color-scheme: light }` que já existia só em CSS.

A simulação de tema escuro forçado do Chromium desktop não reproduziu o bug exato do Android, então essa parte específica fica sem confirmação automatizada — só a validação manual do dono do produto no celular real vai confirmar de verdade.
