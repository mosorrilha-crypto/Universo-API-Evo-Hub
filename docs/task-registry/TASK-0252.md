## Objetivo

Disparo em massa vira módulo com liga/desliga por tenant + entrada no menu + fix responsividade

## Atualizações

O Disparo em Massa (broadcast/marketing, TASK-0171) estava hard-gated a `requireRole('saas_admin')` em todas as ~22 rotas de `server/routes/broadcast.ts` e só existia dentro do SaaS Admin Dashboard — nenhum tenant normal (nem o admin da própria empresa) conseguia ver ou usar. A pedido do usuário, virou um módulo real: liga/desliga por tenant pelo SaaS Admin, aparece no menu de navegação de quem tem acesso.

Reaproveitado, ponta a ponta, o padrão já em produção de **Logs do Sistema** (`operations.system_logs`) — entitlements por feature (`features`/`plan_feature_rules`/`tenant_feature_overrides`, `server/services/featureEntitlementService.ts`): nova feature `marketing.broadcast` nasce fechada pra todo mundo (`default_enabled=false`), e só um override manual do SaaS Admin (já existente, via `TenantEntitlementsModal.tsx` + `POST /api/admin/tenants/:id/feature-overrides`) libera por tenant. Nenhuma UI de admin nova, nenhuma rota nova.

Papel mínimo do lado do tenant: **admin** (mesmo nível de Logs do Sistema/Qualidade da IA) — envolve token real da Meta e risco de custo/reputação por envio em massa.

**Mudanças:**
- `supabase/migrations/0078_broadcast_feature_gate.sql` (novo) — cadastra a feature `marketing.broadcast`; aplicada via `mcp__Supabase__apply_migration`, confirmada em `list_migrations` e via SQL direto (feature `default_enabled=false`, 3 `plan_feature_rules` seedadas com `enabled=false` pelo trigger `features_seed_disabled_rule` já existente desde a migration 0063).
- `server/routes/broadcast.ts` — renomeado `requireSaasAdmin` → `requireBroadcastAdmin`, rebaixado de `requireRole('saas_admin')` pra `requireRole('admin')` (22 ocorrências, `replace_all`); comentário de topo atualizado.
- `src/components/BroadcastAdminPanel.tsx` — comentário de topo atualizado; **fix de responsividade** (achado com print real do usuário, mobile): 3 linhas de formulário com `flex items-end gap-N` sem `flex-wrap` e um `flex-1` (flex-basis:0) competindo com irmãos de largura própria (select de texto longo, botão) — o campo `flex-1` encolhia até ~1 caractere visível em vez do layout quebrar linha. Corrigidas as 3 ocorrências (`:767` CSV, `:780` segmento — a quebrada no print, `:983` agendamento): `flex items-end gap-N` → `flex flex-wrap items-end gap-N`, e `flex-1` → `flex-1 min-w-[160px]` no wrapper do input.
- `src/lib/tenantCapabilities.ts`, `src/types.ts`, `src/lib/activeTab.ts`, `src/App.tsx`, `src/components/Header.tsx` — gate `broadcast` replicando exatamente o padrão de `systemLogs` (constante `canSeeBroadcast`, redirect se bloqueado, render com `OperationsModuleFrame` accent `blue` — `sky` não existe no componente, único ajuste em relação ao plano original —, item no menu "Configurar" com ícone `Radio` reaproveitado do próprio painel).
- Testes existentes ajustados pra incluir o novo campo `broadcast`: `src/lib/tenantCapabilities.test.ts`, `src/components/__tests__/Header.empresasMenu.test.tsx`.

**Validação:** `npm run lint` (tsc --noEmit) limpo; `npx vitest run` — 258/258 arquivos, 1419/1419 testes passando; `npm run build` limpo (vite + esbuild); `grep -rn "requireSaasAdmin" server/routes/broadcast.ts` sem ocorrências.
