## Objetivo

Reforça regra do agente: listar cada opção do catálogo com preço em vez de resumir faixa de preço quando cliente pergunta por categoria

## Atualizações

Pedido direto do dono do produto, com 2 prints reais de conversas do mesmo tenant no mesmo dia: numa (Lili Meza), a cliente perguntou pelos combos e a resposta listou cada combo com nome e preço, um por linha — certo. Noutra (Elvi), a cliente disse só "Cejas" (categoria genérica) e a resposta resumiu "tenemos... desde Gs 60.000 hasta Gs 150.000" — só uma faixa, sem dizer quais serviços existem nem qual preço é de qual.

**Investigação:** o dado já está correto e estruturado — `formatKnowledgeBaseForPrompt` (`knowledgeBaseStore.ts:915`) já monta o catálogo pro prompt item por item, com nome e preço de cada produto/variante, agrupado por categoria. O problema não é falta de dado na Base de Conhecimento — é a REGRA DE ESTILO (Camada 1, universal, `autoReply.ts`) não instruir explicitamente o modelo a listar as opções de uma categoria em vez de comprimir numa faixa resumida.

**Mudança:** nova regra 25 na lista de "REGRAS DE ESTILO" de `server/services/autoReply.ts` (mesma seção que já tem as regras 1-24, cacheada por tenant via `buildCachedSystemInstruction`) — quando a cliente menciona só uma categoria genérica com até 5 opções cadastradas no catálogo, lista cada uma com nome e preço em vez de resumir em faixa; acima de 5 opções, mantém o comportamento de pedir uma especificação curta (regra 15) antes de cotar. É uma regra universal (Camada 1), não específica de nenhum tenant — qualquer negócio com catálogo em categorias se beneficia do mesmo princípio. Não mexi no revisor de segurança (`replySafetyGate.ts`) — ele não replica as REGRAS DE ESTILO (foco dele é veracidade/compliance, não apresentação), e esta regra é só de estilo/qualidade comercial, não de segurança.

**Arquivos:** `server/services/autoReply.ts`.

**Validação:**
- `npm run lint` limpo (precisou de `npm install` — a `main` avançou desde a última sessão e trouxe `cookie-parser` como dependência nova, TASK-0306/0311); `npx vitest run` — 270 arquivos / 1494 testes (nenhum teste fixa o texto exato das regras numeradas, só a presença do marcador "REGRAS DE ESTILO"); `npm run build` limpo.
