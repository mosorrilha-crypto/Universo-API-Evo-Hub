# TASK-0160 — Corrige transcrição alucinada de áudio sem fala real que alimentava resposta automática

- **Iniciado em:** 2026-08-29T17:41:30.933Z
- **Agente/plataforma:** Claude
- **Issue central:** [#290](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/290)
- **Status:** concluído

## Objetivo

Bug real reportado pelo dono do produto com print do painel: ele enviou deliberadamente um áudio SEM nenhuma fala (silêncio) pro número da Monique. Mesmo assim o sistema gerou uma transcrição completa e plausível ("Oi, Ana! Tudo bem? Então, queria saber o valor pra fazer as sobrancelhas com henna e se você tem horário pra essa semana ainda.") — 100% inventada, já que não havia fala nenhuma. Essa transcrição alucinada alimentou o motor de resposta automática, que gerou um rascunho; só não chegou a sair porque o revisor pré-envio bloqueou.

## Atualizações

**Causa raiz confirmada em código:** `transcribeAudioWithGemini` (`server/services/geminiTranscription.ts`) nunca instruía o modelo sobre o que fazer quando não há fala real no áudio — o prompt força um JSON com `"transcription"` obrigatoriamente preenchida, e o Gemini, sem essa saída de escape, inventa uma fala plausível em vez de admitir que não ouviu nada (mesmo padrão de alucinação de ASR documentado em outros sistemas, tipo Whisper, quando forçados a produzir texto de silêncio).

O guard existente de "nunca fabricar dado" nesse arquivo (comentário original, linhas 81-86) só cobre o caminho de FALHA TÉCNICA da chamada (erro de rede/timeout, `source: 'fallback'`) — nunca cobria o caso em que a chamada tem sucesso técnico (`source: 'gemini'`) mas o CONTEÚDO retornado é alucinado. `transcriptionQueue.ts` só verificava `outcome.source === 'gemini'` pra decidir se dispara resposta automática, sem nenhuma checagem de que a transcrição continha fala real.

**Fix (2 arquivos):**
1. `geminiTranscription.ts` — nova regra explícita no prompt: se o áudio estiver em silêncio, só tiver ruído de fundo, ou a fala for curta/abafada demais pra captar conteúdo real, o modelo deve responder `"transcription": ""` (nunca inventar fala plausível), com os demais campos (summary/intent/sentiment/etc.) também neutros nesse caso.
2. `transcriptionQueue.ts` — novo `hasNoDetectedSpeech` (source 'gemini' + transcription vazia/em branco) tratado exatamente como uma falha técnica: nunca dispara resposta automática (gate atualizado), sempre escala pra revisão humana ("Áudio sem fala detectável (silêncio/ruído) — operador precisa ouvir manualmente antes de responder"), e grava `[Áudio sem fala detectável]` no histórico da conversa em vez de deixar a mensagem em branco no painel.

## Encerramento

**Arquivos:** `server/services/geminiTranscription.ts`, `server/services/transcriptionQueue.ts`, `server/services/__tests__/geminiTranscriptionSilence.test.ts` (2 testes novos: prompt contém a instrução anti-alucinação; `source: 'gemini'` com `transcription: ''` é devolvido corretamente quando o modelo reporta ausência de fala).

**Validação:** `npm run lint`, `npx vitest run` (227 arquivos, 1177 testes) e `npm run build` — todos limpos. Não escrevi teste de integração completo pro worker `transcriptionQueue.ts` (processJob) — o módulo importa ~10 outros serviços diretamente (sem injeção de dependência pros módulos internos), tornando um teste end-to-end desproporcional ao escopo deste fix; a lógica nova ali é um guard booleano simples, espelhando exatamente o padrão já existente pro caso `source === 'fallback'` (que também nunca teve teste dedicado).

**Pendente ou risco:** a mitigação é via instrução de prompt — não há garantia 100% de que o modelo sempre obedeça (mesma classe de risco que outras regras de prompt já documentadas no projeto, ex. TASK-0096 sobre a sugestão supervisionada trocando idioma apesar da regra explícita). Se esse tipo de alucinação persistir mesmo com a instrução, o próximo passo seria uma heurística adicional client-side (ex. duração mínima de áudio, detecção de energia/silêncio antes de mandar pro Gemini) — não implementado agora por falta de evidência de que a instrução de prompt sozinha seja insuficiente.
