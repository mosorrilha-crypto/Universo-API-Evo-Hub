## Objetivo

Desafoga tela de Atendimento: etiquetas no popover, badge de janela 24h, aviso do rodapé vira ícone

## Atualizações

Pedido direto do usuário com print real (mobile, conversa aberta): "nossa tela de atendimento está muito poluída com muitos cards de avisos, como podemos otimizar". Print mostrava 4 blocos empilhados, cada um seu próprio card de largura cheia, acima/abaixo da lista de mensagens: barra de etiquetas, card "CONTEXTO SUPERVISIONADO", faixa de status da janela de 24h ("aberta - faltam 17h") e o aviso fixo de assunção de controle acima do campo de texto. Todos vivem em `src/components/WhatsAppLeadsSim.tsx` (mais `ContactContextPanel.tsx` pro item 2), cada um como `<div>` irmão independente — já a 3ª/4ª rodada de enxugamento dessa tela (TASK-0185/0187 já tinham simplificado a barra de etiquetas e feito o card de contexto se auto-esconder quando vazio).

Decisões confirmadas com o usuário (`AskUserQuestion`) antes de implementar:
1. Janela de 24h aberta e sem ação pendente → vira badge pequeno no cabeçalho (junto da linha telefone/mensagens), reaproveitando o mesmo padrão visual do pill "ao vivo" já existente. O card cheio com botão continua idêntico a hoje quando a janela fecha (aí sim há ação real: reengajar ou reabrir).
2. Aviso fixo do rodapé → vira ícone `Info` (lucide) com tooltip nativo (`title`) + `onClick` com `window.alert` (cobre toque no mobile, onde `title` não abre sozinho), dentro da caixa arredondada do composer, mesmo estilo do botão de emoji.
3. Barra de etiquetas → sugestões tracejadas saem da barra sempre visível e passam a morar dentro do popover que já existe no botão "+ Nova" — mesma lógica/ações de aplicar e excluir do catálogo, só que sob demanda.

Adenda de baixo risco (decidida por mim, mesmo arquivo/print): o texto do card "CONTEXTO SUPERVISIONADO" cortava no meio de uma palavra (`truncate`, uma linha só) — trocado por `line-clamp-2` (já usado em outros 9 componentes do repo, Tailwind v4 nativo, sem plugin extra) pra mostrar mais contexto antes de cortar, sem mudar a lógica de visibilidade do card (que já se auto-esconde quando não há dado real).

**Mudanças:**
- `src/components/WhatsAppLeadsSim.tsx` — as 3 mudanças de gate/posição descritas acima; import de `Info` acrescentado ao bloco de ícones lucide-react já existente.
- `src/components/ContactContextPanel.tsx` — `truncate` → `line-clamp-2` no texto principal da variante compacta.

Nenhuma mudança de backend, nenhuma mudança de estado/lógica de negócio — só reorganização visual e de quando/onde cada informação aparece. Alerta de escalonamento (`:4064-4091` original, sinal de segurança) intocado por decisão explícita já registrada no código.

**Validação:** `npm run lint` (tsc --noEmit) limpo; `npx vitest run` — 258/258 arquivos, 1419/1419 testes passando (sem teste novo — mudanças são de apresentação, sem lógica nova pra cobrir); `npm run build` limpo (vite + esbuild).

**Pendente:** verificação manual pós-deploy (não automatizável neste ambiente) — confirmar visualmente numa conversa real: (a) sem etiqueta aplicada, barra compacta e sugestões só aparecem ao tocar "+ Nova"; (b) janela de 24h aberta mostra badge pequeno no cabeçalho, sem card de linha inteira; janela fechada mantém o card cheio com botão igual antes; (c) rodapé mostra só o ícone de info, toque/hover mostra o aviso completo; (d) texto do "CONTEXTO SUPERVISIONADO" quebra em até 2 linhas em vez de cortar no meio da palavra.
