# TASK-0262 — Firebase sem apiKey quebrava o boot inteiro do app (tela branca), nao so login/Firestore como o aviso sugeria

- **Status:** concluído

## Objetivo

Firebase sem apiKey quebrava o boot inteiro do app (tela branca), nao so login/Firestore como o aviso sugeria

## Atualizações

Achado feito testando o painel de verdade num navegador, não por leitura
de código — pedido do dono do produto pra usar a skill `agent-browser`
recém-instalada (PR #639/#640) exatamente pra pegar esse tipo de coisa
que passaria despercebida numa revisão só de código.

Subi o servidor local (`npm run dev`) sem `SUPABASE_URL`/`SUPABASE_KEY`
configuradas (modo demo documentado no `CLAUDE.md`/`.env.example` — evita
qualquer risco de tocar dados reais de produção durante o teste) e abri
`http://localhost:3000` com `agent-browser`. Tela completamente branca,
`#root` com `innerHTML.length === 0` — o React nunca chegava a renderizar
nada. `agent-browser console` não mostrava nenhum erro (só o aviso comum
de `[firebase] VITE_FIREBASE_API_KEY não configurada`), mas o comando
dedicado `agent-browser errors` revelou a causa real: uma
`FirebaseError: auth/invalid-api-key` **não capturada**, lançada de forma
síncrona em `src/lib/firebase.ts:49` (`export const auth = getAuth(app)`)
no momento em que o módulo é avaliado — ou seja, antes mesmo de
`main.tsx` chegar em `createRoot(...).render(...)`. Qualquer exceção
síncrona durante a avaliação da cadeia de imports interrompe o processo
inteiro, então o app inteiro falhava ao carregar, não só "login com
Google/e-mail e Firestore" como o aviso na linha ao lado (`console.warn`)
dava a entender.

**Correção** (`src/lib/firebase.ts`): inicialização do Firebase
(`initializeApp`/`getAuth`/`getFirestore`) passa a ser condicional —
só roda se `firebaseConfig.apiKey` estiver presente. Sem apiKey, `auth`/
`db` ficam `undefined` e cada função exportada (`loginWithEmailPassword`,
`registerWithEmailPassword`, `loginWithGoogle`, `resetUserPassword`,
`logoutFirebase`, `onAuthUpdate`) passa por um guard (`requireAuth()`/
`requireDb()`) que lança um erro claro e capturável só quando alguém de
fato tenta usar a função — não mais no import do módulo. Confirmado que
só `loginWithGoogle` é chamado em algum lugar do app hoje
(`LoginModal.tsx`), que já tem um `try/catch` em volta da chamada
(`setErrorMsg` no catch) — então o comportamento pra quem clicar em
"Autenticar com Conta do Google" sem Firebase configurado passa a ser
uma mensagem de erro no próprio formulário, não mais um crash da
aplicação inteira.

**Validação visual, não só de código**: depois da correção, recarreguei
o app no `agent-browser` numa sessão totalmente nova (`close --all` +
`open` de novo) — zero erros (`agent-browser errors` vazio), `#root` com
30443 caracteres de HTML real, e o screenshot confirma a tela de login
("Acesso seguro à plataforma") renderizando por completo, com os dois
métodos de login (e-mail/senha e Google) visíveis.

Arquivos alterados: `src/lib/firebase.ts`.

**Sincronização com `main`:** ao registrar esta tarefa, `main` já tinha
avançado só com o merge do próprio PR anterior desta sessão (#640,
registro do hook do `agent-browser`) — `git merge origin/main` resolveu
como fast-forward, sem conflito.

## Encerramento

**Status: concluído.** Bug real de robustez de boot, encontrado por teste
de navegador de verdade (exatamente o tipo de achado que uma revisão só
de código deixaria passar, já que o `console.warn` ao lado do bug real
sugeria degradação graciosa que o código não entregava). Correção
mínima e escopada (só `firebase.ts`, sem mudar comportamento quando o
Firebase ESTÁ configurado corretamente — produção real não é afetada,
já que lá a apiKey existe). Sem self-merge.

**Validação:** `npm run lint`, `npx vitest run` (259/259 arquivos,
1423/1423 testes) e `npm run build`, todos limpos, após o merge com
`main`. Validação visual real via `agent-browser`: tela branca antes da
correção → tela de login renderizando por completo depois, confirmado
por screenshot e por `#root` deixando de estar vazio.

**Pendente ou risco:** nenhum conhecido — mudança puramente defensiva
(guard antes de usar `auth`/`db`), sem alterar o caminho feliz (Firebase
configurado, que é o caso de produção). Não testei o clique real em
"Autenticar com Conta do Google" sem Firebase configurado (só confirmei
que a página carrega e que o guard existe no código) — se quiser,
posso confirmar esse clique específico numa próxima rodada.
