## Objetivo

Menu mobile: fecha ao tocar fora e ao arrastar pra cima, aparecimento suave, reorganiza escala de fonte e ícones

## Atualizações

Pedido direto do dono do produto, com print do menu hambúrguer mobile
("Universo") aberto, listando 3 pontos.

**Achado real ao investigar** ("ele não fecha"): o menu mobile (`Header.tsx`,
estado `isMobileMenuOpen`) nunca teve um listener de clique fora nem de
tecla Escape — diferente de TODOS os outros menus do mesmo arquivo
(`isProfileMenuOpen`, `openToolsMenu`, `isMobileTenantMenuOpen`, todos com
seu próprio `useEffect` de fechar ao clicar fora). O único jeito de fechar
era: tocar de novo no ícone que abriu, ou selecionar uma aba (que já chamava
`setIsMobileMenuOpen(false)` dentro de `selectTab`). Confirmado lendo o
código antes de mexer, não só pelo relato.

1. **Aparecimento suave.** Reusa `.animate-page-enter` (fade + slide de 8px,
   já existente no `index.css`, usado noutras partes do painel) — sem
   inventar uma animação nova.
2. **Fecha ao tocar fora + arrastando pra cima.**
   - Toque fora: um backdrop `fixed inset-0` (`z-20`, abaixo do painel do
     menu em `z-30` e do header em `z-30` — o header continua sempre
     clicável por cima) fecha ao clicar, mesmo padrão já usado nos popovers
     de anexo/emoji do Atendimento (TASK-0184).
   - Arrastar pra cima: `onTouchStart`/`onTouchEnd` no painel do menu —
     mede a distância vertical do gesto; acima de 48px pra cima, fecha.
     Escopo: só o wrapper do menu inteiro tem o listener (não cada item
     isolado), então funciona em qualquer ponto do menu.
3. **Organização + escala de fonte/ícones.**
   - Adicionado um rótulo de seção "Navegação" (mesmo padrão visual já usado
     pra "Empresa ativa"/"Modo visual" logo abaixo) — antes a lista de abas
     e os cartões de conta/aparência tinham o mesmo peso visual, sem
     nenhuma divisão clara.
   - Fonte dos itens de navegação: `text-sm` (14px) -> 15px; ícones:
     `w-4 h-4` (16px) -> 20px. Escopado via CSS (`.mobile-nav-menu__items`)
     em vez de editar `renderTab`/`renderSubmenuItem` diretamente — essas
     funções são COMPARTILHADAS com a barra de navegação desktop, que o
     dono do produto não reclamou; iria mudar as duas ao mesmo tempo se
     tivesse editado ali. O seletor CSS também ficou restrito só à lista de
     navegação (não ao menu inteiro), pra não inflar os cartões de "Empresa
     ativa"/"Modo visual" logo abaixo, que têm botões pequenos de propósito
     (chips compactos).

Arquivos alterados: `src/components/Header.tsx`, `src/index.css`.

## Encerramento

desta sessão: sem verificação em dispositivo real (o gesto de arrastar em
particular só é testável de verdade num touchscreen) — não fiz self-merge.

**Validação:** `npm run lint`, `npx vitest run` (237/237 arquivos,
1275/1275 testes, incluindo `Header.empresasMenu.test.tsx` que cobre o menu
mobile) e `npm run build`, todos limpos.

**Pendente ou risco:** confirmar em dispositivo real touch que o gesto de
arrastar pra cima fecha o menu sem interferir no scroll da lista de
