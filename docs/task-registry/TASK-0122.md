## Objetivo

Fecha a fila de Pendências da Agenda (botão já existia sem conteúdo real)

## Atualizações

**Contexto:** dono do produto pediu auditoria da PR #494 ("mapear processos e fila de pendências da Agenda", aberta por outro agente). A auditoria encontrada:

1. **PR #494 estava muito desatualizada** — o ponto real onde divergiu do `main` (`git merge-base`) é o commit `6c2b185` (PR #465), bem mais antigo que o `base.sha` que a API do GitHub reportava (`43a12a4`). Nesse intervalo, `main` já recebeu 11 commits tocando exatamente os mesmos arquivos (`agenda mobile hierarchy`, `growth dashboard e ad account snapshot`).
2. **Duas das três frentes da PR #494 já estavam implementadas em `main`, de forma diferente e mais nova**: (a) a navegação móvel "Hoje/Calendário/Pendências" já existe em `AgendaWorkspace.tsx` (até com layout responsivo melhor); (b) o `accountSummary`/`calculateAvailableSpendCap` (saldo e limite de gasto da Meta Ads) que a PR tentava adicionar em `metaAdsInsightsService.ts`/`TrafficCenter.tsx` já foi implementado por outra tarefa (commit `786dcf1`, "optimize growth dashboard and expose ad account snapshot") — mesclar a versão da PR #494 aqui seria redundante/arriscado.
3. **Achado real e ainda válido**: o botão "Pendências" já existe em produção, mas é um beco sem saída — a CSS só escondia parte do calendário, sem nenhuma seção real de pendências renderizada. `pendingAppointments` em `AgendaFinanceiroCenter.tsx` era código morto (calculado, nunca usado em nenhuma UI).
4. **Gap adicional identificado no próprio texto da PR #494** (que descrevia corretamente o problema mesmo com implementação desatualizada): um atendimento já concluído com cobrança ainda em aberto deveria voltar pra fila de pendências pra revisão pós-atendimento — a implementação original da PR filtrava `!event.completed`, nunca cobrindo esse caso.

**Decisão (confirmada com o dono do produto):** não mesclar a PR #494 como está — implementar só a parte que genuinamente falta em produção, direto em cima do `main` atual, e fechar a #494 como superada.

**Fix (`src/components/AgendaFinanceiroCenter.tsx`):** substitui a `pendingAppointments` morta por uma lista real: compromissos não concluídos com cobrança pendente/sem registro entram na fila (regra igual à intenção original); compromissos concluídos só voltam se o Financeiro estiver habilitado e a cobrança ainda não estiver "pago" (fecha o gap do item 4). Ordena por urgência (atrasado > pendente > sem registro) e depois por data, com `slice(0, 12)`. Nova seção `<section className="agenda-financeiro-workspace__pending">` reaproveita o `EventCard` já existente — nenhum componente novo.

**Fix (`src/index.css`):** ajusta as 3 regras de CSS mobile (`agenda-mobile-today/calendar/pending`) pra realmente esconder a seção de Pendências nas outras duas visões e mostrar SÓ ela (escondendo a seção do calendário inteira) na visão "pending" — antes a visão "pending" era idêntica à "today".

**Testes novos:** `src/components/__tests__/AgendaFinanceiroCenter.pendingQueue.test.tsx` (3 testes) — compromisso futuro sem cobrança confirmada aparece; atendimento concluído com cobrança aberta volta à fila e um concluído já pago não aparece; sem módulo Financeiro habilitado, um evento concluído nunca entra na fila (evita "pendência" sem sentido nesse caso).

**Validação:** `npm run lint` limpo; `npx vitest run` — 220 arquivos / 1137 testes aprovados; `npm run build` limpo.

**PR #494:** fechada como superada (não mesclada) — comentário explicando o motivo publicado na própria PR antes do fechamento.

**Pendente ou risco:** nenhum sobre este fix específico. Fica como aprendizado: o `base.sha` reportado pela API de PR do GitHub não é confiável como indicador de quão desatualizada uma branch está — usar sempre `git merge-base` real antes de decidir resolver conflitos "na mão".
