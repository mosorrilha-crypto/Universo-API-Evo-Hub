## Objetivo

Achado real na sessão anterior (PR #405, itens 3/4): a tela "Tenants & Conexões" e os 3 botões de conexão (WhatsApp QR, CAPI, Instagram) em `SaaSAdminDashboard.tsx` mantinham 4 cópias independentes da lista de tenants (`useState` + `fetchRealTenants` local cada um). Criar/editar/excluir um tenant só atualizava a cópia local de quem agiu — as outras 3 só refletiam depois de um F5 manual na página. Confundiu o dono do produto duas vezes na mesma sessão anterior (achava que o cadastro tinha falhado).

## Atualizações

- Criado `src/hooks/useRealTenants.ts` — store compartilhado fora do React (module-level, `useSyncExternalStore`), com uma única função `refetchRealTenants()` e um único array `tenants` que qualquer componente lê via `useRealTenants()`.
- Refatorados os 4 pontos em `SaaSAdminDashboard.tsx` (`ConectarEvolutionQrCode`, `GerenciarCredenciaisCapi`, `GerenciarCredenciaisInstagram`, `SaaSAdminDashboard`) pra consumir o hook em vez de `useState`+fetch próprios — mantendo os nomes de variável locais (`isLoadingTenants`, `fetchRealTenants`) via alias na desestruturação, pra não precisar tocar no resto de cada componente.
- Lógica de "selecionar o primeiro tenant automaticamente" (que dependia do array recém-buscado dentro do próprio `fetchRealTenants`) movida pra um `useEffect` observando `realTenants`, já que agora a atualização chega via re-render do store externo, não de forma síncrona dentro da função de fetch.
- Removida a interface `RealTenant` local duplicada (o hook exporta a sua própria, mais completa).
- Testes novos `src/hooks/__tests__/useRealTenants.test.ts` (3 casos, usando `renderHook` do `@testing-library/react` + `vi.resetModules()` pra isolar o store entre testes): dois consumidores independentes leem a mesma lista; `refetchRealTenants()` chamado por um atualiza o outro sem F5; falha de rede não quebra o hook.
- Validado com `npm run lint` (limpo), `npx vitest run` (890 testes, 172 arquivos, todos verdes), `npm run build` (limpo).
- **Nota de processo:** o PR anterior (#405, que descobriu e documentou esse gap como follow-up) já tinha sido mergeado quando esta tarefa começou — branch recriada a partir do `main` atualizado (`git checkout -B <branch> origin/main`) em vez de empilhar em cima do histórico já mergeado, conforme instrução do harness.
