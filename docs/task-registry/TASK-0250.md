# TASK-0250 — Painel de qualidade: ver lista completa de perguntas e respostas de uma rodada de avaliação, incluindo casos aprovados

- **Iniciado em:** 2026-09-03T19:08:00.472Z
- **Agente/plataforma:** Claude
- **Issue central:** [#504](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/504)
- **Status:** concluída

## Objetivo

O dono do produto pediu diretamente: além de ver "X/Y aprovados" na tela de
"Avaliação automática do agente" (`QualityAuditCenter.tsx`), poder abrir
qualquer rodada e ver a lista completa de pergunta+resposta gerada,
**inclusive os casos que passaram** — não só os que viraram achado em
`quality_reviews` — pra conseguir auditar sozinho se o veredito do
julgador/revisor automático estava mesmo certo. Motivação real: várias
tasks recentes desta sessão (TASK-0235 a TASK-0248) encontraram o
julgador/revisor errado nos dois sentidos (reprovando resposta certa,
aprovando resposta com problema), então "confiar no resumo agregado" não é
suficiente.

## Atualizações

`runAgentEvaluation` (`agentEvalService.ts`) já calculava, pra cada caso
sintético gerado, um `AgentEvalCaseResult` completo (pergunta, histórico,
tipo de agente, bolhas de resposta, veredito de segurança, veredito de
qualidade, `passed`) e já expunha isso via um parâmetro `onCaseResult`
— mas nenhuma rota do painel conectava esse callback a persistência
alguma; só um script de CLI usava, pra dump em arquivo local. Ou seja, o
dado que o dono do produto pediu já existia em memória durante a rodada,
só nunca era salvo.

Implementado:
- **Migração** `supabase/migrations/0077_agent_eval_run_cases.sql`
  (renumerada de 0076 pra 0077 depois de colidir com
  `0076_conversation_list_summary_window.sql`, mesclado por outra sessão
  enquanto esta task estava em andamento — a tabela já tinha sido criada
  no Supabase via `apply_migration` com o nome lógico
  `agent_eval_run_cases`, então só o arquivo local precisou ser renomeado)
  — cria `agent_eval_run_cases` (run_id, tenant_id, category, question,
  history jsonb, agent, bubbles jsonb, passed, safety_approved,
  safety_reason, quality_issues jsonb, suggested_fix, error, created_at),
  índice em `(run_id, created_at)` e RLS `tenant_jwt_isolation` no mesmo
  padrão de `0075_agent_eval_runs.sql`.
- **`server/services/agentEvalRunCaseStore.ts`** (novo) —
  `recordAgentEvalRunCase` e `listAgentEvalRunCases`, seguindo o padrão de
  mapeamento de linhas de `agentEvalRunStore.ts`.
- **`server/routes/qualityAudit.ts`** — conecta `onCaseResult` (na chamada
  já existente de `runAgentEvaluation` em `POST
  /api/quality-audit/eval-runs`) pra gravar cada caso via
  `recordAgentEvalRunCase` (fire-and-forget com `.catch()` só logando
  aviso — nunca deve derrubar a rodada de avaliação em si); nova rota `GET
  /api/quality-audit/eval-runs/:runId/cases` lista os casos de uma rodada.
- **`src/components/QualityAuditCenter.tsx`** — cada linha do histórico de
  rodadas com `completedCount > 0` fica clicável ("Ver perguntas e
  respostas"), abrindo um drawer lateral (mesmo padrão visual do drawer já
  existente de revisão individual) com cada caso: ícone/selo
  aprovado/reprovado, categoria e tipo de agente, pergunta gerada, bolhas
  de resposta reais do atendente, e — se reprovado — motivo de
  segurança/qualidade.
