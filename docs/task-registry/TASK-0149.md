## Objetivo

captura utm_source no clique do catalogo pra distinguir trafego de anuncio vs organico/direto

## Atualizações

**Contexto:** ao analisar por que a campanha "Catálogo — Tráfego Site" tem custo por conversa de ~R$47-49 (muito acima do CTWA nativo), o gestor pediu pra comparar a taxa de conversão de quem chega pela página do catálogo vindo de anúncio vs. tráfego orgânico/direto. Investigando, achei que isso era impossível: o link do anúncio não tinha nenhum parâmetro de rastreamento, nosso endpoint de clique só grava `source` (qual CTA/versão da página gerou o clique, não de onde a visita veio), e todos os links de saída usam `rel="noreferrer"`.

**Implementado:**
- `supabase/migrations/0067_public_catalog_click_utm_source.sql`: nova coluna `utm_source` (text, nullable) em `public_catalog_whatsapp_clicks`, aplicada via Supabase MCP (`apply_migration`, projeto `pkocepjfedtsxmufymvd`).
- `server/services/publicCatalogClickStore.ts`: `recordCatalogWhatsappClick` aceita e grava `utmSource`; `CatalogClickRecentEntry`/`CatalogClickLead` expõem `utmSource`; novo agrupamento `byOrigin` (análogo ao `bySource` já existente) no retorno de `getCatalogClickAnalytics`, pra comparar cliques/conversão por origem de tráfego.
- `server/routes/publicCatalog.ts`: `GET /api/public/catalog/:slug/whatsapp-click` lê `req.query.utm_source` (sanitizado, até 100 chars) e repassa pro store.
- `src/components/PublicCatalogPage.tsx` e `src/components/PublicCatalogMoniqueConcierge.tsx` (as duas páginas de catálogo público que geram clique pro WhatsApp): capturam `utm_source` da querystring da própria página no primeiro carregamento (`useState` lazy init) e propagam pra todos os links de clique-pro-WhatsApp (geral, produto, variante, botão direto).
- **Meta Ads**: os 5 anúncios da campanha "Catálogo — Tráfego Site (Luque)" (que apontam pra `PublicCatalogMoniqueConcierge.tsx`, `/catalogo/monique-teste/novo`) tiveram o link atualizado (`update_ad_creative`) pra incluir `?utm_source=meta_ads` — sem isso a instrumentação nova não teria dado real de anúncio pra comparar.

**Arquivos:** `supabase/migrations/0067_public_catalog_click_utm_source.sql`, `server/services/publicCatalogClickStore.ts`, `server/routes/publicCatalog.ts`, `server/routes/__tests__/publicCatalog.test.ts` (1 teste novo), `src/components/PublicCatalogPage.tsx`, `src/components/PublicCatalogMoniqueConcierge.tsx`, `docs/task-registry/TASK-0149.md`.

**Validação:** `npm run lint` limpo. `npx vitest run` — 225 arquivos / 1165 testes, todos verdes (incluindo o novo, que confirma `utm_source=meta_ads` gravado quando presente e `null` quando ausente). `npm run build` limpo (vite + esbuild). Migration aplicada e confirmada via Supabase MCP.

**Pendente ou risco:** nenhum de código. `byOrigin` só está exposto na API (`GET /api/public-catalog-settings/analytics`) — não criei UI nova na aba de Desempenho (`PublicCatalogSettings.tsx`) pra exibir essa comparação; se o gestor quiser ver isso no painel visualmente, é um passo pequeno a mais numa sessão futura. O dado real só começa a existir a partir de agora — os 5 anúncios do Catálogo foram atualizados com `utm_source=meta_ads`, mas cliques anteriores a essa mudança ficam com `utm_source: null` (esperado, não é regressão).
