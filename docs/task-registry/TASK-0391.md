# TASK-0391 — Corrige falha real no primeiro build do pipeline Docker: cache export incompatível com driver docker

- **Iniciado em:** 2026-09-11T20:59:14.937Z
- **Agente/plataforma:** Claude
- **Issue central:** [#504](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/504)
- **Status:** concluído

## Objetivo

A TASK-0390 (pipeline de build/publish Docker via GitHub Actions, PR #754) já tinha avisado explicitamente que não foi possível testar um build real na sessão anterior (rede do sandbox bloqueia o CDN do Docker Hub) — recomendei acompanhar a primeira execução real. Acompanhando: a primeira execução (run #1, disparada pelo push do merge do #754) falhou.

## Investigação

Log real do job (`build-and-push`, run 34646434440):

```
ERROR: failed to build: Cache export is not supported for the docker driver.
Switch to a different driver, or turn on the containerd image store, and try again.
```

Causa raiz: o builder Buildx padrão nos runners do GitHub usa o driver `docker` (o mesmo motor Docker do runner), que não sabe exportar cache — exigido por `cache-to: type=gha` no passo `docker/build-push-action`. Sem um passo `docker/setup-buildx-action` explícito, o `build-push-action` usa esse builder padrão em vez de criar um builder próprio com driver `docker-container` (que suporta exportação de cache).

## O que mudou

`.github/workflows/docker-publish.yml`: novo passo `docker/setup-buildx-action@8d2750c68a42422c14e847fe6c8ac0403b4cbd6f # v3.12.0` antes do login/build — cria o builder certo. SHA confirmado via `git ls-remote --tags` (mesma técnica usada na TASK-0390 pros outros dois SHAs, já que este repositório também está fora do escopo do GitHub liberado nesta sessão).

## Validação

YAML validado com `python3 -c "import yaml; yaml.safe_load(...)"`. Sem como rodar o workflow de novo localmente (mesma limitação de rede do sandbox da TASK-0390) — só confirma de verdade quando este fix chegar em `main` e a próxima execução automática do `docker-publish.yml` rodar.

## Pendente ou risco

Nenhuma área crítica tocada (só infraestrutura de CI, sem código de aplicação). Recomendo continuar acompanhando: se esta correção não bastar (ex: outro passo do build falhar depois), reportar aqui/na #504 antes de tentar de novo às cegas.
