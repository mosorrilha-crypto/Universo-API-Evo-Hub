## Objetivo

Refina menus da conversa: remove scrollbar visual, unifica notificações, separa Documento/Fotos, adiciona Localização e move push pra configurações gerais

## Atualizações

Seguimento direto da TASK-0283 (mesma sessão): o usuário mandou 3 novos prints anotados à mão sobre
os MESMOS dois menus (⋮ do cabeçalho e anexos), com pedidos mais específicos, e um terceiro print do
menu ⋮ REAL do WhatsApp (compacto, cantos arredondados, ancorado no canto, sem faixa vazia do lado).
Antes de implementar, perguntei 3 coisas (AskUserQuestion) pra não adivinhar decisão de produto:
(1) como unificar "Ativar notificações" (push do PWA) com "Silenciar notificações" (mute da
conversa) — respondeu: tirar o push daqui, mandar pras configurações gerais, manter só o de
silenciar com nome correto; (2) manter "Sugerir melhoria"/"Reportar bug" no menu ⋮ — respondeu:
manter; (3) o que o novo ícone "dados da conta" deveria abrir — respondeu: dados bancários/PIX.

**Achado real durante a investigação** (explica o "espaço vazio à direita" que o usuário apontou):
existia uma regra CSS (`@media (max-width: 640px) { .mobile-header-context-menu {...} }` em
`index.css`) que transformava esse menu ⋮ — JÁ corretamente ancorado no ícone via classes inline
(`absolute right-0 top-10 w-52 rounded-xl origin-top-right`) — num bottom sheet FULL-WIDTH com
`!important` sempre que a tela era menor que 640px, sobrescrevendo a largura compacta. Isso é
diferente do padrão real do WhatsApp (confirmado no 3º print): o menu ⋮ é uma caixa pequena
ancorada, nunca uma gaveta de largura total — essa distinção existe no WhatsApp real entre menus de
contexto (pequenos, ancorados) e pickers de ação como o de anexos (gaveta cheia). Removida a regra;
o menu agora usa o mesmo estilo compacto em qualquer largura de tela.

**Mudanças aplicadas:**

1. **`src/index.css`** — nova classe utilitária `.no-scrollbar` (rolagem funcional, sem a faixa
   visual do navegador — `scrollbar-width:none` + `::-webkit-scrollbar{display:none}`), aplicada
   no menu ⋮. Removida a regra `@media (max-width:640px)` que forçava o menu ⋮ a virar bottom sheet
   full-width; ajustado o `box-shadow` dos temas claro/limpo pra apontar pra baixo (dropdown), não
   mais pra cima (resquício do antigo bottom sheet).
2. **`src/hooks/usePushNotifications.ts`** (novo) — extrai `pushEnabled`/`pushBusy`/`pushError`/
   `togglePush` de dentro de `WhatsAppLeadsSim.tsx` pra um hook compartilhado, reaproveitado também
   no `Header.tsx` — evita duplicar a lógica de ativar/desativar push em dois componentes.
3. **`src/components/WhatsAppLeadsSim.tsx`**:
   - Removido o botão "Ativar notificações" (push) do menu ⋮ e da gaveta "Ferramentas" — não são
     ações desta conversa, são configuração de conta/dispositivo.
   - Renomeado "Ativar/Silenciar notificações" (mute desta conversa) pra "Silenciar esta
     conversa"/"Reativar notificações desta conversa" — nome sem ambiguidade agora que o push saiu
     do mesmo menu.
   - Menu de anexos: "Documento ou foto" virou dois tiles separados (Documento, ícone `FileText`,
     `accept` restrito a documentos; Fotos, ícone `ImageIcon`, `accept="image/*"`) — o `accept` do
     `<input type="file">` é setado dinamicamente antes do clique conforme o tile tocado.
   - Novo tile "Localização" no menu de anexos — manda o link do Google Maps já configurado em
     `knowledgeBase.locationMapsUrl` (mesmo campo que o próprio agente de IA já usa quando o
     cliente pergunta o endereço, ver `knowledgeBaseStore.ts`) como mensagem de texto. Só aparece
     quando o tenant já configurou esse link — nunca inventa um endereço. `handleSendTextMessage`
     ganhou um parâmetro opcional `overrideText` pra permitir mandar um texto pronto sem passar
     pela caixa de digitação (sem esse parâmetro, `setInputMessage` + chamada imediata enviaria o
     valor ANTIGO por causa da atualização assíncrona de estado — corrigido usando `overrideText`
     diretamente em vez de depender do estado `inputMessage`).
4. **`src/components/Header.tsx`** — novo botão de notificações push, usando
   `usePushNotifications`: um ícone na fileira desktop (ao lado de "Trocar minha senha") e uma
   linha própria "Notificações push" no menu mobile (junto de "Modo visual"). Erro do toggle
   (`pushError`) é repassado pro novo prop opcional `onToast`.
5. **`src/App.tsx`** — passa `onToast={showToast}` pro `<Header>`.

## Validação

- `npm run lint` (tsc --noEmit): limpo.
- `npx vitest run`: 264 arquivos / 1450 testes, todos passando (nenhum teste existente de `Header`
  quebrou mesmo sem passar a nova prop `onToast`, que é opcional).
- `npm run build`: build de frontend + servidor sem erros.
- Validação visual manual: harness temporário (removido ao final) renderizando `<Header>` +
  `<WhatsAppLeadsSim>` juntos (mesma composição real do `App.tsx`), com `window.fetch` mockado só
  pros endpoints de conversas, via `agent-browser`/Chromium (mobile 390×844). Confirmado:
  - Menu ⋮: agora é uma caixa compacta ancorada no ícone, cantos arredondados, sem vão vazio do
    lado (bug real confirmado via `getBoundingClientRect` antes/depois: `width` ia de `390px`
    — tela inteira — pra `208px`, batendo com `w-52`). Item de push removido; "Silenciar esta
    conversa" com nome correto. Scroll interno sem a barra visual confirmado via `getComputedStyle`
    (`scrollbarWidth: "none"`) — e depois de tirar o push, o conteúdo quase não precisa mais rolar
    (só 16px de overflow no pior caso testado, contra ~591px de altura visível).
  - Menu de anexos: 3 tiles (Documento, Fotos, Localização) lado a lado, cada um com ícone próprio.
    Testado o tile "Localização" de ponta a ponta — enviou o link do Maps mockado como mensagem de
    verdade na conversa.
  - Header: botão de push aparece no menu mobile ("NOTIFICAÇÕES PUSH", com botão "Ativar") e no
    menu desktop (ícone ao lado de "Trocar minha senha"); clique não gerou nenhum erro de console
    (o fluxo completo de assinatura push exige HTTPS/service worker real, fora do alcance deste
    ambiente de teste local).

## Pendências ou riscos

- **"Dados da conta" (PIX/dados bancários) NÃO foi implementado nesta tarefa** — decisão
  deliberada, não esquecimento. Diferente de "Localização" (que já tinha um campo pronto,
  `locationMapsUrl`), não existe hoje nenhum campo estruturado pra dados bancários/PIX do tenant em
  `AgentKnowledgeBase`/`Tenant` — e o sistema de Base de Conhecimento usa um allowlist de campos por
  tipo de documento (`KNOWLEDGE_BASE_DOCUMENT_FIELDS` em `knowledgeBaseStore.ts`) que exige registro
  em vários arquivos (tipo, formulário, backend, auditoria, diff de publicação). Implementar isso
  "de passagem" nesta mesma tarefa, sob pressão de tempo, arriscava (a) inventar/mal-configurar um
  campo financeiro sensível sem validação adequada, ou (b) quebrar o fluxo de rascunho/publicação já
  existente da Base de Conhecimento. Fica como próxima tarefa dedicada, com seu próprio
  TASK-XXXX — inclui campo novo em `AgentKnowledgeBase`, formulário em `AgentKnowledgeBase.tsx`,
  persistência no backend, e o tile no menu de anexos (mesmo padrão condicional usado aqui pra
  Localização, só aparece quando configurado).
- Não testei em produção/staging com dados reais — apenas com mocks locais.
