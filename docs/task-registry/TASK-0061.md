## Objetivo

Troca o acento verde do tema Limpo por azul (referencia Darwin AI)

## Atualizações

Pedido direto do dono do produto no chat: revisitar a referência original (dashboard "Darwin AI",
usada na TASK-0053 pra criar o tema Limpo) e usar o azul dela como acento, no lugar do verde
escolhido na implementação original.

- Mapeados sistematicamente os 7 tons de verde/emerald usados dentro dos blocos
  `html[data-theme='clean']` de `src/index.css` (28-29 cores distintas auditadas via script Node
  descartável) pros tons de azul equivalentes (paleta Tailwind blue 50/200/400/500/600/700),
  preservando o papel de cada um (fundo tintado, borda, texto, botão sólido, hover):
  `--action`/`--button-action` (#047857→#2563EB), `--button-action-hover` (#065F46→#1D4ED8),
  `--bubble-ai`/fundos claros (#ECFDF5/#F0FDF7→#EFF6FF), `--bubble-ai-border`/bordas
  (#A7F3D0→#BFDBFE), acentos de hover (#34D399→#60A5FA), scrollbar/tint decorativo
  (#10B981→#3B82F6, incluindo as variantes rgba equivalentes).
- Cuidado extra pra não vazar a mudança pros outros temas: várias regras no arquivo combinam o
  seletor `clean` com `dark` no mesmo grupo (ex: `.bg-emerald-500, html[data-theme='dark']
  .bg-emerald-500 { background-color: var(--action) !important; }`) — confirmado que TODAS essas
  usam a variável `--action` (que já é definida separadamente por tema), então só precisei mudar
  o valor de `--action` no bloco `html[data-theme='clean'] { ... }`, nunca o corpo das regras
  combinadas. Os poucos casos com cor literal hardcoded foram confirmados individualmente
  (contexto de cada linha) como exclusivos do `clean` antes de editar. `git diff` final confirma
  zero linhas de `light`/`dark`/`blue` tocadas.
- **Achado colateral real, corrigido**: validação visual com Playwright (Chromium pré-instalado)
  mostrou que o botão de login continuava verde mesmo após a troca. Causa: `.bg-emerald-600`
  (usado por ~54 botões primários no app, ex: `LoginModal.tsx`) nunca teve regra de override em
  NENHUM tema — só `.bg-emerald-500` tinha (`src/index.css:944-951`). Ficava sempre com o verde
  padrão do Tailwind, inclusive fora do tema escuro nativo (**o tema Azul já existente tem essa
  mesma lacuna hoje em produção** — confirmado com print, fora do escopo desta correção). Regra
  faltante adicionada só pro tema Limpo.
- Validado com `npm run lint` (limpo), `npx vitest run` (894 testes, 173 arquivos, todos verdes),
  `npm run build` (limpo), e visualmente com Playwright + Chromium pré-instalado
  (`playwright-core` instalado com `--no-save` em `/tmp`, não versionado): tela de login com
  `data-theme=clean` forçado via `localStorage` mostra ícone/badge/borda de foco/botão em azul,
  sem nenhum verde residual.

**Achado relacionado, não corrigido (fora do escopo pedido)**: o tema "Azul" já existente também
tem o mesmo gap de `.bg-emerald-600` sem override — o botão de login nesse tema hoje mostra verde
Tailwind padrão em vez do azul do próprio tema. Vale uma correção futura se alguém notar.
