## Objetivo

Preview visual das bolhas no rascunho bloqueado do Escalonamentos, evitando confusao com o separador / no textarea

## Atualizações

Achado relatado ao vivo pelo dono do produto (print real do painel mobile, 01/09/2026): mesmo com "Aprovar e enviar" já mandando bolhas separadas de verdade desde 30/08/2026 (`server/routes/conversations.ts`, `text.trim().split(' / ')` quando `escalationId` está presente), o card de "Rascunho bloqueado" no `EscalationsPanel.tsx` só mostrava o rascunho como UM bloco de texto com "/" literal no meio — visualmente igual ao bug antigo, mesmo o envio já estando correto. O operador não tinha como confirmar visualmente que sairia como mensagens separadas sem editar o texto.

Fix: nova preview read-only acima do `AutoResizeTextarea`, calculada com o MESMO split (`' / '`) usado no envio — mostra cada bolha já formatada como balão de chat (mesmo visual do WhatsApp), só quando há mais de uma bolha (`previewBubbles.length < 2` não renderiza nada, pra não poluir o caso comum de rascunho de 1 bolha só). Puramente aditivo: não muda o textarea nem o fluxo de envio, só dá visibilidade de que o "/" some no envio real. Operador pode aprovar direto, sem precisar editar, só conferindo a preview.

**Arquivos/commits:** `src/components/EscalationsPanel.tsx`.

**Validação:** `npm run lint` e `npm run build` limpos. Sem teste automatizado novo — `EscalationsPanel.tsx` não tem nenhum arquivo de teste hoje (nenhum já existente pra seguir o padrão, e montar toda a árvore de props obrigatórias só pra esta mudança puramente visual/aditiva não parecia proporcional); mudança é read-only (não altera nenhum estado nem o payload enviado).

**Pendente ou risco:** nenhum identificado — mudança aditiva, sem risco de regressão no envio real (usa o mesmo split já usado lá). Recomendo o dono do produto confirmar visualmente na próxima ocorrência real de rascunho bloqueado com mais de uma bolha.
