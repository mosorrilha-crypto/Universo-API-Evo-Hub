## Objetivo

separa cliques de WhatsApp por origem (catálogo original vs segundo catálogo) pra comparar conversão de verdade

## Atualizações

O usuário perguntou o potencial de conversão do segundo catálogo (TASK-0087). Ao investigar, achei
que os dois catálogos (`/catalogo/monique-teste` e `/catalogo/monique-teste/novo`) apontam pro
mesmo endpoint `/api/public/catalog/:slug/whatsapp-click` e gravam no mesmo contador
(`public_catalog_whatsapp_clicks`, sem coluna de origem) — não havia como comparar as duas
páginas com dado real, só juntas. O usuário topou resolver isso.

- Migration `0054_public_catalog_click_source.sql`: coluna `source` (nullable, "legacy"/"novo")
  em `public_catalog_whatsapp_clicks`. Aplicada em produção via Supabase MCP
  (`apply_migration`), confirmada em `list_migrations`.
- `recordCatalogWhatsappClick` ganhou parâmetro opcional `source`; a rota valida contra allowlist
  (`legacy`/`novo`, qualquer outro valor vira `undefined`/null).
- `getCatalogClickAnalytics` agora também agrega `bySource` (clicks/matched por origem), com
  `null` tratado como `legacy` (cliques antigos, de antes desta coluna existir).
- `PublicCatalogPage.tsx` (catálogo original) passou a mandar `source=legacy`; isso é a única
  mudança nesse arquivo desde que foi criado — decisão consciente pra permitir a comparação real,
  registrada aqui com transparência (o compromisso anterior era "zero linha alterada" nesse
  componente).
- `PublicCatalogMoniqueConcierge.tsx` (segundo catálogo) passou a mandar `source=novo`.
- Aba "Desempenho" (`PublicCatalogSettings.tsx`) mostra um comparativo lado a lado (cliques,
  conversas, taxa) por origem — só aparece quando há dado de mais de uma origem, pra não poluir a
  tela de tenants com um único catálogo.
- Testes: `publicCatalogClickStore.test.ts` (source persistido) e
  `publicCatalogSettings.test.ts` (bySource agregado corretamente, incluindo null→legacy).

## Encerramento

**Validação:** `npm run lint`, `npx vitest run` (186 arquivos, 963 testes) e `npm run build`,
todos limpos. Migration confirmada aplicada via `list_migrations`.

**Pendente ou risco:** os dados históricos de cliques anteriores a esta migration ficam como
`null`/"legacy" no comparativo (não dá pra saber retroativamente se vieram do catálogo antigo ou
de algum teste manual) — só cliques novos, de ambas as páginas, terão a origem correta. Sem
volume real ainda (páginas acabaram de subir), a comparação só vai ficar significativa depois de
algum tráfego.
