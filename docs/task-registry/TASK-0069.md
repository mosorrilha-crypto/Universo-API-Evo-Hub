## Objetivo

Torna recolhivel o resumo da operacao na tela de Atendimento (pedido direto com print do celular)

## Atualizações

Pedido direto do dono do produto, com print do celular anexado no chat: o bloco de resumo no topo
da tela de Atendimento (`AtendimentoWorkspaceFrame.tsx` — ícone+título, 2 cartões de contagem,
aviso "IA supervisionada", banner "Nenhuma mensagem é enviada sem aprovação") ocupava boa parte da
tela útil em mobile antes de qualquer conversa aparecer na lista.

- `src/components/AtendimentoWorkspaceFrame.tsx`: o bloco `.atendimento-workspace__signals` virou
  condicional, atrás de um botão de alternância compacto ("Resumo da operação · N pendências
  humanas ▾"). Começa **recolhido por padrão** (sem preferência salva) — o pedido era por uma
  "página de atendimento limpa e exclusiva". A contagem de pendências humanas continua visível no
  próprio texto do botão fechado, pra nunca esconder que existe algo esperando um humano só porque
  o resumo está fechado.
- Preferência de aberto/fechado persistida em `localStorage` (`atendimento_summary_open`), mesmo
  padrão já usado por tema/idioma em `AppPreferencesContext` — quem prefere ver sempre não precisa
  reabrir a cada visita.
- `src/index.css`: novo par de classes `.atendimento-workspace__summary-toggle`/`-chevron`,
  espelhando o estilo já usado no seletor de tenant (`.atendimento-workspace__tenant-trigger`/
  `-chevron`), com overrides pros 4 temas (Escuro nativo + Claro/Limpo/Azul).
- Testes novos em `AtendimentoWorkspaceFrame.test.tsx` (`@testing-library/react` + `jsdom`, 4 casos):
  recolhido por padrão sem localStorage prévio, contagem de pendências visível no botão fechado,
  expandir/recolher ao clicar, e persistência entre montagens. Descoberto durante a escrita que o
  projeto não usa `@testing-library/jest-dom` — ajustado pra matchers nativos (`toBeNull`/
  `getAttribute`), seguindo a convenção já usada em `Header.empresasMenu.test.tsx`.
- Validado com `npm run lint` (limpo — precisou de `npm install` primeiro, já que o branch foi
  recriado a partir do `main` atualizado e trouxe uma dependência nova, `sharp`, de outra PR
  mergeada nesta sessão), `npx vitest run` (903 testes, 174 arquivos, todos verdes), `npm run
  build` (limpo).
- **Validação visual real**: a tela de Atendimento de verdade exige login/Supabase configurado
  (indisponível neste sandbox). Montei o componente isoladamente numa página de preview temporária
  (`preview-temp.html`/`.tsx`, criados e removidos só pra essa checagem, nunca comitados) e validei
  com Playwright (Chromium pré-instalado) nos 4 temas — recolhido (barra compacta com contagem) e
  expandido (cartões completos), sem quebra visual em nenhum tema.

**Nota de processo:** o PR anterior (#414, já mergeado) foi a última vez que este branch tinha sido
sincronizado — sem PR pendente desta vez pra reiniciar, o branch já estava atualizado a partir do
`main` (mesma base do #414).
