# TASK-0027 — corrige erros de tipo string|string[] pós-migracao Express 5 (npm run lint quebrado no main)

- **Iniciado em:** 2026-08-23T21:00:00.000Z
- **Agente/plataforma:** Claude
- **Issue central:** [#290](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/290) (fechada sem sucessora, ver TASK-0026)
- **Status:** concluída

## Objetivo

Corrigir os ~98 erros de `npm run lint` (`tsc --noEmit`) que ficaram no `main` desde a migração pro Express 5 (PR #383, commit `63e8218`), identificados e documentados como pré-existentes durante a TASK-0026/PR #385.

## Causa raiz

`@types/express-serve-static-core` (trazido por `@types/express@5`) alargou `ParamsDictionary` pra `{ [key: string]: string | string[] }`, porque o Express 5/path-to-regexp v8 suporta segmentos repetidos (`/:nome+`, `*splat`) que produzem array. **Nenhuma rota deste projeto declara esse tipo de padrão** (confirmado por busca — zero rotas com `*` ou `+` no path), então `req.params.x` sempre é uma `string` de verdade em runtime; só o tipo estava errado.

Todos os pontos de erro passavam por `AuthenticatedRequest` (`server/middleware/auth.ts`), que tipava `req` como `Request<ParamsDictionary>`. Os 3 handlers sem essa anotação explícita (`googleCalendar.ts:88`, `admin.ts:46`, `admin.ts:81`) não erravam porque o TypeScript infere o tipo de `params` a partir da string da rota quando não há anotação explícita — só a anotação explícita força de volta o `ParamsDictionary` genérico largo.

## Correção

Um arquivo só: `server/middleware/auth.ts` — trocado `Request<ParamsDictionary>` por `Request<StringParamsDictionary>`, uma interface local `{ [key: string]: string }`. Corrige a causa raiz pra todo handler que usa `AuthenticatedRequest` de uma vez, em vez de fazer cast em cada um dos ~50 pontos de uso espalhados por `conversations.ts`, `crm.ts`, `financial.ts`, `googleCalendar.ts`, `qualityAudit.ts`, `roadmap.ts` e `admin.ts`.

## Validação

- `npm run lint`: 0 erros (antes: 98).
- `npx vitest run`: 165 arquivos, 858 testes, todos passando.
- `npm run build`: Vite + esbuild concluídos sem erro.

## Pendente ou risco

Nenhum conhecido — mudança é só de tipo (compile-time), não altera nenhum comportamento em runtime.
