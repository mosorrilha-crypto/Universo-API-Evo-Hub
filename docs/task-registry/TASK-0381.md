## Objetivo

Adiciona Playwright para testes E2E no navegador (fluxo login + abrir conversa como prova de conceito)

## Atualizações

**Contexto:** pedido direto do dono do produto — instalar Playwright pra
testar o app rodando de verdade num navegador, não só a lógica isolada que
o Vitest já cobre. Motivação explícita: vários bugs visuais recentes desta
sessão (caixa de mensagem estreita, aviso de 24h quebrando palavra por
palavra, botões sumindo em certa largura de tela) só foram descobertos
porque o dono do produto mandou print depois do deploy — um teste de
navegador real roda antes disso, sem depender de alguém notar.

**Implementado:**
- `npx create-playwright@latest` (TypeScript, só Chromium — mesmo browser
  já pré-instalado neste ambiente, `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` já
  setado —, sem baixar Firefox/WebKit, sem os specs de exemplo padrão).
- `playwright.config.ts` — `baseURL`/`webServer` configurados pra subir o
  próprio `npm run dev` (server.ts serve API + Vite juntos numa porta só)
  antes dos testes, reusando uma instância já rodando localmente
  (`reuseExistingServer`) em vez de sempre subir uma segunda.
- `vite.config.ts` — `test.exclude` ganhou `tests/**` (pasta do Playwright):
  sem isso, `npx vitest run` tentava rodar os specs `test()`/`test.skip()`
  da API do `@playwright/test` como se fossem testes do Vitest e quebrava
  ("test.skip() can only be called inside test, describe block or
  fixture") — achado real ao rodar a suíte depois do scaffold.
- `tests/login-and-open-conversation.spec.ts` (novo, prova de conceito) —
  login real (e-mail/senha) + clicar na primeira conversa da lista +
  confirmar que a caixa de digitar resposta aparece. Lê credenciais de
  `E2E_OPERATOR_EMAIL`/`E2E_OPERATOR_PASSWORD` (documentadas no
  `.env.example`, TASK-0381) e **pula** (não falha) quando ausentes — nunca
  deve usar a conta do tenant real de produção (a beauty studio pagante);
  o comentário no arquivo instrui criar um operador dedicado de teste via
  `npm run create:operator` num tenant de teste.
- `src/components/chat/LeadListRow.tsx` / `src/components/WhatsAppLeadsSim.tsx`
  — dois `data-testid` novos (`conversation-row`, `message-composer`), os
  únicos no frontend inteiro (confirmado por grep antes de começar — zero
  `data-testid` existiam). Sem eles o teste dependeria de texto visível
  (frágil, muda por idioma/copy) pra achar a lista de conversas.
- `package.json` — novo script `test:e2e` (`playwright test`).
- `.env.example` — `E2E_OPERATOR_EMAIL`/`E2E_OPERATOR_PASSWORD`/`E2E_BASE_URL`
  documentadas.

**Achado operacional (não é bug de código, é um fato sobre este
ambiente):** rodar `npm run dev`/`npx playwright test` aqui conecta ao
Supabase de PRODUÇÃO de verdade — as variáveis `SUPABASE_URL`/`SUPABASE_KEY`
já estavam presentes no shell desta sessão (confirmado pelos logs do
webServer citando tenants reais: Clic Piscinas, Monique, Dr. Daniel — os
mesmos tenants tocados em tarefas anteriores desta sessão). O teste rodado
sem `E2E_OPERATOR_EMAIL`/`E2E_OPERATOR_PASSWORD` pulou corretamente (design
proposital), então nenhum dado real foi criado/alterado — mas registrando
aqui pra quem for configurar CI/rodar localmente: nunca deixar esse teste
rodar sem credenciais de um tenant/operador dedicado a teste.

**Rodado de verdade ponta a ponta** (atualização depois do primeiro commit
desta task): o dono do produto passou credenciais de um operador `saas_admin`
real (confirmado via SQL antes de usar: vinculado ao tenant "Monique -
Evolution", slug `monique-teste` — o tenant de TESTE, não a beauty studio
real de produção). `E2E_OPERATOR_EMAIL=... E2E_OPERATOR_PASSWORD=...
npx playwright test` — **passou** (login real + primeira conversa da lista
+ composer visível, 17.5s).

**Achado/correção no caminho:** o Chromium pré-instalado neste ambiente
(`/opt/pw-browsers`, revisão 1194) não bate com a revisão que o
`@playwright/test` 1.63 tenta baixar sozinho (1243) — o launch falhava com
"Executable doesn't exist". Corrigido em `playwright.config.ts`: o projeto
`chromium` passa `launchOptions.executablePath: '/opt/pw-browsers/chromium'`
quando `PLAYWRIGHT_BROWSERS_PATH` está setada (só neste tipo de ambiente
sandbox — em CI/outra máquina sem essa var, cai no comportamento padrão do
Playwright).

**Validação:** `npx playwright test --list` (spec compila e é descoberto,
1 teste), `npx playwright test` sem credenciais (pula corretamente, sem
erro), `npx playwright test` COM credenciais reais de teste (1 passed,
17.5s), `npm run lint` (limpo), `npx vitest run` (293 arquivos / 1634
testes, todos passando — confirma que excluir `tests/**` resolveu o
conflito), `npm run build` (limpo).

**Pendente ou risco:**
- Sem CI configurado pra rodar `npm run test:e2e` automaticamente em PRs —
  fica como próximo passo natural, não incluído aqui por ser uma decisão
  de infraestrutura maior (precisa de secrets de CI, tenant de teste
  dedicado, etc.) que não foi pedida explicitamente. Se um CI de verdade
  não tiver `PLAYWRIGHT_BROWSERS_PATH` setada (ambiente diferente deste
  sandbox), o `executablePath` fixo não se aplica — cai no comportamento
  padrão (baixar o Chromium certo pra versão instalada), então não há
  acoplamento indevido a este ambiente específico.
- Durante o teste, o servidor local logou erros pré-existentes não
  relacionados a esta tarefa (`TOKEN_ENCRYPTION_KEY` ausente quebrando
  `GET /api/google-calendar/status` pros 3 tenants existentes) — não é
  regressão desta tarefa, é lacuna de configuração deste ambiente
  específico (faltam segredos de produção que não pertencem a um sandbox).
