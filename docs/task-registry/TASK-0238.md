# TASK-0238 — Ativa o login com Google de verdade (verificação de ID token no backend via Firebase Admin)

- **Issue central:** [#504](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/504)

## Objetivo

O botão "Autenticar com Conta do Google" já existia no `LoginModal.tsx` desde
antes, mas só provava posse do e-mail via Firebase client-side
(`signInWithPopup`) — nunca emitia um JWT de backend de verdade. O código
montava um `UserProfile` local com `tenantId: 'tenant_004'` fixo e
`onLogin(authenticatedUser, undefined)` (sem token), então o botão parecia
funcionar mas nenhuma rota protegida realmente abria (ficavam corretamente
bloqueadas com 401, já que não havia Bearer token real). Esta tarefa fecha
essa lacuna de verdade.

## Atualizações

**Política de acesso decidida com o dono do produto**: login com Google só
funciona para um e-mail que já corresponde a um operador cadastrado no
Supabase — igual à exigência do login por senha. Um e-mail Google sem
operador cadastrado é rejeitado, nunca cria conta automaticamente.

**`server/services/firebaseAdmin.ts` (novo)** — verifica o ID token do
Google contra a API do Firebase usando uma credencial de conta de serviço
(`FIREBASE_ADMIN_CREDENTIALS`, o JSON completo baixado do Firebase Console
como uma única variável de ambiente). Rollout sem quebra, mesmo padrão de
`tokenCrypto.ts`: a variável é opcional — sem ela, `verifyGoogleIdToken`
lança `FirebaseAdminNotConfiguredError` e a rota devolve 503 (login com
Google indisponível), mas login por senha e todo o resto do sistema
continuam funcionando normal. App do Firebase Admin cacheado (não
reinicializa a cada requisição).

**`server/routes/auth.ts`** — nova rota `POST /api/auth/login-google`
(mesmo `authLoginRateLimiter` por IP do login por senha): recebe `idToken`
do frontend, verifica via `verifyGoogleIdToken`, exige `emailVerified`,
busca operador por e-mail (`.ilike`, mesma busca case-insensitive do login
por senha) e — se encontrado — emite o mesmo JWT de sempre (`id`,
`tenantId`, `role`), passando pela mesma checagem de `tenants.is_active`.
A checagem de tenant bloqueado + emissão do JWT foi extraída pra um helper
`issueSessionForOperator` compartilhado entre as duas rotas de login, pra
não duplicar essa lógica.

**`src/components/LoginModal.tsx`** — o clique em "Autenticar com Conta do
Google" agora: `loginWithGoogle()` (Firebase, já existia) → pega o ID token
real (`googleUser.getIdToken()`) → `POST /api/auth/login-google` → constrói
o `UserProfile` a partir da resposta REAL do backend (não mais valores
fixos/inventados) → `onLogin(user, data.token)` com o token de verdade.
Erro do backend (e-mail não cadastrado, não verificado, tenant bloqueado,
serviço indisponível) aparece na mesma área de erro do formulário de senha.

**`server/services/firebaseAdmin.ts` requer o pacote `firebase-admin`**
(adicionado ao `package.json`) — usa a API modular (`firebase-admin/app`,
`firebase-admin/auth`), não o namespace `admin.*` legado (a v14 instalada
não exporta mais esse formato).

Arquivos: `server/services/firebaseAdmin.ts` (novo),
