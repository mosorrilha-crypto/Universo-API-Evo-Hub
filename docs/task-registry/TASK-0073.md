## Objetivo

corrige agente de agendamento oferecendo horario ja passado no mesmo dia

## Atualizações

**Reportado pelo dono do produto** (print do painel de escalonamentos): o agente de agendamento ofereceu "martes 25 a las 08:30 o 16:30" numa resposta gerada às 14:29 do próprio dia 25/08 — 08:30 já tinha passado havia horas.

**Causa raiz:** `computeAvailabilityForDates` (`server/services/googleCalendar.ts`) gera os horários candidatos só a partir do expediente configurado (abre/fecha) e do Google Calendar real (freebusy) — nunca comparava o horário candidato com "agora". Um slot da manhã continuava aparecendo como "disponível" a tarde inteira até virar ocupado de verdade na agenda. Bug de ferramenta determinística, não de raciocínio do modelo — por isso não dava pra corrigir só ajustando o prompt.

**Correção:** adicionado filtro `slotStartMs <= nowMs` dentro do loop de geração de slots — como `slotStartMs` já é timestamp absoluto (via `localNaiveToUtcIso`), a comparação direta com `Date.now()` cobre qualquer data sem precisar tratar "hoje" como caso especial (datas futuras nunca são afetadas).

**Testes:** novo caso em `server/services/__tests__/findWeeklyAvailability.test.ts` — expediente 07:30-20:00, "agora" 14:30 local, confirma que 07:30/14:00 não aparecem e 15:00 (primeiro slot após "agora") aparece.

**Validação:** `npm run lint`, `npx vitest run` (904 testes, todos passando), `npm run build` — todos OK.

**Pendente/risco:** nenhum conhecido. Efeito colateral esperado e desejado: a lista de horários disponíveis fica mais curta conforme o dia avança, o que é o comportamento correto.
