## Objetivo

Corrige insecure temporary file (CodeQL High) em videoTranscode.ts e audioTranscode.ts usando fs.mkdtemp

## Contexto

3º PR da varredura dos 52 alertas de CodeQL Code scanning (ver TASK-0197).
Cobre "Insecure temporary file" (High, `js/insecure-temporary-file`) em
`videoTranscode.ts:39` (`transcodeToWhatsAppVideo`) e `audioTranscode.ts:71`
(`transcodeToWhatsAppVoiceNote`), e "Network data written to file" (Medium)
nas mesmas linhas — mesma causa raiz.

`isAudioEffectivelySilent` (mesmo arquivo `audioTranscode.ts`) já tinha sido
corrigido com este exato padrão numa PR anterior (comentário já presente no
código, "Achado do CodeQL neste PR") — as duas funções de transcodificação
(`transcodeToWhatsAppVideo`/`transcodeToWhatsAppVoiceNote`) tinham ficado de
fora daquela correção.

## Causa raiz

`path.join(os.tmpdir(), \`nome-com-id-aleatorio\`)` seguido de
`fs.writeFile` não é atômico: em tese um processo concorrente no mesmo host
poderia prever/pré-criar esse caminho entre o cálculo do nome e a escrita
(TOCTOU), mesmo com um sufixo aleatório de `crypto.randomBytes`.

## Correção

Mesmo padrão já usado em `isAudioEffectivelySilent`: `fs.mkdtemp(path.join(
os.tmpdir(), '<prefixo>-'))` cria um diretório com sufixo aleatório de forma
atômica (garantida pelo Node, falha se já existir) — sem essa janela de
corrida. `crypto.randomBytes` deixou de ser necessário (import removido dos
dois arquivos), e o cleanup no `finally` virou `fs.rm(tmpParentDir, {
recursive: true, force: true })` em vez de dois `fs.unlink` separados.

- `server/services/videoTranscode.ts`: `transcodeToWhatsAppVideo`.
- `server/services/audioTranscode.ts`: `transcodeToWhatsAppVoiceNote`.
