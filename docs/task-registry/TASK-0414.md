# TASK-0414 — Corrige resposta duplicada quando rajada de mensagens é dividida em dois turnos do agente

- **Status:** concluído

## Objetivo

Pedido direto do dono do produto, a partir de um print real (tenant Dr. Daniel, cliente "Lizandra"): "depois da última alteração do prompt o agente está muito agressivo na agendamento e enviando valores muito cedo sem ser solicitado".

## Investigação

Descartei primeiro a hipótese mais óbvia (minha própria PR anterior, TASK-0408/#779, que abriu uma exceção opt-in pra fechar preço com convite de agenda): confirmei via Supabase que `pricing_policies.businessRules` do tenant do Dr. Daniel está **vazia** — a exceção só ativa quando o tenant pede isso explicitamente, então não é a causa aqui.

Reconstruí a conversa real (`Lizandra Becker Goss`, 5567992658072) direto no Supabase. O "preço cedo demais" é comportamento **configurado** no `brand_voice` do próprio tenant (publicado há 2 dias, não é código novo) — a seção "VALOR DA CONSULTA" já instrui a IA a informar preço e perguntar período proativamente assim que há interesse em agendar. Isso não é bug, é conteúdo que o dono do produto pode ajustar direto no painel se quiser mudar.

O bug real, técnico e concreto: a cliente mandou 3 mensagens em rajada (nome, "quero marcar", sintoma+exame) com um intervalo de 16.5s entre a penúltima e a última — mais que os 10s de silêncio do buffer (`messageBuffer.ts`, `SILENCE_MS`). O buffer fechou as duas primeiras como um turno (respondeu preço + manhã/tarde), e a terceira mensagem, chegando depois, virou um SEGUNDO turno independente que repetiu quase a mesma resposta (preço + manhã/tarde de novo) 24 segundos depois — mesmo com `runExclusive` (perPhoneQueue.ts) serializando os dois turnos e a resposta anterior já estando no histórico que o segundo turno viu. A regra de anti-repetição já existente no prompt cobria só "pergunta de qualificação repetida pelo cliente" — não cobria explicitamente o caso de o PRÓPRIO agente reabrir preço/horário que ele mesmo acabou de responder segundos antes.

## Correção

Nova regra de estilo em `server/services/autoReply.ts` (`STYLE_RULES`, aplica a todos os agentes): antes de responder, o agente confere se a ÚLTIMA linha do histórico foi enviada por ele mesmo ("Atendente:", formato real de `buildHistoryText`) — se essa mensagem já informou preço e/ou já perguntou período/horário, e a nova mensagem do cliente só trouxe informação adicional sem pedir esse dado de novo explicitamente, não repete; reconhece a informação nova e aguarda a resposta pendente. Continua permitido reafirmar se o cliente pedir o mesmo dado de novo explicitamente.

Não mexi no buffer de silêncio (`SILENCE_MS = 10_000`) — aumentar a janela adiaria TODA resposta (mesmo de conversa com uma mensagem só) pra mitigar um caso que ainda assim podia escapar (o gap real foi de 16.5s, maior que qualquer janela razoável); a correção no prompt ataca a causa que realmente gerou o problema visível (a repetição), não a divisão em si, que é esperada quando o cliente pausa por mais tempo entre mensagens.
