# TASK-0009 — investigar erro path-to-regexp no deploy do Render

## Objetivo

Investigar o erro `TypeError: Missing parameter name at index 1: *` observado nos logs do Render e eliminar a incompatibilidade sem alterar as rotas de negócio.

## Diagnóstico

A ocorrência correspondia ao fallback da SPA em `server.ts`, que registrava `app.get('*', ...)`. Essa sintaxe de wildcard literal é incompatível com versões novas de `path-to-regexp` usadas por Express 5, embora o checkout atual ainda use Express 4. A reprodução isolada com a dependência local mostrou que o checkout atual aceita o padrão; a expressão regular foi escolhida para manter compatibilidade com ambos os parsers e proteger o deploy contra resolução futura para Express 5.

Não foram encontradas outras rotas Express com wildcard literal. O erro acontecia no registro da rota durante a inicialização, antes de o servidor ficar disponível; por isso podia aparecer como `unhandledRejection` no processo de boot do Render.

O CodeQL também encontrou um risco high no primeiro PR: o fallback fazia acesso ao sistema de arquivos sem rate limit. Esse alerta foi corrigido adicionando `spaFallbackRateLimiter` somente nessa rota, sem afetar assets estáticos ou rotas da API.

## Correção aplicada

- substituído `app.get('*', ...)` por `app.get(/.*/, ...)`;
- adicionado rate limit de 120 requisições por minuto ao fallback da SPA;
- mantido o fallback apenas para requisições GET;
- nenhum comportamento de autenticação, pagamento, mensageria ou isolamento por tenant foi alterado.

## Validação

A validação local passou com `npm run lint`, `npx vitest run` com 139 arquivos e 760 testes, `npm run build` e `git diff --check`. O PR [#376](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/pull/376) passou no CI, incluindo lint/test/build e as duas análises CodeQL. Após o merge, o Render respondeu HTTP 200 em `/`, `/health` e `/api/health`, servindo o bundle atualizado.

## Encerramento

A correção foi incorporada à `main` pelo commit de merge do PR #376. O relatório final foi publicado na issue #290. Não há pendência de código; se o mesmo erro voltar a aparecer, deve-se verificar se o Render está executando o commit mais recente e consultar os logs do novo deploy.
