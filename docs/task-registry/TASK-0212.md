# TASK-0212 — Desktop: remove barras redundantes (Modo Visual, cabeçalho Atendimento), move Abrir ficha pra conversa, dedup toolbar x bottom-nav e elimina rolagem externa da página

- **Iniciado em:** 2026-09-02T14:35:12.675Z
- **Agente/plataforma:** Claude
- **Issue central:** [#290](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/290)
- **Status:** concluído

## Objetivo

Desktop: remove barras redundantes (Modo Visual, cabeçalho Atendimento), move Abrir ficha pra conversa, dedup toolbar x bottom-nav e elimina rolagem externa da página

## Atualizações

Pedido direto do dono do produto, com dois prints comparando o painel
Universo com o WhatsApp Web em telas de desktop/tablet — o segundo chegou
como interrupção no meio da execução do primeiro, ampliando o escopo. Um
brainstorm sobre transformar tudo numa barra lateral vertical unificada
(mobile+tablet+desktop, com colapso estilo Claude Code) ficou decidido
como tarefa futura — nesta rodada mantive o mobile exatamente como está.

1. **Duas barras redundantes removidas.** A fileira "Modo Visual" (4 ícones
   de tema, sempre visível no desktop) duplicava o botão único de tema
   (ciclo dark→light→blue→clean) que já existe ao lado do seletor de
   empresa/perfil — removida (`Header.tsx`). O cabeçalho "Atendimento" +
   seletor de empresa do `AtendimentoWorkspaceFrame` (já escondido no
   mobile desde 29/08 pelo mesmo motivo) também saiu do desktop — a busca
   confirmou que seu seletor de empresa é uma DUPLICATA exata do que já
   existe no menu de perfil do SaaS Admin em `Header.tsx` (mesmos
   `tenants`/`activeTenant`/`onSelectTenant`). O componente virou só um
   wrapper de layout (as classes CSS `.atendimento-workspace`/`__content`
   continuam existindo — a cadeia de flex da TASK-0159/0162 depende delas).
2. **"Abrir ficha" mudou de lugar.** Só faz sentido com uma conversa aberta,
   mas vivia numa barra de ferramentas genérica sempre visível. Migrou pro
   cabeçalho da conversa aberta (`hidden lg:flex`), junto dos outros ícones
   que já são exclusivos dela — mesma posição do equivalente mobile
   (`IdCard`), agora os dois usam o mesmo padrão em vez de dois mecanismos
   diferentes.
3. **Duplicação real encontrada num 2º print** (interrupção durante a
   execução): em largura de tablet (~640–1023px), a barra de ferramentas
   (Pendências/Agenda/Ferramentas, `hidden sm:flex`) e a
   `.atendimento-bottom-nav` (Conversas/Pendências/Agenda/Ferramentas,
   `lg:hidden`) ficavam visíveis ao MESMO TEMPO — mesmos handlers duplicados
   dos dois lados. Corrigido trocando o gate da toolbar de `sm:` pra `lg:`
   nos 4 pontos (caixa + 3 botões + painel expandido) — agora cada faixa de
   largura tem exatamente uma barra dona, nunca as duas juntas. Também
   corrigi, na mesma varredura, uma condição pré-existente
   (`isToolbarSettingsOpen ? '' : hidden ...`) que forçava a caixa a ficar
   visível VAZIA abaixo do breakpoint sempre que o painel "Ferramentas" era
   aberto (bug real desde antes desta tarefa, só que restrito a `<640px`; o
   gate mais largo `lg` teria espalhado o mesmo bug pra 640–1023px se não
   fosse simplificado) — a gaveta (`lg:hidden`, com seu próprio
   cabeçalho+X) já cobre 100% desse caso abaixo de `lg`.
4. **Comentário incorreto corrigido.** Um comentário antigo dizia que
   "Header.tsx já tem a aba Escalonamentos com o mesmo contador" — checado
   agora (`grep escalations Header.tsx`), isso nunca foi verdade. O botão
   "Pendências" (toolbar + bottom-nav) é a ÚNICA rota da UI pra
   `activeTab === 'escalations'` — `CrmWorkspace.tsx` recebe um prop
   `onGoToEscalations` mas nunca chama. Corrigido o comentário.
5. **Rolagem externa da página eliminada.** `.atendimento-chat-shell` usava
   `lg:h-[calc(100dvh-154px)]` — constante fixa chutada num commit de
   23/08 (`de470b5`), que nunca soube que a shell é irmã de outro conteúdo
   (a caixa de ferramentas acima dela) nem que `.app-main` mantém padding
   vertical em `lg` (`lg:p-8`, só é zerado abaixo de 1024px — de propósito,
   pra dar respiro ao redor do card arredondado da conversa no desktop).
   Somando as partes fixas acima da shell com a própria altura fixa dela, o
   total passava de `100dvh`, gerando rolagem no documento inteiro (visível
   no 1º print). Corrigido reaplicando a MESMA técnica já validada no
   mobile (TASK-0159/0162: `var(--atendimento-header-h)` medida por
   `ResizeObserver` sobre o `<Header/>` real): `App.tsx` não escapa mais
   pra `lg:block lg:h-auto` — a aba fica com altura limitada
   (`h-[calc(100dvh-var(--atendimento-header-h,0px))]`) em qualquer
   largura, com um `lg:h-[...]` extra subtraindo também os 4rem do padding
   de `.app-main` que continuam existindo só nesse breakpoint.
   `.atendimento-chat-shell` trocou a altura fixa por `lg:flex-1
   lg:min-h-0`, dividindo o espaço já correto via flexbox com a caixa de
   ferramentas, sem depender de mais nenhum número mágico.

**Fora de escopo desta rodada (decisão explícita do dono do produto):**
barra lateral vertical unificada substituindo toolbar + bottom-nav em
TODAS as larguras (incluindo mobile) — fica pra uma atualização futura.
Mobile (`<640px`, barra inferior horizontal) não foi tocado nesta tarefa.
Limpeza do CSS morto de `.atendimento-workspace__header` (a classe não é
mais renderizada, mas segue referenciada em variantes de tema no
`index.css`) também ficou de fora — não bloqueia nada funcionalmente.

Arquivos alterados: `src/components/Header.tsx`,
`src/components/AtendimentoWorkspaceFrame.tsx`, `src/App.tsx`,
`src/components/WhatsAppLeadsSim.tsx`,
`src/components/__tests__/AtendimentoWorkspaceFrame.test.tsx` (reescrito —
o antigo testava o seletor de empresa que foi removido; o novo só confirma
que o componente renderiza os filhos dentro do wrapper de layout, sem
nenhum cabeçalho próprio).

## Encerramento

**Status: concluído.** Esta foi a maior mudança estrutural feita nesta tela
até agora — mexe em breakpoints, altura (`dvh`) e a árvore flex/grid que já
teve 7+ rodadas de regressão em tarefas anteriores (TASK-0150 a TASK-0159).
Sem self-merge.

**Validação:** `npm run lint`, `npx vitest run` (242/242 arquivos,
1303/1303 testes) e `npm run build`, todos limpos.

**Pendente ou risco:** sem dispositivo/browser real disponível nesta sessão
pra confirmar visualmente que a rolagem externa sumiu de verdade e que a
altura calculada bate em telas reais (telefone estreito, tablet, desktop) —
recomendo fortemente o dono do produto testar nas 3 larguras antes do
merge, dado o histórico desta tela. Se sobrar/faltar espaço em alguma
largura específica, é rápido de ajustar numa rodada seguinte agora que o
cálculo é medido (não mais chutado) — só a subtração fixa de `4rem` do
padding em `lg` é um valor "conhecido" (não medido), então é o ponto mais
provável de precisar de ajuste fino se o `lg:p-8` do `.app-main` mudar no
futuro.
