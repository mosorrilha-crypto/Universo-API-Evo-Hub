## Objetivo

Menu mobile do Header: gaveta overlay de verdade, botão de tema vira popover com 4 opções, notificações push viram sub-linha discreta

## Atualizações

Print do usuário do menu mobile (hambúrguer, `Header.tsx`) reclamando de um espaço vazio grande, "Modo visual" redundante com o ícone de tema no topo ("está quebrado"), e "Notificações Push" por já existir nas ferramentas da conversa. Investigação com uma correção de rota importante no meio do caminho:

1. **Minha branch estava ~31 commits atrasada da `main`.** Outra sessão paralela mesclou várias tasks (0274-0288) nas horas anteriores, incluindo a TASK-0284 que moveu justamente "Notificações Push" pra dentro do `Header.tsx` — antes vivia só no menu ⋮ da conversa (`WhatsAppLeadsSim.tsx`), removido de lá por pedido explícito anterior do próprio usuário. Confirmado direto no Render (`list_deploys`, deploy `df6d3b84` live) e comparando `origin/main` via `git show`. Reportado ao usuário: remover "Notificações Push" do Header como pedido inicialmente deixaria o app sem NENHUM jeito de ativar/desativar push. Confirmado: mantém, só menos destacado.
2. **Botão de tema genuinamente quebrado**: `toggleTheme` ciclava nos 4 temas (dark→light→blue→clean→dark) mas o ícone/tooltip só tinha 2 estados (`theme === 'dark' ? Sun : Moon`) — pra light/blue/clean (3 dos 4) mostrava o mesmo ícone de lua e a mesma dica "Modo escuro", sem indicar o tema atual nem o que o clique faria.
3. **"Espaço vazio" — causa raiz só ficou clara depois de um segundo print do usuário**: não era um gap de CSS entre elementos (não existe nenhum, confirmado até depois de sincronizar com a `main`). O menu mobile é conteúdo INLINE (`relative`) que empurra a lista de conversas pra baixo da tela em vez de flutuar por cima dela como um overlay de verdade — pedido explícito do usuário: "abre o menu como uma gaveta, igual o menu do Claude, sem esconder os itens de baixo".

**Mudanças**, todas em `src/components/Header.tsx`:
- Menu mobile vira overlay de verdade: wrapper passa de `relative` (empurra conteúdo) pra `absolute inset-x-0 top-full` (ancorado no fim do `<header>`, que é `position: sticky` — estabelece bloco de contenção pra posicionamento absoluto igual `relative` faria, sem precisar calcular altura do cabeçalho em pixel), com `max-h-[85vh] overflow-y-auto` e fundo próprio (`bg-slate-900`, antes transparente). O backdrop (`fixed inset-0`) ganha `bg-slate-950/60` (antes 100% transparente, só existia pra capturar o toque de "fechar fora") — escurece a lista de conversas atrás sem escondê-la de verdade.
- Botão de tema vira popover: `ToolsMenuKind` generalizado de `'configuration'` pra `'configuration' | 'theme'`, reaproveitando toda a infraestrutura já existente de menu suspenso (`openToolsMenu`/`toggleToolsMenu`, o `useEffect` de fechar ao clicar fora via `data-tools-menu`, `desktopMenuPosition`). Novo `renderThemeMenu(placement)`: o ícone-gatilho agora reflete o tema ATUAL corretamente (um de 4, nunca mais Sun/Moon binário), abre painel com os 4 nomeados + checkmark no ativo. `toggleTheme` removida.
- Fileira "MODO VISUAL" removida por completo — função absorvida pelo popover acima.
- "Notificações Push" deixa de ter caixa própria — vira sub-linha (`border-t`, mesmo padrão já usado pra separar a lista de tenants) dentro do card "Empresa ativa". Mesma lógica de sempre (`togglePush`/`pushEnabled`/`pushBusy`, TASK-0284), só menos destacada.
