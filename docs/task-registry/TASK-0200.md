## Objetivo

Corrige file data in outbound network request (CodeQL Medium) em mediaImageStore.ts e knowledgeBaseVideoStore.ts

## Contexto

4º PR da varredura dos 52 alertas de CodeQL Code scanning (ver TASK-0197).
Cobre "File data in outbound network request" (Medium,
`js/file-data-in-outbound-network-request`): `mediaImageStore.ts:39` e
`knowledgeBaseVideoStore.ts:64`. O 3º alerta desta categoria
(`evolutionSend.ts:82`, dentro de `sendEvolutionVoiceMessage`) já deve estar
coberto pelo fix da TASK-0197 (PR #578) — essa função chama
`requireCredentials`, que já valida `apiUrl` antes do fetch.

## Causa raiz

Dado binário (`buffer`, recebido de um upload de mídia do cliente) é
mandado como corpo de uma requisição de rede (`fetch(...).body = buffer`)
sem validar a URL de destino antes. `supabaseUrl` nesses dois arquivos vem
sempre de configuração do servidor (env `SUPABASE_URL`), nunca de input
direto de request — mesmo raciocínio da TASK-0197 (SSRF).

## Correção

Mesma checagem estrutural (URL bem-formada, protocolo `http`/`https`) já
usada em `evolutionSend.ts`/`admin.ts` — duplicada localmente em cada
arquivo (`assertValidHttpUrl`) em vez de extraída pra um módulo
compartilhado, pra manter os PRs desta varredura independentes entre si
(evita acoplar este PR ao merge de TASK-0197/#578, que altera arquivos
diferentes mas ainda não foi mesclado).

- `server/services/mediaImageStore.ts`: `saveMediaImage` e `getMediaImage`.
- `server/services/knowledgeBaseVideoStore.ts`: `uploadKnowledgeBaseVideo`,
  `getKnowledgeBaseVideo` e `deleteKnowledgeBaseVideo`.

## Validação

- `npm run lint` (tsc --noEmit) — limpo.
- `npx vitest run` — 237 arquivos / 1275 testes, todos passando (inclui
  testes que exercitam estas duas stores com `supabaseUrl` mockado —
  confirma que URLs http(s) válidas continuam funcionando normalmente).
- `npm run build` — limpo.
