## Objetivo

Pedido direto do dono do produto: "coloca um botão de baixar o catálogo como PDF lá nas config do catálogo". Adicionar, na tela "Catálogo" do painel (`PublicCatalogSettings.tsx`), um botão que gera e baixa um PDF com os produtos ativos do tenant + dados de contato — útil pra enviar por WhatsApp/e-mail sem depender do catálogo público (`/catalogo/:slug`) estar habilitado.

## Decisão de implementação

Avaliei duas formas de gerar o PDF: (1) chamar o endpoint público `/api/public/catalog/:slug` (já existente, usado pela página `/catalogo/:slug`) e (2) gerar localmente no navegador a partir dos dados já carregados no painel (`knowledgeBase.products`, autenticado). Escolhi a opção 2 porque a opção 1 depende de `tenants.public_catalog_enabled = true` (`getPublicCatalogBySlug` retorna `null` se estiver desativado) — o botão de PDF precisa funcionar mesmo com o catálogo público desligado, já que são funcionalidades independentes (o admin pode querer só o PDF, sem publicar o link).

- `src/lib/catalogPdf.ts` (novo): função `downloadCatalogPdf(tenantName, contact, products)` monta um PDF simples (A4, `jsPDF`) com cabeçalho (nome do negócio + contato: WhatsApp/Instagram/endereço/horário) e a lista de produtos ativos (nome, categoria, preço, duração, descrição, variantes), com paginação automática. Nome do arquivo é o nome do negócio "slugificado".
- **Import sob demanda**: `jsPDF` (~130KB gzip) só é importado dentro do handler de clique (`await import('jspdf')`), não no topo do arquivo — confirmado via `npm run build` que o bundle principal do painel não cresceu (permanece ~386KB gzip); `jspdf.es.min-*.js` virou um chunk separado, carregado só quando o botão é clicado.
- `src/components/PublicCatalogSettings.tsx`: botão "Baixar PDF" no cabeçalho do card (ao lado de "Ver catálogo"), com ícone de spinner enquanto gera. Desabilitado quando não há produto nenhum cadastrado. Reaproveita os mesmos campos de contato já preenchidos no formulário (WhatsApp, Instagram, endereço, horário) — nenhuma chamada de API nova.
- `src/App.tsx`: `PublicCatalogSettings` passou a receber `tenantName={activeTenant.name}` e `products={knowledgeBase.products || []}` (ambos já existiam no estado do componente pai, só precisavam ser repassados).
