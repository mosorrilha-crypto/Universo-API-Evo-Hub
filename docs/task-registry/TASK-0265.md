## Atualizações

Achado registrado numa sessão anterior (comentário na #504, 04/09/2026, durante o planejamento da Partner API): `CLAUDE.md` afirmava que `OperatorCRM.tsx` era "pure `localStorage`-backed mock with zero API calls", mas isso ficou desatualizado desde que `server/routes/crm.ts`/`server/services/crmStore.ts` (tabela `crm_lead_state`) entraram em produção.

Auditado antes de corrigir (não confiei de graça no achado anterior, conforme convenção do próprio `CLAUDE.md`):
- `grep apiFetch` dentro de `OperatorCRM.tsx` não encontra nada — o componente em si não chama a API diretamente.
- Isso não significa mock: como a maioria dos componentes filhos de `App.tsx`, ele recebe `leads`/`onUpdateLead`/`onDeleteLead` como props; quem chama `GET/PATCH/DELETE /api/crm/leads` é o próprio `App.tsx` (linhas 788/920/950).
- O próprio arquivo já documenta isso num comentário (linha 31-32): o banner "não conectado ao backend real" foi removido por estar desatualizado.

Corrigido o parágrafo em `CLAUDE.md` (seção "Frontend architecture") pra refletir isso, incluindo a ressalva de que "sem `apiFetch` no arquivo" não é sinal confiável de mock nesta base de código — o padrão real é verificar o que `App.tsx` passa como prop.

Mudança é só de documentação, sem código de produto alterado.
