## Objetivo

Corrige chips de filtro Tudo/Nao lidos com verde de marca do WhatsApp hardcoded

## Atualizações

Achado real reportado pelo dono do produto com print do celular: no tema Limpo, o chip de filtro
"Tudo (N)" (visível logo acima da lista de conversas) continuava verde mesmo depois da
normalização completa dos 4 temas (TASK-0061/0062/0067). Causa raiz: `WhatsAppLeadsSim.tsx` usava
`bg-[#00a884]` — o verde de marca do próprio WhatsApp, hardcoded via Tailwind arbitrary value —
nos chips "Tudo"/"Não lidos" quando selecionados, não `bg-emerald-500`/`600`. Como é uma classe
totalmente diferente (valor arbitrário, não a paleta `emerald-*`), nunca foi tocada pelas regras
de tema que mapeiam `emerald` para `var(--action)`.

- `src/components/WhatsAppLeadsSim.tsx`: trocado `bg-[#00a884]` por `bg-emerald-500` nos dois
  chips selecionados ("Tudo"/"Não lidos") — já 100% coberto pelas regras de tema existentes.
- **Escopo deliberadamente restrito**: NÃO alterados os outros 8 usos de `bg-[#00a884]` no mesmo
  arquivo (bolha de mensagem do agente, player de áudio, borda de preview de resposta, anel de
  foco do campo de mensagem, botão de enviar). Esses simulam deliberadamente a aparência real do
  WhatsApp dentro da conversa — mudá-los sem pedido explícito arriscaria quebrar essa fidelidade
  visual intencional, que é um domínio de decisão diferente ("nossa própria interface segue o
  tema" vs. "a conversa simulada parece um WhatsApp de verdade"). Fica registrado como decisão em
  aberto caso o dono do produto queira esses também seguindo o tema no futuro.
- Validado com `npm run lint` (limpo), `npx vitest run` (903 testes, 174 arquivos, todos verdes —
  nenhum teste cobria essa classe especificamente), `npm run build` (limpo), e visualmente com
  Playwright numa página de preview isolada (mesma técnica das tarefas anteriores) — confirmado
  que o chip "Tudo" fica azul no tema Limpo.
