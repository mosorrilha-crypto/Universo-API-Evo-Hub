## Objetivo

Hospedar mapa do projeto como site estatico no Render

## Atualizações

Pedido do dono do produto: compartilhar o mapa visual (`docs/mapa-do-projeto/index.html`,
já publicado como Claude Artifact desde a TASK-0207) também via um link próprio no Render,
pra outros analistas acessarem sem depender de conta/link do Claude.

Achado técnico antes de hospedar: o arquivo fonte do Artifact **não** contém o script do
Mermaid — os diagramas só renderizam porque o próprio Artifact injeta o runtime
(`mermaid-11.16.1.min.js` via `/_runtime/`) na hora de publicar. Confirmado lendo a versão
live do Artifact (`action: read`) e comparando com o arquivo do repositório: fora do
ambiente do Artifact, os `<pre class="mermaid">` apareceriam como texto cru, não como
diagrama. Por isso não hospedei o arquivo original direto — criei uma cópia derivada.

Criado `docs/mapa-do-projeto/site/index.html`: documento HTML completo e independente
(doctype/head/body reais, diferente do fragmento que o Artifact espera), com o mesmo
conteúdo do mapa + Mermaid carregado via CDN (cdnjs) e inicializado no carregamento
(tema claro/escuro pelo `prefers-color-scheme`). Gerado programaticamente a partir do
arquivo original (script Python descartável, não commitado) pra evitar erro de
transcrição manual num arquivo de ~800 linhas.

Serviço Render criado via MCP (`create_static_site`):
- Nome: `universo-mapa-arquitetura`
- Tipo: Static Site (sem custo de compute, servido por CDN — não é mais um serviço
  Starter cobrado, diferente dos 3 já existentes no workspace)
- Repo: `mosorrilha-crypto/Universo-API-Evo-Hub`, branch
  `claude/gestor-refinamento-atendimento-mwu1a7` (a mesma branch de trabalho desta
  sessão — auto-deploy a cada commit nela; ainda não passou por PR/merge em `main`)
- Publish path: `docs/mapa-do-projeto/site`
- URL pública: **https://universo-mapa-arquitetura.onrender.com**

Deploy `dep-dac7r0bq87js73aseb70` confirmado com `status: live` (~20s de build, só
`echo` porque não há passo de build real).

## Encerramento

`npm run lint`, `npx vitest run` (240 arquivos / 1296 testes) e `npm run build` rodados
e passando limpo antes do commit — mudança é só de um arquivo estático novo, nenhum
código de aplicação foi tocado. Deploy no Render confirmado `live` via
`mcp__Render__get_deploy`.

**Correção pós-deploy (mesma tarefa):** o dono do produto reportou com print que os
diagramas apareciam como texto cru do Mermaid, não como imagem. Causa raiz: a versão
do Mermaid apontada no cdnjs (`11.4.1`) foi um número inventado sem checar se existia
de verdade — o script falhava ao carregar (404 ou similar), `mermaid` ficava
`undefined`, e `mermaid.initialize()` nunca rodava. Corrigido no commit `d3e1720`:
troca pra jsDelivr (serve direto do pacote npm publicado, sem depender de mirror do
cdnjs) na versão `11.16.1` — confirmada real por ser a mesma que o próprio Claude
Artifact usa no seu runtime interno (`mermaid-11.16.1.min.js`, visto ao ler a versão
live do Artifact). Também mudei `securityLevel` de `strict` pra `loose` (os diagramas
usam `<br/>`/`<i>` nos rótulos dos nós, que `strict` sanitiza) e adicionei um aviso
visível na página caso o CDN falhe de novo, em vez de falha silenciosa. Novo deploy
(`dep-dac8932d0e5s73ckb4qg`) confirmado `live` via `mcp__Render__list_deploys`.

Pendente ou risco: (1) o site aponta pra uma branch de trabalho, não `main` — se essa
branch for deletada após merge, o Render precisa ser reapontado pra `main` (ou repetir
o deploy) nesse momento, senão o site quebra; (2) a cópia em `docs/mapa-do-projeto/site/`
é derivada e pode divergir do arquivo fonte (`docs/mapa-do-projeto/index.html`) se
alguém editar só um dos dois — futuras edições do mapa devem atualizar ambos (ou
regenerar a cópia) na mesma tarefa, mesma disciplina já aplicada ao Artifact; (3) ainda
não tenho confirmação visual de quem tem acesso a navegador de que os diagramas
renderizam certo depois da correção — o dono do produto validou o bug original por
print, mas ainda não confirmou a correção.
