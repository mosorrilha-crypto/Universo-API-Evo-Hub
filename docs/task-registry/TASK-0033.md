## Objetivo

Pedido direto do dono do produto: depois de confirmar que o catálogo público (`/catalogo/monique-teste`) já está renderizando certo, pediu autonomia sobre a mensagem pré-preenchida que abre no WhatsApp ao clicar nos botões da página — até aqui era texto fixo em `PublicCatalogPage.tsx`, exigia deploy de código pra mudar.

## Implementação

- **Migration `0046_public_catalog_whatsapp_message.sql`**: colunas `public_whatsapp_message_general` e `public_whatsapp_message_product` em `tenants` (nullable — `NULL` mantém o texto padrão atual, retrocompatível). Aplicada em produção via Supabase MCP (`apply_migration`) e confirmada via `list_migrations`.
- **`server/services/publicCatalogStore.ts`**: `PublicCatalog.contact` ganha `whatsappMessageGeneral`/`whatsappMessageProduct`; `getPublicCatalogBySlug` lê as novas colunas.
- **`server/routes/conversations.ts`**: `GET/PUT /api/public-catalog-settings` passam a ler/gravar os dois campos novos, mesmo padrão de validação e escopo por `tenantOf(req)` das rotas já existentes.
- **`src/components/PublicCatalogSettings.tsx`** (aba Catálogo do painel): dois `textarea` novos — mensagem do botão geral e template da mensagem por produto, com `{produto}` como placeholder substituído pelo nome do produto.
- **`src/components/PublicCatalogPage.tsx`**: `whatsappUrl` agora aceita o template vindo do catálogo público; troca `{produto}` pelo nome real do produto quando presente; cai no texto padrão de sempre (`"Hola, quiero información sobre..."`) quando o campo está vazio.
