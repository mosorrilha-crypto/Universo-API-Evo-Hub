## Objetivo

Adiciona mapa visual do projeto (HTML) gerado como artifact para consulta rápida de onboarding

## Contexto

O usuário pediu um "mapa explodido" visual do projeto (arquitetura, fluxos,
o que já está ativo) por ser iniciante e achar o repositório grande demais
pra se orientar só pelos docs em texto. Foi gerado como Artifact (HTML
autocontido com diagramas Mermaid do fluxo de mensagem e do fluxo do
painel, tabela de estado real por área e lacunas conhecidas, todos com
conteúdo extraído de `docs/GUIA-DO-PROJETO.md`) e compartilhado com o
usuário. Ele pediu em seguida para adicionar esse mesmo arquivo ao
repositório.

## Mudança

- `docs/mapa-do-projeto/index.html`: cópia do HTML publicado como Artifact
  — página autocontida (CSS + Mermaid via CDN), sem dependência do backend
  da aplicação. Não é servido por nenhuma rota; é pra abrir localmente no
  navegador.
- `docs/GUIA-DO-PROJETO.md`: nova seção "Mapa visual (onboarding)" logo no
  topo, apontando pro arquivo e deixando explícito que é um snapshot
  gerado a partir do próprio guia (2026-09-01/02) — se o guia mudar depois,
  o mapa pode ficar desatualizado até alguém regenerá-lo. O guia continua
  sendo a fonte de verdade, o mapa é só uma visualização derivada.

## Validação

- `npm run lint` (tsc --noEmit).
- `npx vitest run`.
- `npm run build`.
- Revisão manual: HTML é conteúdo estático, sem alteração de código de
  aplicação/rota/lógica de negócio.

## Pendente/risco

- O mapa é um snapshot, não gerado automaticamente a partir do guia —
  qualquer mudança futura no `GUIA-DO-PROJETO.md` (nova fase concluída,
  gap fechado) não atualiza o HTML sozinho; alguém precisa regenerá-lo
  manualmente quando o desalinhamento incomodar.

## Atualização (mesma tarefa, 2ª rodada)

O usuário revisou a primeira versão e apontou que faltavam muitos
processos/funcionalidades reais do produto, e pediu duas coisas: (1) cobrir
mais do ecossistema, não só o fluxo de mensagem; (2) representar as
pendências **dentro do próprio fluxo visual** (nó tracejado), não como uma
lista solta separada — e removeu a seção de Obsidian/skills numa rodada
anterior por poder confundir outros analistas.

Levantamento adicional em `server/routes/`, `server/services/` e
`src/components/` (muito além do que o guia resume em uma tabela) e
cruzamento com o changelog do `GUIA-DO-PROJETO.md` pra confirmar o que é
real vs. planejado. `docs/mapa-do-projeto/index.html` ganhou 4 diagramas
novos (Mermaid, mesmo padrão visual dos 2 já existentes):

- **Agenda & Financeiro**: pré-reserva → lock → hold expira ou confirma →
  lembrete (nó pendente: template do Meta não aprovado) → comprovante →
  confirmação humana → transação financeira → despesa recorrente (nó
  pendente: sem gateway de pagamento real).
- **CRM, Escalonamento & Qualidade**: funil de vendas → lead ganho vira
  cobrança automática; resposta arriscada → revisor pré-envio → rascunho
  bloqueado → "Aprovar e enviar" → vira exemplo aprovado que realimenta o
  agente; Central de Qualidade como evidência humana (nó pendente/parcial:
  não altera o agente sozinha, por decisão de escopo).
- **Marketing, Catálogo público & Oferta comercial**: Meta Ads + CAPI +
  Central de Tráfego; catálogo público por tenant; página `/oferta` de
  planos comerciais (nó pendente: ativação de piloto novo é manual);
  disparo em massa (nó pendente/parcial: sem botão liga/desliga manual).
- **Administração, Entitlements & Alertas de sistema**: criação de tenant →
  checklist de ativação → entitlements → RBAC; os 4 jobs de alerta
  (agente pausado, WhatsApp caiu, erro genérico, pagamento pendente) → nó
  pendente: sem error tracking geral fora desses 4 casos.

A tabela "Estado real por área" também foi ampliada (CRM, escalonamento,
qualidade, Meta Ads, catálogo público, oferta comercial, entitlements,
alertas de sistema) e **um erro de fato foi corrigido nela**: a linha do
CRM dizia "ainda é localStorage puro" (repetindo uma frase desatualizada
do `CLAUDE.md`) — mas o próprio `GUIA-DO-PROJETO.md` (que é a fonte que
vence em caso de conflito) já registra que `OperatorCRM.tsx` está ligado à
API real desde antes, com ponte pro Financeiro em leads ganhos. Corrigido
o chip de "lacuna" pra "ativo" nessa linha.

A seção "Lacunas conhecidas" (lista solta) foi removida — as pendências
agora vivem só dentro dos fluxos, como pedido.
