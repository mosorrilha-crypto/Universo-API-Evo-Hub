## Objetivo

Qualidade da IA: cores respeitam os 4 temas e pagina fica borda a borda

## Atualizações

Pedido direto do dono do produto, com print da aba "Qualidade da IA"
sempre aparecendo clara/branca, independente do tema selecionado:
"ajusta as cores desta página nos 4 temas e faz o mesmo ajuste da página
de atendimento nas demais pra ficar de margem a margem" (escopo
confirmado via pergunta direta: só esta página nesta rodada — as outras
~9 telas ficam pra próximas rodadas, mesmo padrão cauteloso já usado
nesta sessão).

**Achado real (causa raiz das cores erradas):** não era falta de suporte
a tema — era um bloco CSS `.quality-workspace--clear` (index.css) que
JÁ EXISTIA de propósito, com um comentário explícito: "Esta área é
deliberadamente clara mesmo se o operador estiver usando outro tema
global". Essa classe remapeava `bg-slate-900`/`text-white`/`text-slate-400`/
etc. pra uma paleta clara FIXA via `!important`, sem nenhum gate de
`html[data-theme='...']` — ou seja, sobrescrevia incondicionalmente o
sistema de temas geral que JÁ existe no projeto (confirmado: o mesmo
conjunto de classes Tailwind cruas já tem remapeamento correto pros 4
temas em `index.css`, usado pelo resto do painel). Essa é uma decisão de
design anterior sendo revertida agora por pedido explícito do dono do
produto — registrando a discrepância em vez de simplesmente sobrescrever
por baixo, como pede o CLAUDE.md.

1. **Cores nos 4 temas**: removida a classe `quality-workspace--clear` de
   `QualityAuditCenter.tsx` e `AgentContextUsageDocumentation.tsx` (a
   subtela "Como usar", mesmo problema). Removido o bloco CSS inteiro em
   `index.css` (~230 linhas: variáveis `--quality-*` fixas + remapeamento
   `!important` de dezenas de classes Tailwind) e as duas referências
   residuais (`.quality-workspace--clear { background: var(--surface-
   gradient-soft) ... }` e a entrada na media query de `box-shadow`). A
   página agora herda o sistema de temas já validado pro resto do app —
   sem paleta própria fixa.
2. **Borda a borda**: mesmo mecanismo já usado no Atendimento
   (TASK-0221/0222/0225/0226) — nova classe `app-main--quality`
   (`App.tsx`, aplicada quando `activeTab === 'quality'`) reaproveita a
   MESMA regra CSS de `.app-main--atendimento` (`max-width: none; padding:
   0;`, index.css) e o cabeçalho/menu (`Header.tsx`, `headerInnerClassName`)
   também esticam junto nessa aba. Seguro porque `OperationsModuleFrame`
   (que envolve o conteúdo da aba) já tem seu próprio card com padding/
   borda/cantos arredondados — não depende do padding do `.app-main` pra
   ter respiro.

Teste ajustado: `AgentContextUsageDocumentation.test.tsx` esperava a
classe `quality-workspace--clear` em 2 asserções — trocado pra
`quality-workspace` (a classe base, que continua existindo).

**Sincronização com `main`:** ao registrar esta tarefa, `main` já tinha
avançado com trabalho concorrente (correção de rodadas de avaliação
presas, TASK-0228/0229). `git merge origin/main` resolveu sem conflitos.

Arquivos alterados: `src/App.tsx`, `src/components/Header.tsx`,
`src/components/QualityAuditCenter.tsx`,
`src/components/AgentContextUsageDocumentation.tsx`,
`src/components/__tests__/AgentContextUsageDocumentation.test.tsx`,
`src/index.css`.
