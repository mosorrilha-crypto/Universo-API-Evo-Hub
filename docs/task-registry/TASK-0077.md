## Objetivo

Fix: header colado na barra de status do iPhone (safe-area-inset-top)

## Atualizações

Pedido direto de chat: usuário mandou print do celular (iPhone, app em PWA —
sem chrome de navegador, só a barra de status do iOS) mostrando o header
("Universo" + botão de menu) colado atrás do relógio/bateria/sinal, texto
sobrepondo texto, menu impossível de tocar.

Localizei o header único e sticky em `Header.tsx:197` (`sticky top-0`) —
único caso desse padrão no app (auditado, `grep` por `sticky top-0|fixed
top-0` em todos os componentes). `index.html` já tem `viewport-fit=cover`
configurado, mas nenhum elemento usava `env(safe-area-inset-top)` (só existe
um uso de `safe-area-inset-bottom`, num bottom sheet — TASK diferente).

Fix: `style={{ paddingTop: 'env(safe-area-inset-top)' }}` no `<header>`.
0px fora de PWA em tela cheia/notch (não muda nada em navegador normal
nem em Android), reserva o espaço exato da barra de status quando existe —
é o padrão universal recomendado pra esse problema, suportado por todo
browser moderno (incluindo Safari iOS, que é o caso do bug).

Tentei escrever um teste automatizado (`Header.empresasMenu.test.tsx`)
verificando o estilo aplicado, mas o parser de CSS do jsdom (`cssstyle`)
rejeita `env(...)` como valor inválido e nem chega a gravar no atributo
`style` do elemento — testado, confirmado, removido o teste (deixaria
comentário explicando o porquê em vez de forçar uma asserção que dá falso
negativo sempre). Não consigo validar visualmente num iPhone real nesta
sessão — fix baseado em causa raiz clara (ausência do `env()` que já é
usado com sucesso em outro lugar do mesmo app) e padrão amplamente
documentado, mas pendente de confirmação visual pelo usuário.
