## Objetivo

Corrige legenda de imagem recebida via WhatsApp descartada (não persistida na conversa)

## Atualizações

Bug real reportado por print (28/08/2026): uma imagem chegou pro painel da
Monique sem a legenda que a cliente digitou junto (evento/corrida com
data, local, valor). A UI (`WhatsAppLeadsSim.tsx`) já tem uma faixa
dedicada pra mostrar legenda abaixo da imagem — o problema era 100%
backend: nenhum dos dois parsers (`webhookParsers.ts`) extraía o campo de
legenda do payload (`image.caption` na Meta Cloud API, `imageMessage.caption`
no Baileys/Evolution API), e `webhooks.ts` gravava sempre o texto fixo
"📷 Imagem recebida", descartando qualquer legenda real.

Corrigido: novo campo `caption?: string` em `ParsedIncomingMessage`,
preenchido pelos dois parsers quando o campo existe e não é só espaço em
branco; `webhooks.ts` agora grava `msg.caption || '📷 Imagem recebida'`
como texto da mensagem de imagem.

Entregue: `server/services/webhookParsers.ts`, `server/routes/webhooks.ts`,
`server/services/__tests__/webhookParsersEvolutionImage.test.ts` (+2 testes),
`server/services/__tests__/webhookParsersMetaImageCaption.test.ts` (novo,
3 testes).

## Encerramento

**Status: concluído.** Toca o caminho de mensageria (webhook de entrada) —
aguardando autorização explícita antes de mesclar, mesmo padrão já usado
nesta sessão pra qualquer coisa ligada a mensageria, mesmo sendo uma
mudança aditiva (só preserva dado que antes era descartado, não muda
comportamento de resposta automática nem confirma nada sozinho).
Validação: `npm run lint`, `npx vitest run` (221 arquivos, 1144 testes) e
`npm run build`, todos limpos.

**Pendente ou risco:** nenhum. Comportamento reversível e sem migration —
só passa a preservar um campo que já vinha no payload do provedor.
