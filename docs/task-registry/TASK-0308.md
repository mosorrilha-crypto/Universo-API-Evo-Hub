# TASK-0308 — Unifica leitura da Base de Conhecimento no sistema tipado/publicado (getRuntimeKnowledgeBase), corrige divergência texto vs áudio e ETag stale do painel

- **Issue central:** [#504](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/504)
- **Status:** concluída

## Objetivo

Unifica leitura da Base de Conhecimento no sistema tipado/publicado (getRuntimeKnowledgeBase), corrige divergência texto vs áudio e ETag stale do painel

## Contexto

Há dois sistemas de Base de Conhecimento em paralelo: o novo, tipado e versionado (`knowledge_base_documents`, 8 tipos com draft→publish, editado por `AgentKnowledgeBase.tsx`, lido via `getRuntimeKnowledgeBase()`), e o legado (`knowledge_base`, 1 jsonb por tenant, lido via `getKnowledgeBase()`). Publicar um documento tipado nunca escreve de volta no legado — congelado desde o backfill da migration `0057_knowledge_base_typed_documents.sql`. Isso causou um bug real (botão "Localização" da conversa mandando texto antigo minutos depois de editar/publicar) e um mais sério confirmado nesta tarefa: o agente respondia com uma base diferente pro mesmo tenant dependendo se o cliente escreveu texto (`webhooks.ts` já usava a base tipada) ou mandou áudio (`transcriptionQueue.ts` ainda usava a legada).

O plano original citava uma "TASK-0307" como origem/hotfix manual — não foi localizada em `docs/task-registry/`, PRs ou issues do repositório. O dono do produto confirmou que o achado técnico (dois sistemas de KB, leitura desatualizada, bug texto-vs-áudio) já estava validado de forma independente por 3 agentes de investigação (Explore) e autorizou seguir sem esse registro. `TASK-0105` (issue #96) foi quem originalmente cortou `autoReply.ts`/`webhooks.ts`/`publicCatalogStore.ts`/`admin.ts` pro runtime tipado — já mergeado e ativo, apesar do registro ainda dizer "aguardando revisão humana" (bookkeeping desatualizado).

## Mudança

- **Leitura consolidada em `getRuntimeKnowledgeBase()`** (troca de `getKnowledgeBase()` legado) em: `server/routes/conversations.ts` (linhas de contexto de transcrição/mídia de exemplo/sugestão de resposta de escalonamento, e o call site de maior risco — `resolveProductAmountByName` dentro de `recordFinancialTransactionForVerifiedPayment`, que resolve o VALOR gravado numa transação financeira aprovada), `server/routes/webhooks.ts` (transcrição de áudio enviado pelo operador direto do celular) e `server/services/transcriptionQueue.ts` (correção do bug real: o áudio do CLIENTE agora usa a mesma base que o texto). Não mexido: `POST /api/knowledge-base` (salvamento do blob legado) e as rotas de anexo (`POST`/`DELETE /api/knowledge-base/documents`) — fora do escopo, ver pendências.
- **`GET /api/knowledge-base`** (`conversations.ts`): trocado o select cru na tabela legada por `getRuntimeKnowledgeBase()`; o ETag deixou de vir de `updated_at` (não existe mais uma única linha/timestamp) e passou a ser um hash SHA-256 do conteúdo devolvido — mesma finalidade (evitar reenviar ~12MB quando nada mudou), agnóstica à fonte. Comentário obsoleto que citava `autoReply.ts`/`publicCatalogStore.ts` como leitores diretos do legado foi corrigido/removido.
- **`AgentKnowledgeBase.tsx`**: `handlePublishTypedDrafts`, ao publicar com sucesso, agora dispara `window.dispatchEvent(new CustomEvent('universo:knowledge-base-published', { detail: { tenantId } }))`.
- **`App.tsx`**: o efeito de busca da Base de Conhecimento (dependência `[activeTenant.id]`) ganhou um listener desse evento — refaz a busca quando `detail.tenantId` bate com o tenant ativo, sem precisar recarregar a página. Mesmo formato do listener de `universo:entitlements-changed` já existente (esse padrão nunca teve um dispatcher real até agora — esta é a primeira vez que ele é de fato exercitado ponta a ponta).
- **Testes ajustados**: `knowledgeBaseEtag.test.ts` (3º caso agora muda o `data` de verdade, não só `updated_at`, coerente com ETag por conteúdo); `conversationsSendEvolution.test.ts`, `conversationsSendExamplePhotoPersist.test.ts`, `conversationsKnowledgeBaseVideo.test.ts`, `transcriptionQueueHistoryCutoff.test.ts`, `transcriptionQueueTenantContext.test.ts` — todos mockavam só `getKnowledgeBase`; adicionado mock de `getRuntimeKnowledgeBase` (nos 3 primeiros, delegando pro mock de `getKnowledgeBase()` existente, preservando os `mockResolvedValueOnce` por teste sem duplicar).
