## Objetivo

Fluxo de aprovar-e-enviar rascunho bloqueado em escalonamentos + aba de arquivados + exemplos aprovados alimentando o agente

## Atualizações

Pedido direto de chat (com print da fila de Escalonamentos): duas perguntas
do dono do produto — (1) onde ficam os escalonamentos arquivados, e (2)
quando o revisor pré-envio bloqueia uma resposta duvidosa da IA, por que não
dá pra aprovar aquele rascunho e enviar direto, alimentando o agente pra
situações parecidas.

Investigação confirmou os dois gaps reais no código:
1. `EscalationsPanel.tsx` filtrava `status !== 'archived'` tanto em
   Pendentes quanto Resolvidos — arquivar fazia o caso sumir da tela pra
   sempre (ficava só no banco). `listEscalations` também filtrava
   `deletedAt` sempre, sem opção de incluir.
2. O rascunho bloqueado já ficava salvo (dentro do texto de `reason`, via
   regex) e "Gerar sugestão" já usava esse rascunho como base — mas só dava
   pra Copiar/Salvar edição/Descartar, nunca enviar direto, e nenhuma ação
   realimentava o agente. Central de Qualidade (`QualityAuditCenter.tsx`)
   já existe mas é só "evidência para revisão humana; não é uma regra
   automática" (comentário explícito no código) — não fecha esse ciclo.

Desenho aprovado pelo usuário antes de implementar: aprovar (como está ou
editado) → enviar pelo MESMO caminho real do operador
(`POST /api/conversations/:phone/send`) → só then fecha o escalonamento e
grava um "exemplo aprovado" — nunca a IA decidindo sozinha, nunca reescreve
a Base de Conhecimento. O exemplo aprovado entra no contexto dinâmico
(Camada 4, nunca cacheado) das próximas mensagens do tenant, via
`combinedExtraContext`, mesmo padrão já usado pra `operatorGuidanceContext`.

Entregue:
- `supabase/migrations/0054_escalation_approved_replies.sql` (aplicada em
  produção): `escalations.blocked_draft` (estruturado, não mais só regex
  no `reason`) + tabela `tenant_approved_reply_examples` (RLS JWT).
- `server/services/approvedReplyExampleStore.ts` (novo).
- `server/services/escalationStore.ts`: campo `blockedDraft`, opção
  `blockedDraft` em `logEscalation`, `includeArchived` em `listEscalations`
  (default `false`, preserva todo comportamento existente), nova
  `restoreEscalation`.
- `server/routes/webhooks.ts`: passa `blockedDraft` estruturado ao criar o
  escalonamento do revisor pré-envio.
- `server/routes/conversations.ts`: `GET /api/escalations` aceita
  `?includeArchived=true`; novas `POST /api/escalations/:id/approve-and-resolve`
  (nunca disponível pra `payment_proof`) e `POST /api/escalations/:id/restore`.
- `server/services/autoReply.ts`: injeta até 3 exemplos aprovados recentes
  do tenant no contexto dinâmico do especialista (melhor esforço, nunca
  trava a resposta normal se a busca falhar).
- Frontend (`EscalationsPanel.tsx`, `App.tsx`, `types.ts`): aba
  "Arquivados" nova, botão "Restaurar", rascunho bloqueado mostrado de
  forma estruturada no card, botão "Aprovar e enviar" na caixa de
  sugestão (desabilitado se a janela de 24h já fechou, com aviso
  explicando o motivo).
