## Objetivo

Pedido direto do dono do produto (2 prints de tela do painel real, em dispositivo real): a seção "Configurações de Meta Pixel e CAPI" (`AdAttributionCAPI.tsx`) tinha dois links soltos no cabeçalho do card, sem ligação visual com nenhum campo — "Gerar token no Graph API Explorer" (duplicado, o mesmo link já aparecia corretamente embaixo do campo Access Token) e "Abrir Eventos da Meta (Pixel e testes)" (link genérico, não ligado a nenhum campo específico). Pedido: remover a redundância e colocar cada link junto ao campo a que ele realmente se refere.

## Causa raiz

O PR #393 (mergeado antes desta tarefa) adicionou os 3 links "oficiais" (Graph API Explorer, System Users, Access Token Debugger) tanto no cabeçalho do card de CAPI quanto — corretamente — embaixo do campo Access Token. Isso deixou o link do Graph API Explorer duplicado (aparecia 2x com o mesmo destino) e o link do Gerenciador de Eventos (Events Manager) órfão no cabeçalho, sem indicar pra qual campo ele ajuda.

## Correção

`src/components/AdAttributionCAPI.tsx`, painel "Configurações de Meta Pixel e CAPI":
- Removido o bloco de 2 links do cabeçalho do card (`Gerar token no Graph API Explorer` + `Abrir Eventos da Meta`).
- O link "Gerar este token no Graph API Explorer" já existente embaixo do campo Access Token Graph API foi mantido (era o único não-duplicado).
- O link do Gerenciador de Eventos da Meta (`business.facebook.com/events_manager2`) foi dividido em dois links contextuais, cada um preso ao campo certo:
  - Embaixo de **Meta Pixel ID**: "Ver meu Pixel ID no Gerenciador de Eventos" — é lá que se encontra/copia o ID real do Pixel.
  - Embaixo de **Test Event Code (Meta Test Tool)**: "Gerar código de teste no Gerenciador de Eventos" — é lá (aba Test Events) que se gera o código de teste.

A seção "Conectar a leitura de campanhas" (`TrafficCenter.tsx`, segundo print) foi revisada e **não precisou de mudança**: os 3 links ali (Graph API Explorer, System Users, Access Token Debugger) já estão agrupados corretamente dentro do bloco do campo "Token da Marketing API para gerenciamento" — não são duplicados entre si, cada um cobre um caminho diferente e legítimo pra obter/validar o mesmo token (teste rápido via Explorer, token de produção via System Users, conferência via Debugger).
