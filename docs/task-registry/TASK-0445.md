## Objetivo

Achado real, print anotado com um círculo vermelho: no painel "Editar produto" (Base de Conhecimento → Catálogo de Serviços, mobile), os botões de duplicar produto, excluir produto e "Fechar" apareciam todos amontoados/sobrepostos no canto superior direito.

## Investigação

O painel tem duas barras de ação no mesmo canto superior direito: uma barra "Fechar" mobile (`lg:hidden`, dentro do fluxo normal do documento) e um grupo de ícones duplicar/excluir posicionado com `absolute top-3 right-3` — sem nenhuma classe responsiva, sempre renderizado independente do tamanho de tela. No desktop isso nunca dava problema (a barra "Fechar" só existe no mobile), mas no mobile os dois elementos disputavam exatamente o mesmo espaço, ficando visualmente empilhados.

## Correção

`src/components/AgentKnowledgeBase.tsx`: duplicar/excluir produto agora entram na própria barra "Fechar" no mobile (mesma linha, com "Fechar" por último). O grupo posicionado (`absolute`) vira exclusivo do desktop (`hidden lg:flex`), onde não há mais nenhuma barra concorrendo por aquele canto. Nenhuma mudança de comportamento — os handlers (`handleDuplicateProduct`/`handleDeleteProduct`) continuam os mesmos, só a posição dos botões no mobile.

## Arquivos/commits

`src/components/AgentKnowledgeBase.tsx`, `src/components/__tests__/AgentKnowledgeBase.productEditHeaderOverlap.test.tsx` (novo, 3 testes).

## Validação

`npm run lint` (limpo), `npx vitest run` (323 arquivos / 1862 testes, 3 novos) e `npm run build` (limpo). Os 3 testes novos cobrem: o grupo posicionado carrega as classes `hidden`/`lg:flex` (nunca aparece por padrão), duplicar produto pela barra mobile funciona (mesmo comportamento de sempre), e excluir produto pela barra mobile funciona e fecha o painel.

## Pendente ou risco

Mudança puramente visual/estrutural (CSS + reposicionamento de botões existentes), sem lógica nova nem toque em dado sensível — não é área crítica (autenticação, pagamento/mensageria, `tenant_id`).
