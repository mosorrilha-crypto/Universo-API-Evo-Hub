## Objetivo

Avançar lead pro estágio Ganho no CRM automaticamente quando a seña é verificada

## Atualizações

O CRM (`server/routes/crm.ts`) e o fluxo real de verificação de pagamento
(Escalonamentos → `resolve-payment`, via `recordFinancialTransactionForVerifiedPayment`
em `server/routes/conversations.ts`) eram dois sistemas paralelos: confirmar uma seña
criava a transação financeira (`status: 'pago'`) mas nunca tocava no estágio do lead no
CRM, deixando leads com pagamento real confirmado presos em estágios antigos do funil
(`novo`/`contato`/`proposta`) a menos que um operador voltasse ao CRM e marcasse "Ganho"
manualmente.

`recordFinancialTransactionForVerifiedPayment` agora chama
`upsertCrmLeadState(tenantId, phone, { stage: 'ganho' })` logo após confirmar o
pagamento — cobre os 3 pontos reais que chamam essa função (Escalonamentos
`resolve-payment`, cadastro manual com pagamento já recebido, `verify-payment`). Não
chama `recordFinancialTransactionForWonDeal` (`server/routes/crm.ts`), que criaria uma
segunda transação financeira `pendente` duplicada — o registro real já é feito por este
mesmo fluxo. Erro no CRM só loga (`console.warn`), nunca derruba a confirmação real do
pagamento (mesmo padrão de tolerância a falha já usado no resto da função).

Confirmado com o gestor via AskUserQuestion: implementar a ligação automática, e
reaproveitar o estágio `'ganho'` já existente (sem estágio novo no enum).

**Arquivos alterados:**
- `server/routes/conversations.ts`
- `server/routes/__tests__/conversationsVerifyPaymentFinancial.test.ts` (4 casos novos:
  lead sem estado prévio de CRM, lead em outro estágio, pagamento rejeitado não mexe no
  CRM, reentrega/retry idempotente)
- `docs/agente-trafego-pago/ESTRATEGIA-TRAFEGO-MONIQUE.md` (registro de decisão,
  01/09/2026)

**Validação:** `npm run lint`, `npx vitest run` (1141 testes — 1 falha pré-existente
não relacionada em `knowledgeBaseStore.test.ts`, confirmada via `git stash` que já
falhava antes desta mudança) e `npm run build` passaram limpos antes do commit.

**Pendente/risco:** isso não fecha sozinho a porta de saída do H1 (ver
`ESTRATEGIA-TRAFEGO-MONIQUE.md`) — a origem/atribuição da seña (`ctwa_clid`) continua
sendo um problema separado. Só remove o trabalho manual duplicado entre Financeiro e
CRM.
