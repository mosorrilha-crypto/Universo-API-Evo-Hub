# TASK-0202 — Restaura workflow do CodeQL e job de Dependency review no CI, agora que o repositorio esta publico de proposito (GHAS gratis)

- **Issue central:** [#290](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/290)

## Objetivo

Restaura workflow do CodeQL e job de Dependency review no CI, agora que o repositorio esta publico de proposito (GHAS gratis)

## Contexto

Depois de mesclar a varredura completa dos 52 alertas de CodeQL (TASK-0197
a TASK-0201, PRs #578-#582), usuário verificou `Security → Code scanning`
de novo e viu um banner "CodeQL is reporting warnings" com os mesmos 52
alertas de antes, sem nenhuma mudança. Investigação:

1. `.github/workflows/codeql.yml` foi **removido** hoje mais cedo por outra
   sessão do Claude (TASK-0192, commit `8c23a50`, PR #576) — motivo
   documentado: 2 PRs (#560/#561) com logs idênticos mostrando o job
   falhando persistentemente porque **este era, na época, um repositório
   privado sem licença paga de GitHub Advanced Security** (CodeQL/Dependency
   review são gratuitos só em repositório público). Print de
   `CodeQL → language:actions` confirmou a causa exata: "Actions workflow
   file not found — the Action workflow file .github/workflows/codeql.yml
   no longer exists."
2. A mesma TASK-0192 (parte 2, revisão de segurança) já tinha achado que o
   repositório estava **público** quando deveria estar privado (confirmado
   por chamada HTTP não-autenticada). Reconfirmei isso nesta sessão via
   WebFetch na página pública do repo — badge "Public" visível, código
   completo acessível sem login.
3. Usuário esclareceu: deixou o repositório público **de propósito**,
   justamente pra ter GitHub Advanced Security de graça (CodeQL,
   Dependency review) — não foi um erro de configuração. Isso muda a
   decisão da TASK-0192: com o repo público, os dois jobs removidos voltam
   a fazer sentido e devem funcionar sem custo.

## Correção

Restaurei o conteúdo original de `.github/workflows/codeql.yml` e do job
`dependency-review` em `.github/workflows/ci.yml` a partir do commit pai
da remoção (`git show 8c23a50^:...`) — conteúdo idêntico ao que existia
antes da TASK-0192, com um comentário novo em cada arquivo explicando o
histórico (removido → repo ficou público de propósito → restaurado) e
avisando pra remover de novo se o repo voltar a ficar privado sem GHAS
pago.

## Validação

- `npm run lint`, `npx vitest run`, `npm run build` — mudança é só em
  arquivos `.github/workflows/*.yml`, não toca código da aplicação; rodei
  os três mesmo assim por convenção do repositório (nenhum motivo pra
  quebrar, mas confirma que nada mais mudou sem querer).
- Validação real do próprio objetivo (o CodeQL de fato voltar a rodar e
  fechar/reabrir alertas corretamente) só acontece depois do merge, quando
  o workflow rodar de verdade num push/PR real — não dá pra simular
  localmente.

## Pendente/risco

- **Não fiz self-merge**: mudança em CI/CD é uma das categorias que trato
  com cautela extra (pode afetar todo PR futuro) — aguardando "mescla"
  explícita do usuário, mesmo não sendo código de app.
- Depois do merge, o próximo push/PR deve mostrar os checks "CodeQL",
  "Analyze (javascript-typescript)", "Analyze (actions)" e "Dependency
  review" de novo. Recomendo ao usuário: depois que isso rodar contra o
  `main` atual (já com os 5 fixes de segurança da varredura anterior
  mesclados), conferir `Security → Code scanning` de novo pra ver quantos
  dos 52 alertas realmente fecharam.
- Risco documentado nos comentários dos próprios arquivos: se o repositório
  voltar a ficar privado sem uma licença paga de GHAS, estes dois jobs
  voltam a falhar permanentemente em todo PR/push — se isso acontecer, a
  correção é remover de novo (mesma decisão da TASK-0192), não tentar
  "consertar" o job.
