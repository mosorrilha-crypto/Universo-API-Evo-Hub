# TASK-0058 — remove aparência de botão clicável do WhatsApp e corrige resquício de português no PDF do catálogo

- **Iniciado em:** 2026-08-24T23:40:24.131Z
- **Agente/plataforma:** Claude
- **Issue central:** [#290](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/290)
- **Status:** concluída

## Objetivo

Depois de assumir responsabilidade contínua pelo catálogo (página pública + PDF), revisei eu mesmo o PDF gerado pela TASK-0055 (com o dono do produto perguntando se ele daria uma boa experiência ao cliente) e encontrei dois problemas antes de qualquer feedback externo:

1. O botão terracota "CONSULTAR POR WHATSAPP" (com seta ↗) aparece em cada um dos 10 produtos, idêntico ao link clicável da página real — mas no PDF (imagem rasterizada, sem interação) é uma isca visual morta: parece 100% clicável e não faz nada ao tocar.
2. Enquanto revisava, percebi que `main` tinha recebido um commit concorrente (`feat(catalog): improve loading and add ES/PT switcher`) que adiciona um switch de idioma à página pública **e** uma função `normalizeSpanishText()` pra corrigir na exibição dois resquícios de português que sobraram no campo `price` de produtos da Monique ("varia por efeito", "varia pela técnica") — a TASK-0049 só tinha traduzido `name`/`description` no banco, não `price`. O PDF (que não tem esse patch) continuava mostrando o português cru.

## Correção

`src/lib/catalogPdf.ts`:
- Botão de WhatsApp por produto trocado de CTA preenchido pra uma linha de texto simples ("Consultas: WhatsApp {número}") — sem aparência de botão, mas com informação real que o cliente pode usar (o número, que o botão antigo nem mostrava).
- Adicionada a mesma `normalizeSpanishText()` da página real (espelhada, não importada — são bundles/módulos diferentes) e aplicada em todo texto vindo do produto: categoria, nome, descrição, preço e variantes (código + preço) — mesmo alcance que `localizeCatalogText` aplica na página quando o idioma é espanhol.

## Arquivos alterados

- `src/lib/catalogPdf.ts`
- `docs/task-registry/TASK-0058.md`

## Validação

- `npm run lint`: 0 erros (precisou `npm install` antes — `package.json` já tinha `@testing-library/react`/`@testing-library/user-event` de um commit concorrente que não estava instalado localmente).

- `npm run build`: build de frontend (Vite) e backend (esbuild) concluídos sem erro.
- Validação manual via Playwright com os 10 produtos reais da Monique: confirmado visualmente que "Gs 60.000 a Gs 150.000 (varia pela técnica)" agora sai como "... (varía según la técnica)", e que os cartões de produto mostram "Consultas: WhatsApp 595994798081" em vez do botão morto.

## Pendente ou risco

Nenhum bloqueante. Duas notas pra decisão futura, não implementadas agora (fora do escopo de "consertar o que está quebrado"):
- O PDF só cobre o idioma espanhol — a página pública agora tem toggle ES/PT, mas o botão "Baixar PDF" (`PublicCatalogSettings.tsx`) não expõe escolha de idioma. Se o negócio quiser, dá pra adicionar.
- O resquício de português no campo `price` no banco (`knowledge_base.data->products`) continua lá — tanto a página quanto o PDF agora corrigem só na exibição (`normalizeSpanishText`), não na fonte. Corrigir o dado direto no Supabase eliminaria a necessidade do patch nos dois lugares.
