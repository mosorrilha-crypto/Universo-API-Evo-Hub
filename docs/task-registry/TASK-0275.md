# TASK-0275 — Remove cabeçalho duplicado da tela de Agenda e Financeiro (OperationsModuleFrame vs hero interno)

- **Iniciado em:** 2026-09-04T19:11:04.035Z
- **Agente/plataforma:** Claude
- **Issue central:** [#504](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/504)
- **Status:** concluída

## Objetivo

Remove cabeçalho duplicado da tela de Agenda e Financeiro (OperationsModuleFrame vs hero interno)

## Atualizações

Pedido direto do usuário: "acessa o sistema e encontre desperdícios de espaço, eu já encontrei
dois cabeçalhos na aba de agenda" — seguimento da TASK-0272 (unificação das barras do header).

Investigação (`src/App.tsx`): as abas **Agenda** e **Financeiro** envolvem `AgendaWorkspace`/
`FinancialWorkspace` dentro de `<OperationsModuleFrame title="Agenda" eyebrow="..." description="..."
compact>` — esse componente já renderiza seu próprio `<header>` com ícone, eyebrow, `<h1>{title}</h1>`,
descrição e um badge "Dados sincronizados com a operação". Só que `AgendaFinanceiroCenter.tsx`
(renderizado dentro, via `scope="agenda"`/`scope="financial"`) TAMBÉM tem seu próprio hero completo
(`agenda-financeiro-workspace__hero`, linhas ~590-602): eyebrow diferente ("Operação comercial"/
"Controle de caixa"), o mesmo `<h1>Agenda</h1>`/`<h1>Financeiro</h1>` de novo, descrição diferente,
e os botões de ação reais (Novo agendamento / Nova despesa / Receita avulsa). Resultado real
confirmado visualmente (harness temporário com os componentes reais, removido depois — ver
Validação): dois blocos "Agenda" (ou "Financeiro") empilhados, com o badge "Dados sincronizados"
solto entre eles, antes de qualquer conteúdo útil (métricas, calendário).

Descobri que o próprio código já sabia disso parcialmente: `OperationsModuleFrame.tsx` tinha o
comentário "variante compacta remove hero redundante no Financeiro móvel" e uma regra CSS
(`@media (max-width: 639px) { .operations-module-frame--compact > .operations-module-frame__header
{ display: none; } }`) que já escondia o cabeçalho externo — só que **apenas no mobile** (<640px).
No desktop a duplicação ficava visível. A aba **CRM** também usa `OperationsModuleFrame compact`,
mas `CrmWorkspace` não tem hero próprio — depende desse cabeçalho externo pro título aparecer no
desktop, então não dava pra generalizar a regra CSS pra todos os `--compact` sem quebrar o CRM.

Fix aplicado (`src/components/OperationsModuleFrame.tsx` + `src/App.tsx`): adicionada prop
`hideHeader?: boolean` que pula a renderização do `<header>` inteiro (não só CSS `display:none`,
já que o conteúdo nunca precisa existir no DOM pras duas telas que já têm hero próprio). Passada
`hideHeader` nas duas chamadas de Agenda e Financeiro em `App.tsx`; CRM ficou intocado.

## Validação

- `npm run lint` (tsc --noEmit): limpo.
- `npx vitest run`: 262 arquivos / 1435 testes, todos passando.
- `npm run build`: build de frontend + servidor sem erros.
- Validação visual manual: harness temporário (3 arquivos `dev-preview-*.tsx` + `.html`, não
  commitados, removidos ao final) renderizando `OperationsModuleFrame` + `AgendaWorkspace`,
  `OperationsModuleFrame` + `FinancialWorkspace`, e `OperationsModuleFrame` + `CrmWorkspace` com
  os componentes reais (props mínimas). Screenshots via `agent-browser`/Chromium confirmaram:
  Agenda e Financeiro agora mostram um único bloco de título (o hero interno, com os botões de
  ação reais), e o CRM manteve seu cabeçalho "CRM e Vendas" exatamente como antes.

## Pendências ou riscos

- Não testei em produção/staging com dados reais (Supabase) — apenas com mocks locais.
- Notei uma possível redundância menor, não corrigida aqui (fora do escopo do pedido): dentro da
  própria aba CRM, `CrmWorkspace`/`OperatorCRM` tem um sub-cabeçalho "Vendas" logo abaixo do
  "CRM e Vendas" do `OperationsModuleFrame" — títulos parecidos mas não idênticos, pode valer uma
  checagem futura se o usuário quiser continuar essa varredura de espaço.
- Continuando a varredura geral de desperdício de espaço pedida pelo usuário; próximas telas
  serão reportadas em atualização separada nesta mesma issue/task se algo mais for encontrado.
