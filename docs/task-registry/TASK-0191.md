# TASK-0191 — Remove Google API Key exposta em texto puro (firebase-applet-config.json) migrando pra variaveis de ambiente VITE_FIREBASE_*

- **Iniciado em:** 2026-09-01T17:04:32.188Z
- **Agente/plataforma:** Claude
- **Issue central:** [#290](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/290)
- **Status:** concluída (código) — pendente ação manual no Render (setar env vars) e decisão do usuário sobre rotacionar/restringir a chave no Google Cloud Console

## Objetivo

Remove Google API Key exposta em texto puro (firebase-applet-config.json) migrando pra variaveis de ambiente VITE_FIREBASE_*

## Contexto

GitHub Secret Scanning (Settings → Security → Secret scanning alerts) sinalizou
uma "Google API Key" como "Public leak", aberta há 22 dias, apontando pra
`firebase-applet-config.json:4`. É a apiKey do Firebase Web usada pelo
"Login com Google"/e-mail do painel (`src/lib/firebase.ts`, importado por
`src/components/LoginModal.tsx`) — feature real e ativa, não código morto.

O próprio `.env.example` já documentava (antes desta task) que essa apiKey é
"pública por design" — a segurança real do Firebase Web vem das Firestore
Rules (`firestore.rules`, que exige `request.auth != null`), não do sigilo da
chave. Então isso não é uma vulnerabilidade de acesso não autorizado por si
só, mas comitar em texto puro no git ainda é ruído de alerta desnecessário e
foge do padrão do resto do projeto (todo segredo real vem de env var).

## Decisão (pedida ao usuário)

Apresentei 3 opções: (a) corrigir código + usuário rotaciona a chave, (b) só
corrigir o código mantendo a chave atual, (c) não mexer agora. Usuário
escolheu **(b)**: migrar pra env var sem trocar o valor da chave.

## Correção

- `firebase-applet-config.json` removido do git (`git rm`).
- `src/lib/firebase.ts`: monta `firebaseConfig` a partir de
  `import.meta.env.VITE_FIREBASE_*` em vez de importar o JSON; log de aviso
  se `VITE_FIREBASE_API_KEY` não estiver setada.
- `src/vite-env.d.ts` (novo): declara `ImportMetaEnv`/`ImportMeta` — o
  projeto nunca tinha usado `import.meta.env` no frontend antes, `tsc --noEmit`
  não reconhecia a propriedade sem isso.
- `.env.example`: documenta as novas `VITE_FIREBASE_*` (com placeholders, não
  o valor real).

## Pendente / risco

- **Render (`srv-d9p5t5e7bikc738hlen0`, build `npm install && npm run build`)
  precisa das 6 `VITE_FIREBASE_*` setadas como env var** antes do deploy
  desta PR ir pra produção — Vite embute `import.meta.env.VITE_*` em tempo de
  build; sem elas, o build passa (não há validação obrigatória, é só um
  `console.warn`) mas o login com Google/e-mail quebra em produção. Vou
  configurar essas env vars no Render com o mesmo valor atual (reaproveitado,
  não rotacionado, por decisão do usuário) antes de pedir merge.
- Recomendado ao usuário (não executado por mim, sem acesso ao Google Cloud
  Console): restringir a chave por domínio/referrer HTTP em
  https://console.cloud.google.com/apis/credentials, já que ela foi
  publicamente indexada por 22+ dias — mesmo sendo "pública por design", uma
  chave sem nenhuma restrição de referrer pode ser reaproveitada por
  terceiros pra consumir cota de outras APIs do mesmo projeto GCP, se
  alguma outra API além do Firebase estiver habilitada nele.
- O alerta do GitHub provavelmente continua "aberto" mesmo depois do merge —
  a chave ainda existe no histórico de commits antigos; fechar de verdade
  exigiria reescrever histórico (não feito aqui, fora de escopo sem pedido
  explícito) ou rotacionar a chave.
