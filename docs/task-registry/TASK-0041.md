# TASK-0041 — aplica migration 0045 pendente em produção (incidente real: spam de alerta de erro no WhatsApp da Monique)

- **Iniciado em:** 2026-08-24T04:08:00.000Z
- **Agente/plataforma:** Claude
- **Issue central:** [#290](https://github.com/mosorrilha-crypto/Universo-API-Evo-Hub/issues/290)
- **Status:** concluída

## Objetivo

Incidente real reportado pelo dono do produto: o número de WhatsApp da própria Monique (`admin_alert_phone` dela) estava recebendo repetidamente (a cada ~15min, batendo com o cooldown de `systemErrorAlertService.ts`) a mensagem `⚠️ Erro real no sistema GET /api/meta-ads/connection: Não foi possível ler a configuração Meta Ads: column tenant_meta_credentials.meta_ads_management_access_token does not exist`.

## Causa raiz confirmada

A migration `supabase/migrations/0045_meta_ads_management.sql` (adiciona a coluna `tenant_meta_credentials.meta_ads_management_access_token` e a tabela `meta_ads_operation_requests`, parte da feature "Central de Anúncios Meta" do PR #384, já mergeado) **nunca tinha sido aplicada em produção** — confirmado por `mcp__Supabase__list_migrations` (não aparecia no histórico) e por consulta direta a `information_schema.columns`/`to_regclass` no projeto `pkocepjfedtsxmufymvd`. O código do PR #384 já assumia a coluna/tabela existentes (`metaAdsManagementService.ts`), então toda chamada a `GET /api/meta-ads/connection` (rota poll periódica do painel) falhava, disparando `notifySystemError` — que tem cooldown global de 15min, exatamente o intervalo visto nos prints do WhatsApp real da Monique.

Reforça o padrão de risco já documentado no `CLAUDE.md` (mesma classe do incidente da issue #93): migration commitada no repo mas nunca de fato rodada em produção, porque em algum momento não foi aplicada via `apply_migration`/MCP nem manualmente no SQL Editor.

## Correção

Migration `0045_meta_ads_management` aplicada em produção via `mcp__Supabase__apply_migration` (projeto `pkocepjfedtsxmufymvd`). Confirmado depois via SQL direto: coluna `meta_ads_management_access_token` existe em `tenant_meta_credentials`, e a tabela `meta_ads_operation_requests` existe. Nenhuma mudança de código necessária — o bug era 100% de dado/infra (migration não aplicada), não do código do PR #384.

## Arquivos alterados

- Nenhum arquivo de código. Só a migration `supabase/migrations/0045_meta_ads_management.sql` (já existente no repo desde o PR #384) aplicada em produção.
- `docs/task-registry/TASK-0041.md` (este registro).

## Validação

- `mcp__Supabase__list_migrations`: `0045_meta_ads_management` agora aparece no histórico do projeto.
- `mcp__Supabase__execute_sql`: `information_schema.columns` confirma a coluna nova em `tenant_meta_credentials`; `to_regclass('public.meta_ads_operation_requests')` deixou de retornar `null`.
- Não foi possível confirmar em tempo real que os alertas pararam de chegar no WhatsApp da Monique (isso só se confirma no próximo ciclo de poll do painel após o fix) — o dono do produto pode confirmar visualmente.

## Pendente ou risco

- PR #393 (`fix: exibir link do token de gerenciamento Meta`), aberto por outra sessão, ainda não mergeado — não tocado por esta tarefa.
