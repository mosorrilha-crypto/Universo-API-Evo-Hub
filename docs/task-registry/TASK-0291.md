## Objetivo

Corrige dropdown de etiqueta (era select nativo), conserta filtro de 24h que não abria (popover cortado por overflow), remove contorno verde da busca/etiqueta e reduz margens do menu de ações da conversa

## Atualizações

Pedido direto (05/09/2026), 4 pontos com prints anotados da tela de Atendimento no mobile: (1) o
botão de etiqueta abre um dropdown nativo do sistema, sem tema; (2) um "ícone de filtros" não abre
nada ao tocar; (3) a caixa de busca e o botão de etiqueta mostram uma linha verde; (4) o menu ⋮ de
ações da conversa tem margens grandes demais na lista.

**Achado real antes de tudo — branch estava desatualizada:** ao investigar o ponto 2, o código local
não batia com o print (o print mostrava um ícone de funil que meu arquivo local não tinha nessa
posição). `git fetch origin main` mostrou que a branch estava 5 commits atrás — em especial o PR #666
("filtro de janela de 24h (ícone + lista)"), que introduziu esse exato ícone de funil, meu commit
anterior (TASK-0286) nunca tinha sido rebaseado sobre ele. Resetei a branch pra `origin/main` (sem
perda: só havia os dois arquivos de preview temporários, não versionados) antes de continuar.

**Ponto 2 — o "ícone de filtros" (funil, ao lado de "Fora das 24h"):** o usuário confirmou via
pergunta direta que é esse ícone mesmo. Causa raiz real: a fileira de pills (Tudo/Não lidos/filtro de
24h/etiqueta) precisa de `overflow-x-auto` pra rolar horizontalmente — mas a spec de CSS força
`overflow-y` pro mesmo valor (`auto`, que recorta) sempre que só um eixo é `visible`. O popover do
filtro de 24h era `position: absolute` ancorado dentro dessa fileira, então ficava CORTADO
verticalmente pelo próprio container: o estado abria certinho (o ícone até ganhava o destaque verde
de "ativo"), só que a lista de opções nunca aparecia na tela — daí "não abre nada". Corrigido trocando
esse popover (e o novo popover de etiqueta, ponto 1, que teria o mesmo problema) para
`position: fixed`, com coordenadas calculadas via `getBoundingClientRect()` do botão no momento do
clique (novos refs/estado: `windowFilterBtnRef`/`windowFilterMenuPos`,
`labelFilterBtnRef`/`labelFilterMenuPos`). `position: fixed` não é afetado pelo overflow do
ancestral.

**Ponto 1 — dropdown de etiqueta:** o `<select>` nativo (sempre renderiza como picker do sistema
operacional no mobile, impossível de estilizar) virou um botão + popover temático, mesmo padrão
visual/estrutural do popover do filtro de 24h ao lado (inclusive o mesmo `position: fixed` pelo motivo
acima). Mostra a etiqueta ativa truncada no próprio botão; opção "🏷️ Todas etiquetas" sempre no topo
da lista.

**Ponto 3 — contorno verde na busca e no botão de etiqueta:** mesma causa já resolvida uma vez na
TASK-0259 pro campo de digitação da conversa — o Chrome/Android trata o toque num `<input>`/`<button>`
como "navegação por teclado" e aplica o contorno verde global de acessibilidade
(`button/a/input/textarea/select:focus-visible` em `index.css`) mesmo sem uso real de teclado. Seguido
o mesmo padrão já estabelecido: duas novas classes soltas em `index.css`
(`.atendimento-search-input:focus-visible`, `.atendimento-label-filter-trigger:focus-visible`) com
`outline: none`, fora de qualquer `@layer` (CSS solto sempre vence camada Tailwind nas Tailwind v4).
Aplicadas no `<input>` de busca e nos dois botões-gatilho de popover (filtro de 24h e etiqueta) — a
regra global continua intacta pro resto do app.

**Ponto 4 — margens do menu ⋮:** reduzido `px-3.5 py-2.5` → `px-3 py-2` em todos os 14 botões desse
menu específico (`.mobile-header-context-menu`, linhas ~4542–4682 de `WhatsAppLeadsSim.tsx`) e o
`min-height` da regra CSS do menu de `2.75rem` → `2.25rem`.

- Não testado em dispositivo Android real — apenas emulação de viewport/touch via Playwright.
- O popover de etiqueta e o de filtro de 24h calculam a posição só no momento do clique; se a página

  o popover em qualquer toque fora dele — mesmo comportamento que os outros menus do app já tinham).
