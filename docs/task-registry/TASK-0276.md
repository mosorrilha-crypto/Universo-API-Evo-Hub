## Objetivo

corrige flicker na conversa aberta a cada mensagem SSE, causado por historyLoading limpando a lista ja carregada

## Atualizações

Pergunta direta do dono do produto, com print da tela de Conversas: "a
cada nova mensagem a página inteira pisca para atualizar isso é um bug?".

**Causa raiz confirmada no código** (`src/components/WhatsAppLeadsSim.tsx`):
toda mensagem SSE que chega pra conversa atualmente aberta chama
`loadRealConversationHistory(phone, ...)`, que liga
`historyLoading: true` antes do fetch e desliga depois. O render da
lista de mensagens usava só esse flag pra decidir entre mostrar o
placeholder "Carregando histórico completo desta conversa..." OU a
lista real — então cada mensagem nova (mesmo já com o histórico
inteiro carregado e visível na tela) trocava a lista inteira pelo
placeholder por uma fração de segundo, até a mesma resposta (agora com
1 mensagem a mais) voltar. Esse blank-e-repopula, repetido a cada
mensagem recebida numa conversa com tráfego real, é exatamente o
"piscar" relatado.

Corrigido: o placeholder só aparece quando a conversa NUNCA foi
carregada ainda (`historyLoading && !historyLoaded`) — um refresh
silencioso disparado pelo SSE numa conversa já carregada não esconde
mais o que já está na tela, só atualiza o conteúdo quando o fetch
termina.

Arquivo alterado: `src/components/WhatsAppLeadsSim.tsx`.
