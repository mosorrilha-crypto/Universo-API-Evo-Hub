## Objetivo

Suporte à Evolution API no Disparo em Massa: envio de texto livre (sem template Meta) pro número operacional do tenant, com lote pequeno e espaçamento maior por segurança

## Contexto

Continuação direta da TASK-0366: a lista de reaquecimento estava pronta, mas o Disparo em Massa (TASK-0171) só sabia mandar via template aprovado da Meta Cloud API — Monique usa Evolution API (self-hosted/Baileys), que não tem conceito de template. Pedido direto, entendendo o risco (número operacional real, único canal ativo): "implementa com o menor lote possível primeiro e espaçamento maior".

Confirmado no código antes de implementar: `resolveCredentialsForTenant`/`resolveCredentialsForConversation` (`tenantResolver.ts`) já resolvem corretamente credenciais Evolution pro operacional do tenant — só o job de envio da campanha (`broadcastSenderJob.ts`) estava travado na chamada de template. `sendEvolutionTextMessage` (`evolutionSend.ts`) já existe e é usada hoje pros lembretes de agendamento via Evolution.

## Mudança

- `supabase/migrations/0083_broadcast_evolution_provider.sql`: `broadcast_numbers.provider` (`meta` default | `evolution`) — aplicada via Supabase MCP.
- `server/services/broadcastStore.ts`: `BroadcastNumberProvider`, `createBroadcastNumber` aceita `provider` e aplica defaults bem mais conservadores pra Evolution quando o campo não é informado (`per_minute_cap: 1`, `daily_cap: 20`, `min_gap_seconds: 60` vs. 5/1000/8 da Meta).
- `server/routes/broadcast.ts`: piso/teto de segurança pra número Evolution, reconferido tanto na criação quanto no PATCH — nunca aceita `minGapSeconds < 45s`, `perMinuteCap > 3`, ou `dailyCap > 100`, mesmo que o operador tente configurar algo mais agressivo.
- `server/services/broadcastSenderJob.ts`: `processCampaignNumber` agora ramifica por `number.provider`. Pra Evolution: `EVOLUTION_MAX_BATCH_PER_TICK = 2` (vs. 20 da Meta) prevalece sobre qualquer `per_minute_cap`/`daily_cap` configurado — "o menor lote possível" é garantido no código, não só um default sugerido. Envia o texto já renderizado (`renderTemplateDisplayText`, variáveis substituídas) via `sendEvolutionTextMessage`, sem template. A conversa sai sem `phone_number_id` próprio (`null`) — Evolution não tem "pool de números dedicados" como a Meta (Baileys só conecta UM número por instância) — o que faz o envio cair naturalmente no operacional real do tenant via `resolveCredentialsForConversation`, sem precisar tocar em `tenantResolver.ts`.
- `server/services/conversationStore.ts`: `getOrCreateConversationForBroadcast` aceita `broadcastPhoneNumberId: string | null` (era só `string`).
- `src/components/BroadcastAdminPanel.tsx`: seletor de provedor no cadastro de número, campos condicionais (Meta mostra WABA ID/token/qualidade; Evolution mostra só um identificador informativo + aviso de risco), defaults conservadores pré-preenchidos ao trocar pra Evolution, aviso de teto de segurança fixo, e coluna "Provedor" na listagem.
- **Sobre o link de qualidade pedido:** não existe um link real da Meta pra conferir a qualidade de um número Evolution — o WhatsApp Manager da Meta (`business.facebook.com/wa/manage/phone-numbers`) só mostra números registrados de verdade na Meta Cloud API (WABA), e um número Evolution/Baileys nunca é registrado lá (é uma sessão comum do WhatsApp Web automatizada, não uma linha oficial da plataforma). Adicionei esse link no formulário, mas com o texto deixando explícito que ele só vale pra número Meta — não haveria honestidade em fingir que existe um painel oficial de qualidade pra número Evolution.

**Pendente ou risco:**
- **Risco de bloqueio do número operacional real ainda existe**, mesmo reduzido pelos limites — mandar mensagem em massa (mesmo 2 por vez, espaçadas) por um número não-oficial pra contatos que não respondem há dias é um padrão que o WhatsApp pode sinalizar. Recomendo fortemente rodar a primeira campanha com um lote pequeno de teste (2-3 contatos) antes de liberar pros 22 da lista inteira, e observar se o número continua funcionando normalmente no atendimento comum depois.
- Ainda falta CRIAR o número Evolution no painel (Disparo em Massa → Números) e a campanha em si (template com o texto da oferta + a lista já pronta da TASK-0366) — essa parte é decisão de conteúdo/negócio, não fiz sozinho.
- Nenhum jeito real de verificar "qualidade" de um número Evolution — o sinal mais próximo disponível é observar entrega/leitura normais no WhatsApp Business (app) do próprio número, e ficar atento a qualquer notificação de restrição/banimento que aparecer no celular.
