## Objetivo

Transcricao de audio via Groq/Whisper como primeira tentativa (analise em texto via Groq), fallback pro Gemini de sempre

## Atualizações

**Contexto:** última extensão do mesmo incidente ativo (créditos Gemini
esgotados) das TASK-0346/0348/0350. Discutido explicitamente com o dono do
produto ao responder "quem transcreve os áudios?" — confirmei que só o
Gemini transcrevia (`geminiTranscription.ts`), sem nenhum caminho Groq, e
que o fallback existente nunca inventa texto mas também não transcreve
nada quando o Gemini está fora. Pedido direto: "margea e avança com o
winsper" (Whisper).

**Implementado:**
- `server/services/groqClient.ts`: novo `callGroqAudioTranscription`
  (multipart/form-data pro endpoint `/audio/transcriptions` do Groq,
  `GROQ_WHISPER_MODEL = 'whisper-large-v3'`, `response_format:
  'verbose_json'` pra também vir o idioma detectado). Lança em qualquer
  falha (rede, timeout, HTTP não-2xx, campo "text" ausente) — uma
  transcrição vazia (silêncio real) NÃO é tratada como falha aqui, é
  responsabilidade de quem chama decidir o que fazer.
- `server/services/geminiTranscription.ts`: nova função `transcribeAudio`
  (Groq-primeiro-Gemini-de-fallback) que:
  1. Roda a MESMA checagem determinística de silêncio
     (`isAudioEffectivelySilent`, ffmpeg) ANTES de escolher qualquer
     provedor — Whisper é tão suscetível quanto o Gemini a alucinar uma
     transcrição plausível a partir de silêncio puro (achado documentado
     em 29/08/2026 pro Gemini), a mesma barreira vale pros dois.
  2. Transcreve via Whisper (Groq). Se o texto vier vazio, retorna
     `noSpeechDetectedResult()` sem gastar a 2ª chamada.
  3. Se houver texto real, faz uma SEGUNDA chamada Groq (texto puro, não
     áudio — reaproveita `callGroqJsonCompletion` com
     `GROQ_SPECIALIST_MODEL`) pra derivar summary/intent/sentiment/
     keyPoints/suggestedReply/urgencyScore a partir da transcrição
     literal (Whisper só transcreve, não analisa).
  4. Qualquer falha em QUALQUER uma das duas chamadas cai pro caminho
     100% Gemini já existente (`transcribeAudioWithGemini`, mantido
     intacto) — nunca uma transcrição "órfã" sem o resto dos campos.
  - `TranscribeAudioOutcome.source` ganhou o valor `'groq'` (antes só
    `'gemini' | 'fallback'`).
  - Nova função exportada `isRealTranscriptionSource(source)` — `true`
    pra `'groq'`/`'gemini'`, `false` pra `'fallback'` — substitui o
    padrão `source === 'gemini'` repetido em 4 lugares diferentes que
    decidiam "transcrição real, pode disparar resposta automática/checar
    conteúdo" (esse padrão pré-existia só verificando 'gemini'; sem
    generalizar, uma transcrição bem-sucedida via Groq seria tratada como
    se não tivesse fala detectada, e a chamada de auto-reply/escalonamento
    nunca dispararia).
- Atualizados os 4 chamadores pra usar `transcribeAudio` +
  `isRealTranscriptionSource` no lugar de `transcribeAudioWithGemini` +
  `source === 'gemini'`, e passar `groqApiKey` (já existia como dependência
  em todos os 4, só não chegava até a transcrição): `server/routes/ai.ts`
  (`/api/transcribe`), `server/services/transcriptionQueue.ts` (áudio
  recebido do cliente), `server/routes/conversations.ts`
  (`/retry-transcription` e `/send-media` quando o operador manda áudio),
  `server/routes/webhooks.ts` (eco de áudio mandado direto do celular).

**Testes:**
- Novo `server/services/__tests__/geminiTranscriptionGroqFallback.test.ts`
  (5 casos): sucesso via Groq (Whisper + análise) sem chamar o Gemini;
  fallback pro Gemini quando o Whisper falha (HTTP não-2xx); fallback pro
  Gemini quando só a 2ª chamada (análise) falha, garantindo que nunca
  sobra uma transcrição sem o resto dos campos; silêncio real via Whisper
  não gasta a 2ª chamada nem cai pro Gemini; sem `groqApiKey`, nunca chama
  `fetch` (comportamento idêntico ao anterior).
- Testes pré-existentes que mockavam `transcribeAudioWithGemini`
  diretamente (`transcriptionQueueTenantContext.test.ts`,
  `transcriptionQueueHistoryCutoff.test.ts`,
  `conversationsSendMediaAudioTranscription.test.ts`) atualizados pra
  mockar `transcribeAudio`/`isRealTranscriptionSource` — os chamadores
  reais mudaram de função, então o mock também precisou.
- `geminiTranscriptionRetry.test.ts`/`geminiTranscriptionSilence.test.ts`
  continuam intocados — testam `transcribeAudioWithGemini` diretamente,
  que não mudou de comportamento.

**Validação:** `npm run lint` (`tsc --noEmit`), `npx vitest run` (280
arquivos / 1536 testes, suíte completa) e `npm run build` — todos limpos.
Sem chamada real à API Groq Whisper nesta sessão (sem chave/áudio real
disponível) — validação por testes automatizados com mocks.

**Pendente ou risco:**
- Qualidade real da transcrição/análise via Whisper + Llama só será
  confirmada em produção — recomendo acompanhar os primeiros áudios reais
  depois do deploy, especialmente sotaques/gírias do espanhol paraguaio.
- Custo adicional: cada áudio com fala real agora faz 2 chamadas Groq
  (Whisper + análise) em vez de 1 chamada Gemini — ainda assim mais barato
  que manter o Gemini como único caminho, e só ativa quando `GROQ_API_KEY`
  está configurada (já confirmado ativo em produção).
- `GROQ_WHISPER_MODEL` fixo em `whisper-large-v3` (não a variante
  "turbo", mais rápida/barata) — escolha deliberada por qualidade dado
  que não há segunda chance de qualidade nesta mensagem quando o Gemini
  já está fora; pode ser revisitado se a latência incomodar na prática.
