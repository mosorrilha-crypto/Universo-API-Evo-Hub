## Atualizações

### 2026-08-27 — Corte controlado do runtime implementado

- A PR #457 (editor visual) foi mesclada na `main` por autorização explícita do dono do produto antes de iniciar esta tarefa.
- A verificação read-only no Supabase confirmou os 3 tenants com Base de Conhecimento: cada um possui exatamente 8 documentos publicados, sem rascunho ou histórico arquivado criado pelo backfill.
- Uma segunda verificação read-only confirmou equivalência integral entre `knowledge_base.data` sem `lastSaved` e a composição dos oito documentos `published` para os 3 tenants. `lastSaved` continua reconhecido como metadado de UI, não conteúdo do agente.
- Foi criado `getRuntimeKnowledgeBase(tenantId)`: ele só compõe documentos tipados quando os oito tipos estão publicados; rascunhos e `archived` são sempre excluídos. Se a publicação estiver incompleta ou indisponível, retorna ao blob legado, sem apagar ou alterar qualquer dado de rollback.
- `autoReply.ts` e o webhook de entrada passam a usar a fonte efetiva. Cada leitura consulta o banco novamente, portanto uma publicação concluída entre duas mensagens é aplicada à próxima resposta e não fica fixa em conversa/processo.
- Logs estruturados registram apenas fonte e motivo de fallback (`published_documents`, `legacy_blob`, `unavailable`), sem conteúdo comercial ou de cliente.
- O editor visual passou a informar que a publicação vale na próxima resposta e bloqueia o botão de salvar do formulário legado, que permanece visível apenas para auditoria/rollback.
- Testes específicos cobrem publicação completa, exclusão de rascunho/arquivado, fallback conservador, isolamento A/B, atualização entre leituras, continuidade das regras de duração/agendabilidade e comunicação visual.
- Validações locais aprovadas: `npm run lint`; `npx vitest run` (198 arquivos, 1.033 testes); `npm run build`. Os avisos de chunk do Vite e de futura compatibilidade do carregador de config já existiam e não bloquearam o build.
