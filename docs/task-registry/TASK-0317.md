## Objetivo

Corrige quebra de tsc causada pelo bump do pdf-parse 1.1.4 -> 2.4.5 (Dependabot #683)

## Atualizações

Item da lista de preparação do sistema (auditoria geral de prontidão, pedido
direto: "vamos do mais rápido e mais leve de aplicar"). O PR do Dependabot
#683 (`pdf-parse` 1.1.4 → 2.4.5) tinha `lint-test-build` falhando:

```
server/services/knowledgeBaseDocumentStore.ts(9,8): error TS1192:
Module '.../pdf-parse/dist/pdf-parse/esm/index' has no default export.
```

**Causa:** a v2 reescreveu a lib inteira sobre `pdfjs-dist` (Mozilla
PDF.js) — deixou de ser uma função direta (`pdfParse(buffer)`) e virou uma
classe (`PDFParse`), com dependência nova de `@napi-rs/canvas` (binário
nativo) e requisito de engine `node >=20.16.0 <21 || >=22.3.0`. Não é um
fix de import de uma linha — é uma reescrita de API real, então investiguei
a fundo antes de aplicar: instalei a v2 localmente, li o `.d.cts` da classe
`PDFParse`, e testei a extração de texto contra um PDF de verdade (gerado
em código, com offsets de xref calculados, não hardcoded à mão) antes de
mudar o código de produção.

**Achado extra durante a investigação:** a v2 passou a inserir por padrão
um marcador de fim de página (`"-- N of M --"`) no texto concatenado —
isso poluiria o texto que vai pro prompt do agente (Camada 4, base de
conhecimento). Corrigido passando `pageJoiner: ''` em `getText()`.

**Fix:** `server/services/knowledgeBaseDocumentStore.ts` — `import
pdfParse from 'pdf-parse'` → `import { PDFParse } from 'pdf-parse'`;
`extractTextFromDocument` migrado pra `new PDFParse({ data: buffer
}).getText({ pageJoiner: '' })`, com `parser.destroy()` num `finally`
(libera os recursos do canvas/worker que a v2 gerencia internamente —
antes não existia esse conceito).

**Risco de engine verificado, não só assumido:** confirmei via
`mcp__Render__list_logs` que o serviço `universo-api-evo-hub` roda Node
24.14.1 em produção — dentro do range exigido pela v2. `npm install`
(CI e local) também já tinha passado antes de eu tocar em código, prova
que o binário nativo (`@napi-rs/canvas`) resolve corretamente no runner
do GitHub Actions.

**Teste novo:** não existia nenhum teste pra `extractTextFromDocument`
antes (nem pro caminho de PDF, nem pros outros). Adicionado
`server/services/__tests__/knowledgeBaseDocumentStore.test.ts` cobrindo:
extração real de um PDF válido (fixture gerada em código), detecção por
extensão de arquivo (mimeType genérico + `.PDF`), PDF corrompido (nunca
lança, devolve `undefined`), texto puro (sem passar pelo pdf-parse), e
tipo sem suporte (docx).

**Decisão de workflow:** não empurrei direto na branch do Dependabot
(`dependabot/npm_and_yarn/pdf-parse-2.4.5`) — apliquei o mesmo bump +
fix na branch designada desta sessão, num PR próprio. O PR #683 do
Dependabot deve fechar sozinho (ou ser fechado manualmente com um
comentário apontando pra este PR) assim que este for mesclado, já que a
versão alvo passa a existir na `main` pelo mesmo caminho.
